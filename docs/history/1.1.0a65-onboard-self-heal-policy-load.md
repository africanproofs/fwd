# v1.1.0a65 — onboard self-heals the policy load (no manual `rm policy.yaml`)

**Type:** onboarding robustness fix (`install/onboard`). No custody/signing semantics change. Operator-directed: "things like these [the manual recovery steps] should be part and parcel of the installation process."
**Date:** 2026-06-03.

## Why

Onboard Step 3 (load the policy) skipped the daemon restart when the on-disk policy was byte-identical to what it generated (`if [ "$CHANGED" -eq 1 ]`). That is wrong whenever a prior run **wrote** the policy but **died before loading it** — e.g. the a64-class `.env` permission failure made `docker compose restart fwd` fail at exactly that point. On the next run the file matched, so onboard said "already loaded — skipping restart" and proceeded to provision wallets against the still-inert daemon. The only recovery was a manual `rm /opt/fwd/src/config/policy.yaml` to force a rewrite+reload — an operator chore that should not exist.

## What changed

Step 3 now **always** restarts to load the on-disk policy (the `CHANGED`-based skip is removed; `CHANGED` still gates the policy *backup* in Step 2). Restarting to (re)load the same policy is idempotent and costs a few seconds, so onboard self-heals from any partial prior run — a re-run after a failure loads the policy with no manual intervention. The restart's `die` message now also points at `sudo fwd start` for the "stack isn't up" case.

This pairs with a64: a64 stopped the perms failure that caused the half-loaded state; a65 makes onboard recover cleanly even if any future failure leaves a written-but-unloaded policy.

## Verification (Reviewer)

`sh -n` + `dash -n` clean; confirmed the "skipping restart" branch is gone (onboard always loads). The restart + health-wait + `clifwd health` block is unchanged (previously rendered in the a60/a62 stub drills); only the `if/else` wrapper was removed. Live validation is the operator's fresh onboarding (Core invariant #14). Class note (Core invariant #19): the defect class is "idempotency that compares the artifact on disk but not whether the daemon actually applied it"; the fix asserts the desired *state* (policy loaded) every run rather than inferring it from file bytes.
