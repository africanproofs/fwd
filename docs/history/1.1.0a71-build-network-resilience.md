# v1.1.0a71 — build-from-source network resilience (pip/poetry timeout + retries)

**Type:** Dockerfile build-resilience fix. Companion clif ship: **v0.5.12** (same fix in clif's Dockerfile).
**Date:** 2026-06-04.

## Why (operator hit it live, three times)

A from-scratch `curl|sh` install (`docker compose build`, fwd + clif in parallel) failed repeatedly at the dependency-install step — never a code or script bug, always the network:
- clif: `pip install -r requirements.txt` → `ReadTimeoutError: files.pythonhosted.org ... Read timed out` and, on the index query, `pydantic-core==2.46.4 (from versions: none)`.
- fwd: `poetry install` → `ReadTimeoutError` on `cytoolz` / `pycryptodome`.

Reproduced + diagnosed against the code (not guessed): the host reaches PyPI fine; MTU is uniform (1500); a single-package `pip download` succeeds on both the default and host Docker networks. The real differentiators: **pip's default 15-second socket timeout with zero retries** cannot ride out a slow wheel on a variable link (clif failed even built alone), and the **parallel** `docker compose build` (fwd poetry + clif pip contending for bandwidth) tips poetry over its default timeout too (fwd built fine alone, failed in parallel).

## What changed

Build-time resilience only — no runtime/behaviour change:
- **clif `Dockerfile`:** `pip install` (runtime deps + the clif wheel, and the builder's poetry bootstrap) gains `--timeout 120 --retries 5`.
- **fwd `Dockerfile`:** build-stage `ENV POETRY_REQUESTS_TIMEOUT=120` (raised from poetry's 15s default) and `--timeout 120 --retries 5` on the poetry-bootstrap `pip install`.

120s is 8× the old timeout — ample headroom for a slow CDN wheel even under parallel-build bandwidth contention — and 5 retries absorbs transient stalls.

## Verification (real builds, to completion — not asserted)

Reproduced the failure, then proved the fix at three levels: clif image **alone** (was failing) → exit 0; fwd image **alone** → exit 0; the operator's exact **parallel `docker compose build --no-cache`** (full simultaneous re-download of both) → exit 0, both images built, no timeouts. Test images + placeholder env files cleaned up afterward.
