# v1.1.0a98 — grants keyed by `capability_id` (ADR-0001 dialect adoption)

**Type:** constitutional-amendment + feature. Operator-authorized 2026-06-10, ratified under flaresystems **ADR-0003** (interface-cohesion; consumer #2 imminent). `docs/decisions.md` **D25**.
**No signing-path change** — `policy_engine`, sealed master, nonce manager, the sign endpoints are UNTOUCHED. The `src/` change is the grant/policy-schema/CLI surface only.
**Date:** 2026-06-10.

## Headline

`capability_id` (`<consumer>/<network>/<role>`) — ADR-0001 §3's join spine — becomes a real, first-class field threaded through fwd's grant: the policy `CallerBinding`, the create request/response, the hash-chained audit row, and a new operator-gated `fwdctl capability grant`. This **supersedes the a92-era "grants keyed by caller-name / policy_path only" design** (D25 records the supersession honestly, Core #18). **clif is the reference consumer; `fwd-client` (the shared primitive) is unchanged.**

## The locked design (Unit-3 narrowing)

- **`capability_id` is POLICY-SCHEMA-ONLY** — an optional, pattern-validated (`^[a-z0-9][a-z0-9_-]*/[a-z0-9-]+/[a-z0-9-]+$`) field on `domain.CallerBinding`. **No Alembic / custody-DB migration** (it is not a `callers`-table column); it persists in the policy + the audit log only. Back-compat: name-only grants still validate.
- **`fwd` ingests the consumer's `<consumer> spec --json`** (paste-in via stdin/`--spec-file`; no fwd→clif call — zero-egress intact) and **re-renders the ADR-§4 custody diff itself** (never trusts the consumer's rendered diff). Default-deny: only `--approve` mints (Core #15).
- **`generate_policy` stays UNCHANGED** — the spec supplies only the `capability_id` + the diff for operator judgment, never policy *content* (Inv #6).

- **`src/fwd/domain/policy.py`** — `CallerBinding.capability_id` (optional, pattern-validated).
- **`src/fwd/app/caller_create.py`** — `capability_id` threaded into the request/result + the audit `request_json` (success AND the `CallerExistsError` forensic row; commit-before-raise preserved, Core #19); never a key/hash.
- **`src/fwd/api/callers.py`** — `CreateCallerBody`/`Response` gain `capability_id`; new `400 invalid_capability_id` gate (fires before `create_caller`).

- **`src/fwd/infra/policy_loader.py`** — `check_consistency` enforces `capability_id` uniqueness across `CallerBinding`s (the join's integrity).
- **`src/fwd/app/capability_grant.py` (new)** — parse + validate the 12-key spec (incl. the `capability_id`↔`consumer/network/role` join-integrity check), re-render the §4 diff, derive the provisioning plan (the canonical clif/onboard caller-name/policy_path convention).
- **`src/fwd/cli/capability.py` (new, mounted in `cli/main.py`)** — `fwdctl capability grant`: ingest → render diff → default-deny gate → on `--approve` mint each caller via the audited `POST /v1/admin/callers` keyed by `capability_id`; token return-once to stdout as `<env>=<token>`.
- **`install/onboard`** — the 3 live clif `caller_ensure` mints now carry `clif/<net>/{claim,fsp-sign,fsp-submit}` (`set -u`-safe). `env_write`/`--clif-env-dir` UNTOUCHED (Unit 4).

## The three deviations (Phase-0 against live code; all accepted)

1. **The grant command mints + re-renders the diff but does NOT write `policy.yaml` and does NOT emit a bundle.** Phase-0 found a single in-container "mint+write+reload" custody action **unrealizable** (policy reload needs a container recreate, outside the in-container CLI; the spec JSON carries the wallet *name* but not the fwd caller-name/policy_path, so the mint derives them via the canonical clif/onboard convention). The operator authors `policy.yaml` (the `capability_id` lives on the `CallerBinding` there + the audit row) — consistent with fwd's print-only / operator-authors-config posture (Core #6/#12). Whether fwd's app should ever write `policy.yaml`, plus the handoff-bundle / `--clif-env-dir` retirement, are **deferred to Unit 4**.
2. **`callers list` does not yet surface `capability_id`** — it reads the DB, and `capability_id` is policy-schema-only (no DB column). A DB↔policy join on the list surface is the **Unit 5** read surface (explicitly out of scope here). The id is visible on the create response + the audit row + the policy binding (and `policy validate`).
3. **`config/policy.example.yaml` did not exist** — the documented example lives at `docs/policy.example.yaml`; the `capability_id` example lines were added there.

## Core #19 — the real-`session_scope`-rollback test (the Part-A must-fix)

The mock test (`test_caller_create.py`) proves the commit-call + id-in-`request_json` cheaply but is structurally blind to durability. `test_caller_create_forensic_durability.py` (sibling of `test_fsp_forensic_durability.py`) drives the **real** `session_scope` rollback: it pre-creates the active caller, drives `create_caller`'s `CallerExistsError` arm carrying `capability_id="clif/songbird/claim"`, and after the scope unwinds asserts the **error row PERSISTED** (`decision="error"`, `request_json.capability_id == "clif/songbird/claim"`, no key/hash). A self-validating **WITHOUT-commit control** appends a row, raises without committing, and asserts it is **lost**. Mutation check: removing the commit-before-raise makes the test FAIL (0 forensic rows survive) — the harness catches the regression.
