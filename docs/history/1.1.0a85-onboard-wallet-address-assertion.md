# v1.1.0a85 — onboard rerun verifies a present wallet's address, not just its name

**Type:** `install/onboard` custody-safety guard. No daemon change.
**Date:** 2026-06-06.

## Why (surfaced during the live Songbird + Flare onboarding)

On a re-run, `import_pasted()` decided a wallet was already provisioned using **name
existence only**:
```sh
if wallet_exists "$1"; then note "already present: $1 @ $(wallet_addr "$1") — $role"; return 0; fi
```
By that point the wizard had already read on-chain truth in Step 2 (preflight) and
threaded the expected address into `import_pasted` as its 4th arg `_ia_expected`
(claimer ← `claimExecutors`/`_PREFLIGHT_EXE_<net>`; fsp-signing ← signing-policy
address/`_PREFLIGHT_SPA_<net>`/`--signing-policy`; fsp-sender ← `--fsp-sender-address`).
The early-return **never compared** the sealed wallet's address to that expected value.

Failure mode: a wallet row that exists under the right *name* but holds the *wrong key*
(sealed by a pre-`--expected-address` run, a manual `clifwd wallets import` without the
flag, or a stale row from a prior identity) was silently accepted — "already present",
summary `wallets ok`. `clifwd policy validate` cannot catch it: it checks wallet *names*
and policy paths, not Flare/Songbird preflight addresses. The result would be claims/
signing firing from the wrong key, or reverting, with no signal. `--expected-address`
already protects the *first* import (fwd rejects a wrong key before sealing); this closes
the **rerun / pre-existing-wallet** path, where that protection was skipped entirely.

## What changed (`install/onboard`)

New pure helper `wallet_assert_expected() { # name expected_addr }` (placed after
`wallet_exists()`): case-insensitive hex compare (`tr 'A-F' 'a-f'`) of the sealed address
vs the on-chain expectation; empty expected ⇒ no-op skip; on mismatch it `warn`s both
addresses and returns 1. The `import_pasted` early-return now calls it and **fails closed**:
```sh
if wallet_exists "$1"; then
  wallet_assert_expected "$1" "$_ia_expected" \
    || die "refusing to proceed: '$1' is already sealed with the WRONG address ... fwd has no in-place wallet-replace — inspect 'clifwd wallets list', then either reinstall with --reset-state and re-onboard, or remove that wallet row under operator control."
  note "already present: $1 @ $(wallet_addr "$1") — $role"
  return 0
fi
```

Fail-closed rationale: `clifwd wallets` exposes only `create`/`list`/`import` — there is
**no in-place wallet-replace** (`src/fwd/cli/wallets.py`). Silently overwriting a sealed
custody key is dangerous and unsupported, so replacement is the operator's deliberate act
(state rebuild via `install.sh --reset-state` + re-onboard, or an operator-gated removal
of the wallet row).

The check falls out automatically for all three import sites — claimer, fsp-signing, and
fsp-sender (when `--fsp-sender-address` is given) — because each already passes its
expected address as `import_pasted`'s 4th arg; no call-site edits were needed.

Deliberately **not** touched: `wallet_create()` (greenfield generates a fresh key — no
on-chain "expected" exists); the in-loop `rc=3` "already present" branch (unreachable in
the single-operator wizard once the line-415 check passed — no speculative guard).

## Verification

`sh -n` + `dash -n` clean. Function-level drill extracts the **real** function from the
file via `sed` (no copy drift) with a stubbed backend: case-insensitive match → ok;
empty expected → skip; deliberately wrong address → `warn` + rc=1. Live real-infra
confirmation (Core #14, operator) re-runs onboard with a deliberately wrong
`--signing-policy 0x…dEaD`: the wizard dies at the fsp-signing step with the mismatch
message instead of "already present"; a normal re-run returns to "already present" +
complete. The die fires before any paste/import/mint — no key material pasted or mutated.
