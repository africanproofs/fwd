# v1.1.0a63 — installer: fix sealed-master gen+read under a root (sudo) install

**Type:** installer fix (`install/install.sh`). No daemon/custody/signing semantics change — a host-permission correction in the bootstrap path. Operator-surfaced (a real `sudo curl|sh` install failed at master generation).
**Date:** 2026-06-03.

## Why (operator hit it live)

`sudo sh install/install.sh --with-clif` failed at step 5:

```
[fwd-install] generating sealed master (local, mode 0600)
PermissionError: [Errno 13] Permission denied: '/out/master.key'
[fwd-install] ERROR: master generate failed
```

Root cause: under `sudo`, `mkdir -p "$SRC/config"` makes the bind-mount dir **root-owned**. The master-gen step runs `docker run --rm -v "$SRC/config:/out" … clifwd master generate --out /out/master.key`, and the fwd image runs as **non-root uid 1000** (Dockerfile `USER`, Core invariant #1). uid 1000 cannot write into the root-owned dir → `PermissionError`. The same ownership would also block the **runtime read** of `config/master.key` and `config/policy.yaml` (both bind-mounted `:ro`, read by the uid-1000 container). The prod install at `~/fwd` (2026-06-01) worked only because it was a user-owned dir installed as uid 1000 — the bug is specific to root/sudo installs, i.e. the documented `curl … | sudo sh` provider path.

## What changed

`install/install.sh` — after the policy.yaml write and before the build, when running as root, hand the config dir to uid 1000:

```sh
if [ "$(id -u)" = 0 ]; then chown -R 1000:1000 "$SRC/config" 2>/dev/null || true; fi
```

The master.key the container then writes is `0600`, owned by uid 1000 — writable at gen-time and readable at runtime (Core invariants #1/#17: "0600 host file owned by the fwd user"). No-op for a non-root install (the user already owns the tree). The state DB is unaffected (it is the Docker-managed named volume `fwd-state:/data`, not a host bind).

`sh -n` + `dash -n` clean. The guarded `chown` line runs as a clean no-op for a non-root uid (verified). The root path's live validation is the operator's clean rebuild (Core invariant #14 — real-infrastructure verification): a `sudo` install now reaching master-gen → wrappers → start, and the daemon coming up healthy reading the uid-1000-owned master.key, is the proof. `poetry run pytest` (version-consistency + suite).
