## Why this ship

Phase 5 is the largest phase since 3. v0.4.0a2 closed the v0.4.0a1 audit with 5 fixes and 12 deferrals, leaving Phase 5 unblocked. The natural cadence is one big drop, but Phase 3 taught us — six alphas (a1 through a6) bought single-property gates that caught real defects (VAULT_ADDR bug in a2, doctrine churn in a3-a5). Phase 5 inherits that cadence.

v0.4.0a3 is the foundational alpha: it lands the SQLite schema for the rest of the phase so subsequent alphas don't churn migrations, and it introduces transaction-row persistence into the sign-and-send path. The verifiable property of this alpha: a real Coston2 sign-and-send call returns a `tx_id`; a subsequent `GET /v1/transactions/{tx_id}` returns the row with `status="submitted"`. Cross-caller isolation: a different caller's token presenting the same `tx_id` returns 404, not 403.

## What ships

### Schema (Alembic 0004 — six tables)

- **`wallet_chains`** — composite PK `(wallet, chain)`, FK to `wallets`. `architecture.md:208-212` had defined this table but no prior migration created it; v0.4.0a3 closes that orphan. Per D13 it stays unpopulated until Phase 7 if at all (the chain allowlist lives in `infra/rpc.py::ALLOWED_CHAINS` for v1).
- **`nonces`** — composite PK `(wallet, chain)`, FK to `wallets`. Columns: `next_nonce`, `last_confirmed`, `last_reconciled_at`. v0.4.0a4 wires `BEGIN IMMEDIATE` reservation against this table.
- **`transactions`** — single PK `tx_id` (UUIDv7 stored canonical 36-char). 15 columns including `caller` FK, `nonce`, `contract_address`, `method_name`, `value_wei` (decimal string), `idempotency_key` (nullable), `request_json`, `signed_raw`, `status`, `submitted_at`, `confirmed_at`, `receipt_json`, `created_at`.
- **`transaction_args`** — composite PK `(tx_id, arg_name)`. v0.4.0a3 never inserts; Phase 7's ABI intent decoder fills these.
- **`transaction_hashes`** — composite PK `(tx_id, sequence_num)`. v0.4.0a3 inserts exactly one row per transaction (sequence_num=1). v0.4.0a5 inserts on replacement.
- **`audit_log`** — standalone, `seq` autoincrement PK. v0.4.0a3 NEVER inserts; Phase 7 lands the hash-chain writes (per Core invariant #18: schema lands now to avoid migration churn; behaviour lands when the phase that needs it ships).

### Indexes

- `idx_tx_idempotency` — UNIQUE partial on `(caller, idempotency_key) WHERE idempotency_key IS NOT NULL`. Slot exists; replay logic lands in v0.4.0a5 or Phase 7.
- `idx_tx_status` on `(status,)` — for v0.4.0a5 watcher's pending-tx scan.
- `idx_tx_wallet_chain_nonce` on `(wallet, chain, nonce)` — for nonce reconciliation queries.
- `idx_tx_method` on `(method_name, contract_address)` — for Phase 7 audit-by-method queries.
- `idx_audit_caller_ts` on `(caller, ts)` — for Phase 7 audit pagination.

### Code

- **`src/fwd/infra/transaction_repo.py` (NEW, 240 lines)** — mirrors `infra/wallet_repo.py:1-101` pattern. `Transaction` + `TransactionHash` frozen dataclasses, `TransactionExistsError` + `TransactionNotFoundError`, `TransactionRepo(session)` with `create / add_hash / get_by_id / list_hashes_by_tx / update_status`. Status validated against `_VALID_STATUSES = frozenset({"pending","submitted","mined","replaced","failed","dropped"})` at the Python layer (SQLite has no enum). `update_status` accepts `confirmed_at` and `receipt_json` kwargs — used by v0.4.0a5 watcher; v0.4.0a3 unit tests cover it but the use case doesn't call it yet.

- **`src/fwd/infra/uuidv7.py` (NEW, 33 lines)** — RFC 9562 generator inline (Python 3.12 stdlib has no `uuid7()`; landed in 3.13). 48-bit ms timestamp | 4-bit version=7 | 12-bit rand_a | 2-bit variant=10 | 62-bit rand_b. Time-ordered so the `transactions` PK indexes well.

- **`src/fwd/app/sign_and_send.py` (MODIFIED, +56 lines)** — F8.1 closure: `caller: str` is now an explicit `SignAndSendRequest` field (after `wallet`, before `chain`). `sign_and_send()` accepts `tx_repo: TransactionRepo` as a 4th positional arg. After successful broadcast: generate UUIDv7 `tx_id`, compute `method_name = request.data[:10]` (4-byte selector with `0x` prefix; `"0x"` for empty data), compute `contract_address = request.to`, serialise `request_json = json.dumps({...}, sort_keys=True)`, store `signed_raw = "0x" + signed.raw_transaction.hex()`, call `tx_repo.create(status="submitted", submitted_at=now)` and `tx_repo.add_hash(tx_id, tx_hash, sequence_num=1)`. Defense-in-depth at function entry: refuses empty / >64-char `caller`.

- **`src/fwd/api/sign.py` (MODIFIED, -23 net lines)** — replaces `dependencies=[caller_required]` with `caller: Annotated[Caller, Depends(require_caller)]` in the handler signature, plumbing `caller.name` into `SignAndSendRequest`. Adds `tx_repo_cm: TransactionRepoCM = Depends(get_transaction_repo)`. Three CMs enter in one `async with` block. Response model adds `tx_id: str` (first field).

- **`src/fwd/api/transactions.py` (NEW, 76 lines)** — `GET /v1/transactions/{tx_id}`. Caller-gated. Cross-caller isolation: `if tx is None or tx.caller != caller.name: raise 404` (NOT 403 — avoids leaking the existence of other callers' transactions; documented in the docstring). Returns `TxStatusResponse` with `tx_id, wallet, chain, nonce, contract_address, method_name, value_wei, status, submitted_at, confirmed_at, hashes[]`.

- **`src/fwd/app/dependencies.py` (MODIFIED, +14 lines)** — `TransactionRepoCM` async context manager + `get_transaction_repo` FastAPI dep. Mirrors existing `CallerRepoCM` + `get_caller_repo`.

- **`src/fwd/main.py` (MODIFIED, +2 lines)** — register `transactions_router`.

## Deviations from canonical prompt

Sonnet surfaced four deviations; the Reviewer accepted all four.

1. **`wallet_chains` added to migration 0004.** The canonical prompt's "Lands" section listed 5 tables; the verification gate's expected table list included `wallet_chains` (9 entries total). Sonnet noticed the discrepancy and added `wallet_chains` to 0004. **Accepted** — this closes a real orphan: architecture.md:208-212 defined the table but no prior migration created it. Net result: 6 tables in 0004, not 5.

2. **`test_uuid7_str_is_monotonic_in_practice` uses 20 samples with 2ms sleeps** instead of the spec's "100 without sleep". Sonnet's justification: within a single ms, UUIDv7 strings are ordered by `rand_a` (random), so sorting fails. A 2ms gap guarantees distinct ms timestamps and true monotonicity. **Accepted** — sound. The test now asserts what monotonicity actually means in v7.

3. **File-based SQLite via `tmp_path` instead of `:memory:`** in `test_transaction_repo.py`. Sonnet's justification: matches the existing `test_wallet_repo.py` pattern; avoids aiosqlite in-memory StaticPool fiddliness. **Accepted** — pattern-match with existing tests is preferred.

4. **`signed_raw = "0x" + signed.raw_transaction.hex()`** with explicit `0x` prefix. Spec was silent on the prefix. **Accepted** — Ethereum convention; harmless. The structlog scrubber won't redact it (signed-tx hex is far longer than the 64-char privkey-shape).
