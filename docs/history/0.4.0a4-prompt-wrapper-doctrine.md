# v0.4.0a4 — Prompt wrapper doctrine (Reviewer-only, doc-only)

**Shipped**: 2026-05-12
**Author**: Opus 4.7 (Reviewer)
**No Sonnet involvement.** Pure doctrine codification.

## Why this ship

The hand-off between Reviewer (Opus 4.7) and Implementer (Sonnet 4.6) has two seams, not one:

1. **Inside the canonical prompt**: the HAND-OFF fenced block — what Sonnet is meant to read as authoritative spec. Codified at v0.3.0a5 (enforced hand-off demarcation: bold marker → blank line → fenced code block).
2. **Outside the canonical prompt**: the message the operator pastes into a fresh Sonnet 4.6 session — what tells Sonnet which fence is its spec.

v0.3.0a5 closed seam 1. v0.4.0a4 closes seam 2.

The operator surfaced the gap on 2026-05-12 while preparing to hand off v0.4.0a5 (Phase 5 alpha 2, nonce manager): "wrap the prompt file in a message to sonnet. always do this. codify in CLAUDE.md." The pattern they wanted: don't paste the entire canonical prompt body into chat — paste a short wrapper message that names the file path and points Sonnet at the HAND-OFF fenced block inside.

## What the doctrine codifies

In `CLAUDE.md` § Development workflow / Reviewer obligations, after the hand-off-demarcation rule, a new bullet establishing six wrapper requirements:

1. Name the canonical prompt file path explicitly (e.g., `/home/l/.claude/plans/fwd-canonical-prompt-v0.4.0a5.md`).
2. Instruct Sonnet to read the file in full BEFORE doing anything else.
3. Tell Sonnet that the HAND-OFF fenced block inside is the authoritative spec; material outside the fences is Reviewer-internal context.
4. Restate the no-commit / no-version-bump / no-doctrine-edit operating rules (Sonnet doesn't commit; Reviewer commits; Sonnet never edits `CLAUDE.md`, `pyproject.toml` version, `src/fwd/version.py`, or anything under `docs/`).
5. Require deviation surfacing per the final-report format in the canonical prompt.
6. End with "Begin by reading the canonical prompt file."

The wrapper is written bespoke by the Reviewer for each ship (10–20 lines, version-specific). It is presented to the operator IMMEDIATELY after the canonical prompt file is announced ready.

## The failure mode being prevented

A canonical prompt at `~/.claude/plans/fwd-canonical-prompt-v0.4.0aN.md` is a long Reviewer-internal document — typically 400–800 lines — containing:

- Phase 0 findings (what the Reviewer learned from reading the codebase).
- Cadence positioning (where this alpha fits in the phase arc).
- File-by-file specification.
- Deviation-handling tables.
- Verification gates.
- Reviewer obligations for the post-Sonnet commit.

Only the HAND-OFF fenced block (typically 100–200 lines) is meant as Sonnet's input. The rest is Reviewer thinking-aloud — useful for the human Reviewer's own bookkeeping, harmful when Sonnet treats it as instruction.

Concrete failure mode: a Reviewer Phase-0 finding like "The audit deferred F8.1 (caller as explicit input) to Phase 5 spec — this alpha closes it" is meant to tell the Reviewer why a particular spec choice was made. If Sonnet reads that paragraph as instruction, it might implement F8.1's audit framing (which doesn't exist in the codebase as a concrete spec) rather than what's in the fence. Or: a verification-gate table that talks about "If the test flakes 10× in a row, re-architect" is Reviewer-side guidance, not Sonnet-side instruction — but pasted as-is, Sonnet might add flake-detection logic.

The wrapper message is the boundary the operator copies verbatim: it points Sonnet AT the fence, not AT the wrapping document.

## Symmetry with v0.3.0a5

v0.3.0a5 (2026-05-02) codified the rule for **how** to demarcate the hand-off INSIDE the canonical prompt:

> Reviewer obligations include: demarcate every hand-off in canonical prompts with EXACTLY this format — bold marker on its own line, blank line, fenced code block wrapping the entire payload end-to-end.

v0.4.0a4 codifies the rule for **how** to present the canonical prompt to the operator:

> Reviewer obligations include: always produce a Sonnet wrapper message alongside the canonical prompt. The wrapper points Sonnet at the file path and the HAND-OFF fenced block; it never inlines the full prompt body.

Together, they close the Reviewer→Operator→Sonnet hand-off:

```
Reviewer writes canonical prompt (with HAND-OFF fence per v0.3.0a5)
        │
        ▼
Reviewer writes Sonnet wrapper (per v0.4.0a4) and presents to operator
        │
        ▼
Operator opens fresh Sonnet session, pastes wrapper
        │
        ▼
Sonnet reads canonical prompt file, identifies HAND-OFF fence, implements
```

No ambiguity at any boundary.
