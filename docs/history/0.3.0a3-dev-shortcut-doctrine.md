# v0.3.0a3 — Doctrine: Vault Shamir distribution is dev-elidable, production-mandatory

> Reviewer-only doctrine ship landed 2026-05-02. No Sonnet involvement.

## What this ship adds

A single new Core invariant in `CLAUDE.md`:

> **#17. Vault Shamir distribution is dev-elidable, production-mandatory.**

Captures two mutually-reinforcing rules:

1. **Dev shortcut is permitted.** During Phase 3a–7 development, while no production wallet is custodied in Vault, the 5 unseal shares + root token MAY live in a single mode-0600 file on the operator's primary laptop. Canonical path: `~/.fwd-dev/vault-init-output.json`. D6 distribution (2 paper + 3 GPG-encrypted-to-YubiKey across 5 failure domains) is OPTIONAL during this window because Vault holds nothing of value yet — total Vault loss costs at most a re-init.

2. **Production cut is mandatory wipe-and-redo.** Before the FIRST production migration (Phase 8 — `ftso-fee-claimer`'s `setClaimRecipient` rotation onto an `fwd`-custodied wallet), the operator MUST execute the wipe-and-redo sequence:

   ```sh
   docker compose down
   docker volume rm fwd_vault-data         # destroys all dev Vault state
   shred -u ~/.fwd-dev/vault-init-output.json  # plus any copies
   docker compose up -d
   # Then docs/runbooks/vault-init.md from step 1, this time with proper D6 distribution.
   ```

   The dev shortcut is forfeit at this point. No "just for now"; no "after the migration ships."

## Why

A `fwd` Vault that holds even one production privkey behind a single-laptop file is structurally indistinguishable from the `.env PRIVATE_KEY=` pattern Core invariant #7 forbids. The threshold-and-distribution model is the difference. Without it, `fwd` is just a different shape of the same problem.

The dev shortcut is appropriate before privkeys exist because the cost of total dev-Vault loss is small (re-init: minutes). It becomes inappropriate the moment a real privkey enters Vault — and the operator's cognitive shift required to do the wipe-and-redo correctly is exactly the kind of thing that goes wrong without doctrine. Codifying it in CLAUDE.md (always loaded into agent context) means every future agent-assisted Phase-8 attempt sees the rule before any production migration begins.

## Provenance

The dev posture was authorized by the operator on 2026-05-02 during the v0.3.0a1 verification ritual, in response to the friction of executing the full D6 ritual (paper printing + YubiKey GPG encryption + multi-location distribution) against a Vault that held nothing yet. Operator request: codify both the shortcut AND its mandatory revocation at production cut. This ship satisfies that request.

The substantive change is one new invariant in `CLAUDE.md` (~140 words), version bumps in `pyproject.toml` + `src/fwd/version.py`, a row in `docs/implementation-plan.md`, and this history doc. No code, no config, no test changes.
