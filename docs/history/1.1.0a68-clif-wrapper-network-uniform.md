# v1.1.0a68 — `install/clif` header reflects the now-uniform `--network` behavior

**Type:** doc-comment fix (`install/clif` header). No behavior change in fwd. Pairs with the consumer-side clif ship `0.5.10` (clif `8543e86`) that this repo's reviewer specified + binding-passed.
**Date:** 2026-06-04.

## Why

The `clif` host wrapper strips a **leading** `--network <N>` to select `.env.<N>` and passes the rest to clif. Previously `clif chain nonce` declared `--network` as a **required** option, so the leading form (`clif --network songbird chain nonce …`) failed — the wrapper stripped the flag and chain-nonce then errored `Missing option '--network'`. The operator hit this during live Songbird testing. The fix landed in **clif 0.5.10**: `chain nonce`'s `--network` is now optional, defaulting from the `NETWORK` env (like `claim`/`fsp`) — authored here as a canonical prompt, implemented + adversarially reviewed via a workflow, and reviewer-binding-passed (197 tests; SAFE-TO-SHIP). With that live on clif `main`, the leading `--network` form now works for **every** command, so this repo's `install/clif` header — which documented a two-form workaround — was stale.

## What changed

`install/clif` header only: the second usage example switches from the command-level form (`clif chain nonce --network flare …`) to the leading form (`clif --network flare chain nonce …`), and the explanatory comment now states the leading `--network` works uniformly (claim, fsp, chain nonce all read their network from the selected `.env.<net>`), with a command-level `--network` still honored as an explicit override. No code path changes; the wrapper still strips a leading `--network` exactly as before.

`sh -n` + `dash -n` clean on `install/clif`. The behavior is proven by the clif 0.5.10 binding-pass (the env-default path `test_chain_nonce_network_defaults_from_env` + the explicit-flag and keyless tests, all green) — and the leading form was confirmed live against the Songbird RPC during the executor/sender nonce sanity checks. `poetry run pytest` (version-consistency + suite).
