### Substantive changes (correction-by-correction)

**F6.1 (Medium) — `ruff check .` F841 lint failure on `tests/integration/test_caller_auth_e2e.py:139`**

The integration test had an unused `caller` variable from `await caller_repo.create(...)`. Ruff's `F841` rule fires on this. The lint failure was caused by the Reviewer's own path-(a) correction at v0.4.0a1 commit time (the integration test file was added by the Reviewer to close a Sonnet under-reported deviation; the unused-variable pattern slipped past the Reviewer's verification). CI gate is currently broken until this lands.

**Fix**: assert on `caller.name`, `caller.api_key_prefix`, `caller.api_key_hash` to use the variable AND harden the test (it now verifies the persisted Caller carries the same hash + prefix the test generated).

**F1.2 (Medium) — `--shred-source` silently degrades to `unlink()` when `shred` is absent**

Architecture.md § Wallet provisioning § Import says the operator contract is "exit non-zero with a warning if shred fails — the wallet is provisioned but the source file remains on disk for the operator to handle." The implementation in `_shred_file()` violated this on the missing-`shred` path: when `shutil.which("shred") is None`, the code fell through to `path.unlink()` and returned success. Plain unlink does NOT overwrite — recoverable on most filesystems (especially copy-on-write). For a plaintext private-key source file, that's a real silent custody downgrade.

**Fix**: `src/fwd/app/wallet_import.py::_shred_file` now raises `RuntimeError("shred command not found on PATH; source file remains on disk. ...")` when `shred` is missing. The caller (`import_wallet` use case) catches the raised exception and translates to `ShredSourceFailed`, which the CLI maps to a non-zero exit code (6). The wallet is still persisted (the doctrine guarantees that); the source file remains on disk for the operator to handle (architecture.md doctrine). New unit test `tests/unit/test_wallet_import.py::test_shred_missing_raises_shred_source_failed` covers the new behavior and asserts the source file still exists post-failure.

**F1.1 (Medium) — `EnvelopeSigner.import_wallet` not covered by hazard #1/#2 enforcement tests**

Phase 4 added a third privkey-handling path (`EnvelopeSigner.import_wallet` per D12). The v0.3.2 hazard tests covered only `create_wallet` and `sign_transaction`. Coverage report flagged the gap (`src/fwd/infra/envelope_signer.py:116-138` missing).

**Fix**: 3 new tests in `tests/unit/test_envelope_signer.py`, mirroring the existing patterns:
- `test_import_wallet_buffer_is_all_zero_after_zeroize` — hazard #2 contract on the success path.
- `test_import_wallet_buffer_zero_on_address_mismatch` — hazard #2 contract on the `WalletAddressMismatch` raise path (verifies the `finally`-block fires).
- `test_no_32byte_state_after_import_wallet` — hazard #1 contract; signer instance state has no 32-byte `bytes`/`bytearray` after the call returns.

All 3 tests pass. Hazards #1 and #2 are now enforced for all 3 privkey paths (create/sign/import).

**F5.2 (Low) — Stale comments in `infra/api_key.py` and `api/admin_auth.py`**

Two comment-drift cases caught by the doctrine-vs-code audit (Core invariant #18):

- `src/fwd/infra/api_key.py` docstring said "252 bits of entropy" (the actual entropy is 256 bits — 32 random bytes via `secrets.token_urlsafe(32)`) and "parallelism=2" (the installed argon2-cffi 23.1.0 default is `parallelism=4`). **Fix**: corrected to "256 bits" and listed the actual installed defaults (`time_cost=3, memory_cost=65536, parallelism=4, hash_len=32, salt_len=16`); referenced OWASP 2024 minimum recommendations.
- `src/fwd/api/admin_auth.py` docstring said "Phase 4 will replace this with the full caller-auth machinery" — incorrect post-D11. Phase 4 ADDED caller auth as a SEPARATE module per D11 (separate-module model); it did NOT replace `require_admin`. **Fix**: rewrote the docstring to describe the D11 separate-module model and reference `tests/unit/test_admin_caller_bright_line.py` as the canonical attestation.

**F5.1 (Medium) — `0.4.0a1-caller-auth.md` history-doc inaccuracies**

The history doc made two claims that were inaccurate at audit time:
1. The verification-gates section implied `ruff check .` was clean (was actually failing on F6.1).
2. The "What Phase 4 deliberately does NOT include" section listed "Integration test against live Vault... deferred to Phase 7" — but the integration test file `tests/integration/test_caller_auth_e2e.py` had been added by Reviewer at v0.4.0a1 commit time as a path-(a) correction.

**Fix**: appended a `## v0.4.0a2 audit response — corrections (appended 2026-05-07)` section to `docs/history/0.4.0a1-caller-auth.md`. The original lines are preserved per the v0.3.0-phase-3c-sign-and-send precedent (history docs are append-only; addenda record post-ship corrections without rewriting history).
