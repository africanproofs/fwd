## Why this ship

made default-deny real on the live `/v1/sign-and-send` path and wired
the `sign-and-send` + lifespan `policy-load` audit rows. The operator

  / `caller-create` / `caller-revoke` rows (D16 § Audit-row authorship).

  mutation + its audit row commit atomically under one `BEGIN
  IMMEDIATE`.
- **D14 idempotency-replay** — `Idempotency-Key` → cached `tx_id`,
  `sign-and-send-duplicate` row, no re-gate / re-nonce / re-rate.

- **`delete_stale` policy-load prune** (D14 bounded-growth wiring;
  honestly re-marked a6-NOT-done → a7 at the a6 ship).

## What shipped

**`src/fwd/app/dependencies.py`** — `@dataclass(frozen=True)
AdminScope(signer, caller_repo, audit_repo)`; `AdminScopeCM` mirrors
`RequestScopeCM` (open `VaultClient` → `VaultUnavailableError` on
`VaultError`; one `session_scope`; `WalletRepo` → `EnvelopeSigner`,
`CallerRepo`, `AuditRepo` all on that one session; **no `RpcManager`** —
admin actions never touch chain); `__aexit__` closes session then
vault; `get_admin_scope()`. `policy_path_exists` re-exported here
(`from fwd.infra.policy_loader import policy_path_exists as
policy_path_exists`) so the api layer imports it from
`fwd.app.dependencies` (app may import infra; api → app only — the
layer boundary is preserved; this is the Reviewer-confirmed choice over
the spec's other option).

**The four admin use cases** (`wallet_create`, `wallet_import`,
`caller_create`, `caller_revoke`) — each gains a keyword-only
`audit_repo: AuditRepo` and appends **exactly one** row per call:
success → `decision="approved"`; each known-failure exception →
`decision="error"` (with `decision_reason=f"{type(exc).__name__}:
{exc}"`) THEN re-raise. `caller=None` (admin actions are
`FWD_ADMIN_KEY`, not a caller — D16: `caller TEXT` NULL). `request_json`
= `_canonical_json` of name + policy_path (+ `source_file` path for
import); `outcome` = `{"address": ...}` (wallet create/import) or
`{"api_key_prefix": ...}` (caller create) — **NEVER privkey, api_key
plaintext, key_hash, or ciphertext**. `wallet_import` audits every
refusal-table branch (not-found / bad-mode / bad-owner / bad-content)
BEFORE the privkey buffer is wrapped; bad-content `decision_reason`
carries length only. `_canonical_json` is imported at runtime from
`fwd.infra.audit_repo`; `AuditRepo` under `TYPE_CHECKING`.

**`src/fwd/infra/transaction_repo.py`** — `create(...,
idempotency_key: str | None = None)` (both the `.values(...)` INSERT
and the returned `Transaction`); new
`get_by_idempotency_key(caller, key) -> Transaction | None` —
`WHERE caller AND idempotency_key` (per-caller scope; the partial-
unique index guarantees ≤1), row→dataclass mirroring `get_by_id`.

**`src/fwd/infra/audit_repo.py`** — one new read-only
`find_sign_and_send_seq(tx_id) -> int | None`: `select(seq).where(
action=="sign-and-send", decision=="approved",
outcome.like('%"tx_id":"<id>"%')).order_by(seq.asc()).limit(1)`.
Reliable because a6's approved outcome is `_canonical_json({"tx_id":
..., "hash": ..., "nonce": ...})` and `_canonical_json` uses
`separators=(",",":")` — the substring `"tx_id":"<uuid>"` appears
verbatim (UUIDv7, no JSON-special chars). append/get/tail/verify
untouched.

**`src/fwd/api/sign.py`** — `idempotency_key: str | None =
Header(default=None, alias="Idempotency-Key")`; > 128 chars → 400
`bad_idempotency_key`; threaded into `SignAndSendRequest`.
**`src/fwd/app/sign_and_send.py`** — `SignAndSendRequest` gains
`idempotency_key: str | None = None` (last field). Replay branch at
the TOP (after the `request.caller` defensive check, BEFORE step 1 and
BEFORE the policy gate): on a `(caller, key)` hit it reads
`list_hashes_by_tx` (seq-1 = `hashes[0].hash_hex`, the original
broadcast hash — `list_hashes_by_tx` orders by `sequence_num`),
`find_sign_and_send_seq` for `original_audit_seq` (None is acceptable —
`outcome` carries `null`), appends a `sign-and-send-duplicate` row
(`decision="approved"`, `decision_reason="idempotency_replay"`,
`caller=request.caller`, `outcome={"original_tx_id",
"original_audit_seq"}`), and returns the cached `tx_id` + hash +
nonce. **No `gate()`, no nonce reservation, no rate touch** (D14: the
original consumed them; the cached result is valid even if `policy.yaml`
changed). The non-replay path threads `idempotency_key` into the
existing `tx_repo.create(...)`.

**`src/fwd/api/wallets.py` + `src/fwd/api/callers.py`** — POST + DELETE
handlers swapped to `AdminScopeCM` (via `get_admin_scope`); use cases
called with `audit_repo=scope.audit_repo`. `policy_path` validated:
`policy = getattr(http_request.app.state, "policy", None)`; if
`policy is not None and not policy_path_exists(policy, body.policy_path,
kind)` → 400 `unknown_policy_path` (`kind="wallet"` →
`wallet_constraints`; `"caller"` → `permissions`). When no policy is
loaded the check is **skipped** (preserves the create-entities →
write-policy → restart bootstrap order; the restart fail-fast is the
backstop). The 400 (and the existing `_NAME_RE` 400) are raised BEFORE
entering the scope — no audit row for a rejected-before-attempt admin
call. The LIST handlers (GET) stay on their read-only CMs (D16 actions
are create/revoke only). All existing `except` arms (409/503/404)
preserved.

**`src/fwd/cli/wallets.py`** — `import` switched from `SignerCM` /
`get_signer` to `AdminScopeCM` / `get_admin_scope`;
`import_wallet(req, scope.signer, audit_repo=scope.audit_repo)`. Exit
codes unchanged.

**`src/fwd/main.py`** — `_startup_policy_load` success branch (inside
the `session_scope`, AFTER the approved `policy-load` row): `cutoff =
now − 2 days; try: deleted = await RateRepo(session).delete_stale(
before=cutoff)` → `log.info("lifespan.rate_buckets_pruned", ...)`;
`except Exception → log.warning("lifespan.delete_stale_failed", ...)`.
2 days is safely older than the largest `hour`/`day` window. The error
branch (which `SystemExit(1)`s) is untouched — no prune there. A prune
failure cannot block boot.

## Six spec-pinned safety properties (verified directly by the Reviewer)

(a) **Every admin use case writes exactly one row, on the shared
`AdminScope` session, success AND known-failure, with NO secret in
`request_json`/`outcome`** — verified by source read of all four use
cases (the only `api_key`/`privkey`/`ciphertext` tokens in the
audit-bearing bodies are `api_key_prefix` (public, spec-permitted) and
`address` (public); `repo.create(api_key_hash=...)` is the persistence
call, not an audit append) AND by the fixtures comparing against the
*real* generated `api_key`/privkey-hex/ciphertext placeholder.
(b) **The replay branch does not gate / reserve a nonce / touch rate
and returns the cached seq-1 hash** — the branch returns before step 1;
`test_replay_does_not_re_evaluate_policy` replays under a fully-empty
deny policy and still succeeds (if it reached the gate it would Deny at
step 1).
(c) **`get_by_idempotency_key` is per-caller-scoped** — `WHERE caller
== caller AND idempotency_key == key`; `test_different_caller_same_key_
is_not_replay` proves it.
(d) **policy_path validation is skipped when no policy AND enforced
when present** — `getattr(..., "policy", None)` guard; both cases
tested.
(e) **The api layer gained no direct infra import** — `policy_path_
exists` via the `fwd.app.dependencies` re-export; layer-boundary test
green.
(f) **`delete_stale` runs only on the success branch and cannot block
boot** — placed after the approved `policy-load` append, before the
implicit else; the error branch `SystemExit(1)`s without reaching it;
wrapped `try/except Exception → log.warning`.
