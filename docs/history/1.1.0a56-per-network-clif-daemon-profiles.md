# v1.1.0a56 — per-network clif daemon profiles; single clif-auto/clif-fsp-auto removed; `fwd start <net>`

**Type:** compose + host-wrapper ship (`docker-compose.clif.yml`, `install/fwd`, docs). Reviewer-implemented (small, mechanical: 2 service deletions + 6 profile renames + 1 wrapper case); verified by `docker compose config` per profile + `sh -n`. Operator-authorized ("per-net profiles + remove the single daemons"). Prod-migration-sensitive — flagged below.
**Date:** 2026-06-03.

## Why

The second adversarial review's Finding 2: the `--with-clif` overlay shipped (a) a single `clif-auto`/`clif-fsp-auto` reading `${CLIF_ENV:-./clif/.env}` (NOT the per-network `.env.<net>` onboarding writes) that auto-started on `fwd start`, and (b) per-network daemons all under ONE `multichain` profile, so `--profile multichain up/config` validated EVERY network's `.env.<net>` — songbird-only onboarding still failed if `.env.flare`/`.env.coston2` were absent. Deferred from a55 (prod-migration-sensitive) and run after the live drill, per operator choice.

## What changed

- **Removed the single `clif-auto` + `clif-fsp-auto`** from `docker-compose.clif.yml` (they read the wrong env and auto-started). There is no longer a shared clif daemon; each network reads its own `.env.<net>`.
- **Per-network profiles.** The six per-network daemons moved from `profiles: ["multichain"]` to `profiles: ["<net>"]` (`clif-auto-coston2`/`clif-fsp-auto-coston2` → `["coston2"]`, songbird → `["songbird"]`, flare → `["flare"]`). So `docker compose --profile songbird …` activates ONLY songbird's two daemons and validates ONLY `.env.songbird` — the all-or-nothing bug is gone. The one-shot `clif` (`profiles: ["cli"]`) is unchanged.
- **`fwd start [<net>]`** (`install/fwd`). `fwd start` brings up fwd (+ litestream) only; `fwd start <net>` (flare|songbird|coston2) also brings up that network's clif daemons via `--profile <net>`. Help + header + `docs/one-command-install.md` updated.

## Verification (Reviewer)

`docker compose config` (base `.env` + ONLY `.env.songbird` present): default → `fwd`, `litestream` (no clif); `--profile songbird` → + `clif-auto-songbird`, `clif-fsp-auto-songbird` and the **full config SUCCEEDS with `.env.flare`/`.env.coston2` absent** (the fix); `--profile multichain` → no extra services (the profile is now dead); `--profile cli` → + the one-shot `clif`. `sh -n` clean on all install scripts. Single daemons confirmed gone (`grep '^  (clif-auto|clif-fsp-auto):'` empty).

**Prod-migration note (operator's manual run).** This changes what `fwd start` launches: it no longer auto-starts a clif daemon. Recon at drill time confirmed prod runs NO clif daemon currently (only `fwd` + `fwd-litestream`), so removing the single daemons disrupts nothing live. Post-deploy, start a network's always-on automation explicitly with `fwd start <net>`. The FSP daemon stays hard-off unless `FSP_AUTO_ENABLED=true` in that `.env.<net>` (clif enforces).

## Files

`docker-compose.clif.yml`, `install/fwd`, `docs/one-command-install.md`, version files. This closes the second adversarial review's last open finding; the onboarding redesign (clif + fwd a51–a56) is complete pending the operator's live prod run.
