# v1.1.0a102 — membrane-clean handoff: fwd publishes to its OWN outbox

**Membrane fix (install/ only; ADR-0001 one-way dependency restored). Operator directive 2026-06-11:
fwd must not depend on clif or any consumer/caller — on the filesystem axis.**

The onboard previously wrote the handoff bundle **into the consumer's directory** (`CLIF_ENV_DIR`,
default `/opt/clif`) — fwd reaching across the membrane, which forced an install-order entanglement
("clif before onboard"). a102 relocates the bundle to a **fwd-owned outbox**; the consumer pulls it.

- **`install/onboard`:** `CLIF_ENV_DIR` → **`FWD_HANDOFF_DIR`** (default `$FWD_DIR/handoff`, fwd-owned,
  uid-1000 0700). Bundle path `$FWD_HANDOFF_DIR/$CONSUMER-<net>.json` (new `CONSUMER` var). fwd owns the
  outbox lifecycle (**TTL-prune** `*.json` older than 10m). Narration repointed; the import hint points the
  consumer at the outbox path. Return-once + the Core-#7 `PRIVATE_KEY` guard UNCHANGED.
- **`install/install.sh`:** the `--clif-env-dir` flag + `CLIF_ENV_DIR` var / bake-loop / exec-pass-through /
  printed examples **deleted entirely**.
- **`install/fwd` · `clifwd` · `fwdctl`:** `CLIF_ENV_DIR` removed; `fwd status` drops the block that **read
  the consumer's dir** (itself the violation) and reports fwd's own compose state only.
- **Invariant:** `grep -rn 'CLIF_ENV_DIR\|/opt/clif\|clif-env-dir' install/` → empty. Invariant #5 stays
  closed; the membrane now holds on the **filesystem** axis too. The `clifwd()` stdin `-i` fix (`c75843d`)
  is in the base and intact.

Signing path / sealed master / `src/` UNTOUCHED. The **namespace** residual (the onboard still mints
`clif/…`-namespaced capabilities) is a deeper, separate decoupling — flagged, not done here.
`consumer-contract-v1`'s handoff-location update and the secondary-doc reconciliation
(`one-command-install` / `dependencies` / `production-setup`) follow. — `1.1.0a102-membrane-handoff.md`
