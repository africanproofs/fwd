## Why

The a60 cockpit reported *intent* as if it were *verified running state*. The external adversary's post-ship pass raised two MAJORs (both: the cockpit is too confident) plus related truthfulness items. None blocked a60; all are honesty fixes to the new output.

## What changed

- **MAJOR — `fwd status` now propagates `docker compose ps`'s exit code** (`install/fwd`). a60 had `docker compose $COMPOSE ps … || true` and a case-arm ending in `printf`, so `fwd status` returned 0 even when the Docker daemon was down / compose config broken / install path wrong — hiding failure from monitors and scripts. Now: `set +e; docker compose … ps; _rc=$?; set -e`, print the cockpit, emit a stderr note on failure, `exit "$_rc"`. Verified: `PS_RC=0 → exit 0`, `PS_RC=42 → exit 42`.
- **MAJOR — `fwd start` reports `requested` (not `started`)** (`install/fwd`). `docker compose up -d` returns 0 even if a daemon then immediately exits or restart-loops (bad/missing `.env.<net>`, or `FSP_AUTO_ENABLED=false` on an FSP profile — the exact class this cockpit is meant to clarify). The label is now `requested (docker compose up -d):` / `not requested:`, with a pointer: `confirm it stayed up (up -d does not guarantee it): sudo fwd status | sudo fwd logs <svc>`. `fwd status` is the truth command; `fwd start` only states what it asked for. **a59 profile semantics unchanged** (`<net>` = claim daemon only; `<net> fsp` = FSP daemon only).
- **MINOR — drift attribution correct in shared-FSP-sender mode** (`install/onboard`). The summary table's per-network nonce-drift glob was `*"-$net("*`, which misses the shared sender (`fsp-sender`, no `-<net>` suffix) → its drift could show `ok`/`defer` in the cockpit (the unconditional `⚠ UNRESOLVED NONCE DRIFT … exit 1` terminator still fired, so safety was never at risk). `reconcile_nonce` now records the net it was called with — `UNRESOLVED_NONCES` entries are `<wallet>@<net>(…)` — and the glob is `*"@$net("*`, correct for both per-network and shared modes (and the terminator message is clearer). Verified: `claimer-songbird@songbird` and `fsp-sender@songbird` both → drift for net=songbird; `claimer-flare@flare` → no false match.
- **MINOR — truthful installer line** (`install/install.sh`). `clif daemons: stopped` was false on a re-run if daemons were already up (the installer never starts/stops clif daemons). Now `clif daemons: not started by installer`.
- **NIT** (`install/install.sh`): the inline-onboarding log said "running guided reward onboarding" even in compact mode → "running reward onboarding".
- **NIT** (`install/onboard`): documented `guided()`'s printf-format contract (first arg is a format string; a literal `%` must be `%%`) — no current bug, a maintenance guard.
- **NIT** (`docs/one-command-install.md`): the "narrates each step" paragraph now states that narration is **guided-mode** behavior and the default is the **compact** cockpit.
