# v1.1.0a109 — the `native-transfer` capability (signed value-only transfers)

## What shipped

fwd can now sign a **value-only (empty-calldata) native transfer** — `to` + `value`,
no calldata — gated by a new policy section, so a keyless consumer (clif's forthcoming
`clif/<net>/funding` capability) can top up the FSP gas-payer accounts without holding a
key. Before this ship, `app/policy_engine.py` Step 3 denied any `len(calldata) < 4`
request, so fwd could sign contract calls only.

This is a clean extension of Core #3 (sign policy-checked intent, never opaque bytes),
not a hole: a transfer's intent is fully specified by `(to, value)` — there is nothing
opaque to decode — so the gate is a policy **recipient allowlist + per-tx `max_value_wei`
cap + wallet allowlist + per-caller rate + per-wallet daily aggregate cap**. Default-deny
is preserved: a caller with no `native_transfers` rule still hits the Step-3 deny.

## Changes

- `src/fwd/domain/policy.py` — `NativeTransferBlock` (chains, recipient_allowlist,
  max_value_wei, wallet_allowlist, rate; `extra="forbid"`) + `Policy.native_transfers`.
- `src/fwd/app/policy_engine.py` — an empty-calldata branch in `_evaluate_inner` routes
  to `_evaluate_native_transfer` when the caller's policy_path names a `native_transfers`
  block (a non-empty-calldata request from such a caller is denied step 2; a value-only
  request from a caller without the rule keeps the Step-3 deny). The evaluator checks, in
  order: chain · recipient allowlist (case-insensitive) · per-tx value cap (value must be
  > 0, ≤ max_value_wei) · wallet allowlist · **Step 8** per-caller rate · **Step 9**
  per-wallet aggregate + rate constraint (`check_and_increment_wallet`, fail-closed if no
  constraint binding, releasing the Step-8 caller increment on a Step-9 deny — mirrors the
  ABI path exactly). It synthesizes a `DecodedIntent`
  (`nativeTransfer(address,uint256)`, args `{to, value}`) so the audit + response carry a
  human-readable intent. `sign_transaction.py` (the signing/tx-build path) is **unchanged**
  — it already handles `value` + empty `data`.
- `src/fwd/infra/policy_loader.py` — `check_consistency`: a caller binding may resolve to
  `native_transfers` (Check 1c), and `native_transfers[*].wallet_allowlist` entries must
  resolve to known wallets (Check 4c).

## Tests

- `tests/unit/test_native_transfer_policy.py` — 11 cases: allow-in-cap; deny off-allowlist
  recipient; deny over-cap; deny zero-value; deny wrong-chain; deny wallet-not-allowlisted;
  deny non-empty-calldata from a native_transfers caller; **default-deny** (no rule + empty
  calldata → the pre-existing Step-3 deny); rate exhaustion (step 8); **over-aggregate cap
  (step 9)**; **no-constraint-binding fail-closed (step 9)**.
- `tests/unit/test_native_transfer_policy_loader.py` — consistency accepts a native_transfers
  caller binding + a resolvable wallet_allowlist; rejects an unknown wallet.
- `tests/integration/test_native_transfer_http.py` — real-ASGI: POST /v1/sign-transaction
  through the actual route → 200 + a `signed_raw_tx` decoded to assert `to`/`value`/empty
  `data`; off-allowlist → 403 policy_denied; the approved audit row records the intent.

Full suite: **1013 passed, 1 skipped**; ruff clean on all ship files.
