# v1.1.0a32 — provider-distribution surface: install design, `--with-clif` overlay, generic framing

**Type:** docs + deployment-scaffolding ship (no daemon code change). Provider-distribution Phase 0, ship 3.
**Date:** 2026-05-31.
**Authoring:** Reviewer (Opus) implemented directly under operator direction; operator-gated.

## Why

Following the approved provider-distribution plan: make fwd (and the optional
clif layer) presentable and runnable by a THIRD-PARTY Flare FTSO provider on
their own host. After the onboarding tooling (a30 `policy validate`, a31
`policy init`), this ship lands the install DESIGN, the `--with-clif` runtime
artifacts, and decouples AP-specific framing from the provider-facing docs.

## What changed

- **`docs/one-command-install.md` rewritten** to the approved design:
  modernized off the retired Vault to **sealed-master**, framed for any provider
  (not AP-internal), the **single-host positioning** (a single host is a full
  provider stack; it is not necessary/possible to add signer nodes — Core #9),
  **fwd-core + `--with-clif`**, **build-from-source** image delivery (no registry
  dependency / no prebuilt-binary trust), the **two-layer model with the hard
  custody gate**, the **phased onboarding** (runbook + `policy init`/`validate`
  now; `fwd custody init` wizard later), pinned source + checksums (not image
  digests), and the `curl|sh`-for-a-custody-tool security model.
- **`docker-compose.clif.yml`** (new) — the `--with-clif` overlay: clif claim +
  FSP daemons, dual-homed to fwd's `fwd-callers` (to reach `fwd:8080`) + a new
  `egress` bridge (their RPC/broadcast); fwd stays off `egress`. clif build
  context is `$CLIF_SRC` (the installer places clif's pinned source there).
  Inert unless explicitly composed in (`-f docker-compose.yml -f docker-compose.clif.yml`).
- **`install/fwd`** + **`install/clifwd`** (new, executable) — the host command
  contract: `fwd` lifecycle wrapper (start/stop/restart/status/logs; includes the
  clif overlay when present; upgrade/backup deferred to Phase 1 install.sh) and
  `clifwd` delegating into the container (`docker exec fwd clifwd "$@"`).
- **Generic framing** in the provider-facing current-state docs (Core #18 — the
  present, generically): `README.md`, `docs/architecture.md`,
  `docs/dependencies.md`, `docs/threat-model.md` reworded from "African Proofs' /
  AP" to "operator / provider"; `docs/policy.example.yaml` recipient →
  `0xYOUR_CLAIM_RECIPIENT_ADDRESS` placeholder. Honest-history docs
  (`decisions.md`, `docs/history/`, `SHIP-LOG.md`) untouched — they legitimately
  name AP.
