# v1.1.0a92 — de-intermingle clif: fwd is fwd-only; clif is a separate deployment

**Type:** deployment-topology refactor + constitutional amendment (operator-directed). No
daemon/signing-path change — `src/fwd/` is untouched; this is install/deploy tooling + docs.
**Date:** 2026-06-08.

## Why

Through a91 the clif consumer was **bundled into fwd's deployment**: a `docker-compose.clif.yml`
overlay merged clif services into the **fwd compose project**, `fwd start <net>` launched
`clif-epoch-<net>`, `--with-clif` cloned/built clif under `/opt/fwd/clif`, and a bundled `clif`
host wrapper ran one-shots in fwd's project. The operator observed this **defeats the
architectural cleanness of fwd's zero-egress**: the `egress` network lived *in the fwd project*
(`fwd_egress`) and an egress-having consumer ran *as part of* `fwd`'s compose project —
intermingling the signer with the very consumer the zero-egress boundary exists to separate.

## What changed

fwd's deployment is now **fwd-only** (compose project `fwd` = `fwd` + `litestream` on the
`internal: true` callers network — no clif service, no egress network in the project). The clif
consumer is a **separate deployment** (project `clif`) with its OWN `egress` bridge that joins
`fwd-callers` as an `external` network to reach `fwd:8080`. fwd never clones, builds, launches,
or co-hosts clif; clif is managed by its own `clifctl` (a `-ctl` control tool — up/down/status/
logs/run — not a `-d` daemon, since it *controls* the daemon containers).

**Code (install/ only):**
1. **`install/install.sh`** → fwd-only: `--with-clif` removed (accepted as a deprecated no-op);
   `--clif-env-dir DIR` added (default `/opt/clif`, baked into the wrappers); builds/starts/wraps
   **fwd + clifwd only**; the clif clone, the merged overlay, the `--profile cli` build, the
   clif-dir chown, and the `clif` wrapper install are gone.
2. **`install/fwd`** → `start` = fwd + litestream; `start <net>`/`fsp` is **rejected** with a
   redirect to `clifctl up <net>`; status/onboard de-clif'd; `CLIF_SRC`/`CLIF_ENV`/overlay
   removed.
3. **`install/onboard`** → **never invokes clif.** Removed: the Step-2 preflight and the
   chain-reading `reconcile_nonce`/`read_chain_nonce`/`ask_nonce`/`cutover_msg`/`seed_sender`.
   Added: `seed_nonce_or_defer` — a freshly **generated** wallet has on-chain nonce 0 → `nonce
   init 0` (no chain read); an **imported** wallet defers (the operator seeds from chain truth
   via clif). The clif env-write is now **unconditional** → `${CLIF_ENV_DIR:-/opt/clif}/.env.<net>`
   (0600, `chown 1000:1000`); the rehearse/automation guidance points at `clifctl run`/`clifctl
   up` + operator-run `clifctl run <net> preflight`.
4. **`install/clifwd`** → drops `CLIF_SRC`/`CLIF_ENV`, exports `CLIF_ENV_DIR` for the onboard
   route.
5. **Deleted** `docker-compose.clif.yml` (the overlay) + `install/clif` (the one-shot wrapper).

`CLAUDE.md` (new "What FWD IS NOT" bullet: fwd's compose is fwd-only; it does not deploy
consumers — plus the § Scope current-state line), `README.md`, `docs/one-command-install.md`,

## The onboard↔clif-read coupling (the non-obvious part)

The plan under-specified onboard: a single `CLIF_OK` flag gated three things — the preflight
display, the **chain-truth nonce seeding**, *and* the env-write. With clif separated, `CLIF_OK`
would go false and onboard would skip the env handoff too. Decoupled: env-write is **always**
done (provisioning is fwd-admin's job); the **chain reads** are dropped from onboard entirely
(operator decision) because fwd is zero-egress and those reads must come from clif. Fresh
wallets are still auto-seeded (nonce 0, no chain read); imported wallets defer with a precise
instruction.

## clif side (separate ship, separate repo)

`clifctl` (the lifecycle/one-shot tool), a minimal standalone clif install, and clif's docs
ship in the clif repo — clif's `docker-compose.yml` already supports standalone deployment
(declares `fwd-net` as `external` + its own `egress`), so no clif code change is required.

## Migration (operator-gated)

The live bundled instance keeps working on its installed wrappers until the next gated redeploy:
reinstall fwd fresh (fwd-only) → `fwd onboard --clif-env-dir /opt/clif` → deploy clif at
`/opt/clif` (its own installer + `clifctl`) → `clifctl up <net>`.
