# v1.1.0a44 — onboarding is a narrated single-terminal paste wizard, run by default at install

**Type:** tooling ship (`install/onboard` + `install/install.sh` + docs; no daemon
`src/` change). **Date:** 2026-06-01. Reviewer (Opus); operator-gated. Verified on
real (isolated) infra under a pseudo-tty.

## Why

Operator directives, converging on a guided experience:
1. **One terminal** — the a43 key-import gate printed a command and paused for a
   second shell.
2. **Reward signing + fee claiming = the default setup for every install** — the
   installer should set them up, not stop inert (operator chose: install auto-runs
   the wizard; `--inert` opts out; headless falls back to inert).
3. **Explain every step.**
4. **Paste the key directly into the terminal** — no pre-placed file.

All in `install/` + docs; no `src/` change.

## What changed

- **`install/onboard` → a guided wizard.**
  - All prompts read `/dev/tty` (single-terminal; works under `curl|sh` where stdin
    is the piped script). `TTY_OK` probe; recipient is prompted if `--recipient`
    is omitted.
  - **Paste-the-key import** (replaces print-command-then-pause): each key is
    **pasted (hidden, `stty -echo` before the prompt)** and piped straight into a
    0600 fwd-owned in-container temp (`docker exec -i … umask 077; cat > …`), then
    `clifwd wallets import --privkey-file … --shred-source`; the shell var is
    cleared and the temp shredded. No host disk artifact, no network. Blank = defer;
    a bad/duplicate key = warn + skip (never aborts). Signing key (both modes) +,
    with `--import-existing`, the executor + sender.
  - **Narrates each step** (numbered Step 1–8 with a one-line what/why).
  - Imported-sender nonces are prompted on `/dev/tty`; generated wallets stay 0.
- **`install.sh` → auto-runs the wizard by default.** New flags `--recipient`,
  `--networks` (default coston2), `--import-existing`, `--inert`. After bring-up:
  if NOT `--inert` AND fwd started AND `/dev/tty` is usable → run the wizard;
  else → the inert custody-gate banner (the fallback). Header doctrine reworded:
  the installer runs the guided onboarding by default; the custodial acts (pasting
  your key, on-chain auth) stay the operator's, inside the flow.
- **Docs** (`one-command-install.md`): rewards-by-default install, the paste UX +
  custody note (transient surface only; proportionate, Core #17), `--inert`.

The GATE-1 doctrine text moved from "fwd never reads key bytes; run these yourself"
to the accurate paste description: the key is pasted hidden, piped into the daemon
container, sealed, and the transient input shredded — never on host disk, never on
the network.

## Verification (Core #14 — isolated, production untouched)

Isolated `fwd-test` from the `fwd:dev` image, wizard driven under a real
controlling **pty** (`pty.fork()`) feeding scripted input:
- **generate mode:** recipient prompt answered; Steps 1–8 narrated; policy
  built/validated/loaded; `claimer-coston2` + `fsp-sender` generated in-vault;
  signing key **pasted (hidden) → imported + sealed → input shredded**; 3 tokens
  once; nonces 0; greenfield on-chain gate. Container temp confirmed absent.
- **import-existing mode:** 3 keys pasted (all hidden — none leaked to output) →
  imported + sealed + shredded; nonces seeded to the operator-supplied 5 / 7;
  CUTOVER gate. `wallets list` shows the 3; `policy validate` → VALID (schema +
  consistency).
- Echo race fixed: `stty -echo` runs **before** the prompt, so a fast paste can't
  echo.
- `install.sh`: `sh -n` clean; `--help` renders; `--inert`/headless → inert banner
  fallback; the auto-run handoff (`FWD_DIR`/`FWD_CONTAINER` → `install/onboard`) is
  the exact invocation the pty tests drove.
- Production `fwd` untouched. Live-Coston2 reward drill stays the operator gate
  (Core #15).
