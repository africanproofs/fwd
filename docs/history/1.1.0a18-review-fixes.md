# v1.1.0a18 — external-review doc fixes (doc↔code reconciliation)

**Ship type:** documentation reconciliation (Core invariant #18). No `src/` change.
Companion to a16 (README) + a17 (`docs/` tree). Driven by an independent read-only
review (a friendly-colleague LLM, against `src/fwd/`, `pyproject.toml`, `.env.example`,
`docker-compose.yml`) that found ~25 real doc↔code mismatches the a16/a17 sweep missed.
Every finding was **re-verified against the code** before fixing (the reviewer was
right on essentially all; the verification itself caught nuances — e.g. policy-load
"once at startup" is correct, only the *master key* load is per-op).

## Fixes by finding

**README.md** — env var is `DATABASE_URL` (not `FWD_DATABASE_URL`: `Settings` has no
`env_prefix`, and `database_url` is the one field without the `fwd_` prefix); sign
response is `{tx_id, hash, signed_raw_tx, nonce}` (added `hash`+`nonce`); master-key
bootstrap now shows the Docker-only `docker run … clifwd master generate` path (you
can't run `clifwd` before the container, and it can't boot without the key); added a
`cp docs/policy.example.yaml config/policy.yaml` step (missing-file→directory trap);
`wallets import` shreds **only** with `--shred-source`; runbooks doc-table entry now
flags the stale ones; status → a18.

**architecture.md** — **master key is loaded per signing operation** (each scope
constructs `SealedMaster`, reads the file, zeroizes on exit; `mlockall(MCL_CURRENT|
MCL_FUTURE)` at startup covers the pages) — corrected the 4 "loaded once at startup"
claims; **error envelope** is FastAPI `{"detail":{"error","message"}}` with no
`code`/`request_id` (the documented `{code,message,request_id}` was aspirational);
sign response `+hash+nonce`; "generated externally" → internal `create` / external
`import`; idempotency-replay returns the `SignTransactionResponse` (no `status`
field); litestream-on-default-bridge caveat; dead `runbooks/host-hardening.md` ref
removed. **Replacement lifecycle — documented current limitation:** `sign-replacement`
sets the tx to `replaced`, which `/broadcast-result` (wants `pending`) and `/receipt`
(wants `submitted`) reject — the replacement's outcome isn't reportable and the nonce
recovers only via `nonce-sync`; flagged as a follow-up code gap.

## Flagged for follow-up code ships (operator-gated)

1. **Replacement lifecycle gap** — a `replaced` tx cannot report its broadcast/receipt;
   nonce recovers only via `nonce-sync`. Close with a `replaced→mined/reverted`
   transition or a successor tx record.
2. **litestream egress** — pin `network_mode: none` (or the internal network) for a
   strict whole-stack zero-egress posture (it only writes a local volume today).
3. **`tenacity`** — unused since a9; remove from `pyproject.toml`/`poetry.lock`.
