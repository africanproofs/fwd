# v1.1.0a88 — install/compose wiring for clif's epoch-anchored sign→claim daemon

**Type:** `install/` + compose-overlay wiring (fwd-side of a clif feature). No fwd daemon change.
**Date:** 2026-06-06.

## Why

clif's two always-on 15-min pollers (`clif auto` = claim, `clif fsp auto` = sign) were
replaced by ONE epoch-anchored state machine, `clif epoch run` (clif 0.5.16, decisions D17):
per reward epoch — (optional) sign uptime → wait until epoch_end+initial_delay, poll for
reward publication → sign rewards → wait for the >threshold `rewardsHash` finalization →
claim only that epoch → idle. fwd owns the install/compose/onboard surface that launches
that daemon, so this ship rewires it. fwd itself is unchanged — it remains the passive,
zero-egress signer; clif still drives all timing and broadcasts.

## What changed (fwd repo)

- **`docker-compose.clif.yml`** — the 6 per-network services (`clif-auto-<net>` +
  `clif-fsp-auto-<net>`) collapse to ONE `clif-epoch-<net>` per network
  (`command: ["epoch","run"]`, `profiles: ["<net>"]`, healthcheck `clif epoch status`).
  The `<net>-fsp` profiles are gone (one daemon now does both signing and claiming).
- **`install/fwd`** — `fwd start <net>` brings up `clif-epoch-<net>`; the legacy `fsp`
  arg is accepted but maps to the same single daemon (with a note). Status/help/next-step
  text updated.
- **`install/onboard`** — `.env.<net>` now also writes `UPTIME_AUTO_ENABLED` (default
  false), `EPOCH_REWARD_INITIAL_DELAY_SEC` (3600), `EPOCH_POLL_INTERVAL_SEC` (1800), all
  `getval`-preserving across re-runs. The closing hint points at `FSP_AUTO_ENABLED=true`
  + `fwd start <net>` for the unified daemon.
- **`docs/production-setup.md`** — §6 "enable and start automation" rewritten to the
  single epoch daemon (one `fwd start <net>`; the gates + cadence knobs documented).

## Verification

`sh -n` + `dash -n` clean on `install/fwd` + `install/onboard`; both compose files are
valid YAML. The clif side (clif 0.5.16): `clif:dev` image builds with the new code;
in-container `clif epoch --help` shows `run`/`status`; `clif epoch run` hits the
FSP_AUTO_ENABLED hard-off gate (exit 2); `clif epoch status` reports no-state (exit 3);
13 new `tests/test_epoch_auto.py` + full clif suite (210 passed, 1 skipped). The live
Songbird end-to-end run at the next ended epoch is the standing real-infra gate (also the
deferred FSP on-chain acceptance proof).
