# v0.4.0a7 — Phase 5 alpha 4: admin wallet inventory + F6.3 CLI test coverage

**Shipped**: 2026-05-12
**Author**: Sonnet 4.6 (implementation), Opus 4.7 (Reviewer, canonical prompt + review + commit)
**Canonical prompt**: `~/.claude/plans/fwd-canonical-prompt-v0.4.0a7.md`
**Audit deferrals closed**: F7.2 (admin wallet inventory, Medium), F6.3 (CLI test coverage, Low).

## Why this ship

The last substrate alpha in Phase 5. Two audit deferrals from v0.4.0a1 close:

1. **F7.2** — `clifwd wallets list` returned a stub message ("not yet implemented") because `GET /v1/admin/wallets` didn't exist. Without admin visibility into the wallet inventory, ops had no way to enumerate what fwd custodied without `sqlite3 state.db "SELECT name, address FROM wallets;"`.

2. **F6.3** — Every CLI command (`version`, `health`, `wallets create | list | import`, `callers create | list | revoke`) had no unit-test coverage. CLI regressions could ship without surfacing in `pytest`.

After v0.4.0a7, **Phase 5 substrate is feature-complete**. The next ship is v0.4.0 GA — the live Coston2 verification gate (10-concurrent sign-and-send producing monotonic nonces + low-gas-replacement under live mempool).

## What ships

### Admin wallet inventory (F7.2)

- **`src/fwd/app/wallet_list.py`** (NEW, 23 lines) — `list_wallets(repo) -> list[Wallet]`. Mirrors `app/caller_list.py`. Docstring explicitly notes the api/ layer is responsible for stripping `privkey_ciphertext` and `vault_master_key` from the response — the Wallet dataclass exposes them, but the api/ layer never returns them.

- **`src/fwd/infra/wallet_repo.py`** (MODIFIED, +19 lines) — `list_all()` query ordered by `created_at`.

- **`src/fwd/app/dependencies.py`** (MODIFIED, +21 lines) — `WalletRepoCM` + `get_wallet_repo`. Mirrors `CallerRepoCM` exactly. Docstring clarifies that `SignerCM` still owns its own `WalletRepo` for the signing path; this CM is dedicated to read-only admin listing.

- **`src/fwd/api/wallets.py`** (MODIFIED, +48 lines) — `GET /v1/admin/wallets`, admin-gated. `WalletSummary` response model is **public-safe**: only `name`, `address`, `policy_path`, `created_at` (ISO-8601). Docstring explicitly states "NEVER includes `privkey_ciphertext` or `vault_master_key`" with the rationale ("leaking them defeats the Vault Transit envelope-encryption custody property — Core invariant #1").

- **`src/fwd/cli/wallets.py`** (MODIFIED, -15/+28 lines) — `list_command` stub replaced with real HTTP client. Table format: name(32) / address(44) / policy_path. Same env-var contract as `create` (`FWD_ADMIN_KEY`, `FWD_URL`).

### CLI test coverage (F6.3)

New test files using `typer.testing.CliRunner`:

- **`tests/unit/test_cli_main.py`** (NEW, 5 tests) — version output, health success/unreachable/5xx/env.

- **`tests/unit/test_cli_wallets.py`** (NEW, 14 tests):
  - create: success / missing_admin_key / 409 / unreachable
  - list: success / empty / missing_admin_key / http_error / unreachable
  - import: success / bad_mode / not_found / name_taken / address_mismatch

  Pattern: HTTP calls mocked via `patch("fwd.cli.wallets.httpx.<method>", ...)`. For `import`: mock `fwd.cli.wallets.import_wallet` (the use case) — avoids constructing real 0600 privkey files; the use case's own file-validation logic stays tested by `tests/unit/test_wallet_import.py`.

- **`tests/unit/test_cli_callers.py`** (NEW, 10 tests):
  - create: success / missing_admin_key / 409 / unreachable
  - list: success / empty / missing_admin_key
  - revoke: success / 404 / 409

### Endpoint tests with defense-in-depth no-leak scans

**`tests/unit/test_wallets_admin_list_endpoint.py`** (NEW, 7 tests):

1. `test_get_admin_wallets_returns_200_with_summary` — happy path. Assert key-set equality on every response item (`{"name", "address", "policy_path", "created_at"}` only). **Raw body bytes scanned for the strings `privkey_ciphertext`, `vault_master_key`, AND the literal fixture-injected ciphertext value `CIPHERTEXT_SHOULD_NEVER_LEAK`.** Triple-redundant defense against the cardinal "wallet ciphertext never leaves the host" property.

2. `test_get_admin_wallets_returns_empty_array_when_no_wallets`.

3. `test_get_admin_wallets_no_auth_returns_401`.

4. `test_get_admin_wallets_bad_admin_token_returns_401`.

5. `test_get_admin_wallets_caller_token_returns_401` — **D11 bright line on the new endpoint**. Presents a well-formed caller bearer token (`"fwd_live_" + "c" * 43`) and asserts 401. Failure message explicitly calls out "D11 VIOLATION" if hit. Reviewer ran this 5× consecutively during verification — zero flakes.

6. `test_get_admin_wallets_503_when_admin_key_unset` — fail-closed contract on `require_admin`.

7. `test_get_admin_wallets_no_secret_strings_anywhere` — belt-and-suspenders with 5 wallets in the response; same triple-scan as test #1.

### Repo tests

**`tests/unit/test_wallet_repo.py`** (+2 tests): `test_list_all_returns_all_wallets_ordered_by_created_at`, `test_list_all_empty`.
