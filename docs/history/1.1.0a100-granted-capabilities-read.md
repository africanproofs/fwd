**Type:** feature (read-only addition; the 3-artifact feature cap — **no invariant-doctrine change, no D-record**). Ratified under flaresystems **ADR-0003** (interface-cohesion; clif = reference; `fwd-client` unchanged).
**No custody mutation, no signing-path change** — `policy_engine`, sealed master, nonce manager, the sign endpoints, `caller_create` are UNTOUCHED. This is the deferred Unit-3 item #2 (`callers list` couldn't surface `capability_id` without a DB↔policy join — that join is this unit).
**Date:** 2026-06-10.

## Headline

A read-only, admin-gated **granted-capabilities** surface — `clifwd capability list` + `GET /v1/admin/capabilities` — listing the `capability_id`s the **live policy** governs, joined with each caller's status. This is the `doctor` three-way reconcile's "fwd=granted" leg (manifest=desired vs fwd=granted vs consumer=imported).

## The load-bearing design point — read the LIVE POLICY, not the audit log

The granted set is derived from the loaded policy's `CallerBinding`s (`app.state.policy`), NOT the caller-create audit trail. A **hand-edited** policy block (a `CallerBinding` with a `capability_id` added directly, never via `capability grant`) is the doctor's worst drift ("ungoverned grant") — it is in the live policy but NOT in the audit log, so reading the live policy is the only way to surface it (ADR-0001 §6). Each policy `CallerBinding` with a non-null `capability_id` is joined by name with its caller row for `status` (active/revoked) + timestamps; **sorted by `capability_id`** (R6) so the doctor diff is byte-stable across re-runs.

## What changed

- **`src/fwd/app/capability_list.py` (new)** — `GrantedCapability` + `list_capabilities(policy, caller_repo)`: the live-policy→caller-row join; pure read; sorted; `[]` when no policy loaded. A policy binding with no caller row is reported `status=active` with `granted_at=None`.
- **`src/fwd/api/callers.py`** — admin-gated `GET /v1/admin/capabilities` (read-only: policy read + `caller_repo` read; D11) returning `{capability_id, caller_name, policy_path, status, granted_at, revoked_at}`; and `capability_id` added to `CallerSummary`, populated from the live policy in `GET /v1/admin/callers` (the deferred Unit-3 convenience join). NEVER a token value or hash.
- **`src/fwd/cli/capability.py`** — `capability list [--json]` (folded into the unified `capability {grant,list}` group; `--json` = the raw array for a coordinator scrape, human table otherwise). The endpoint stays plural (`GET /v1/admin/capabilities` — REST collection); only the CLI verb unified to one singular noun-group (operator decision).
