## What shipped

The per-ship doctrine-surface rule (CLAUDE.md § Linear-forward versioning,
instituted v1.0.0) capped every ship at three doctrine artifacts. That cap
is correct for **feature ships** but structurally cannot govern two
legitimate non-feature acts: amending the constitution itself, and
reconciling invariant *text* to code a prior byte-verified ship already
made true. This amendment names two bounded non-feature ship-types so the
FSP doctrine reconciliation (Core #3 / #7 / #17 + CLAUDE.md:49) has a
compliant, non-fragmented home — and so 9b / 9c / 10x reuse it without
re-authorization.

- **Constitutional-amendment ship** — bounded surface: amended CLAUDE.md
  section(s) + a `docs/decisions.md` D-record + the three feature-ship
  artifacts + the two version files. Self-ratifying; never a Reviewer
  self-grant; explicit operator authorization is constitutive. **v1.1.0a3
  is the genesis instance** (it enacts D17).
- **Bounded post-verification reconciliation ship** — reconciles invariant
  text to a prior, already-shipped, byte/GATE-verified ship's code under
  four binding constraints (only-verified-text; inline `(code in ship X
  makes this true)` annotation; NO § Scope narrative paragraph; ONE
  coherent ship). Cannot ship until the reconciled code's gate passes.

Neither type relaxes Core invariant #18 — each *narrows* it by forcing
reconciliation into one annotated, operator-visible, gate-anchored ship
instead of leaking partial truth across feature ships.
