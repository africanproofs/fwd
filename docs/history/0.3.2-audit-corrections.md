### Doctrine codification

- **New Core invariant #18**: *Doctrine and code do not drift.* Every claim in `CLAUDE.md`, `decisions.md`, `architecture.md`, `threat-model.md` either describes existing code/config behaviour OR is explicitly marked deferred to a named phase. Drift is detected by audit; drift is fixed by aligning one to the other; drift is **never** tolerated as "we'll fix it later" without an explicit deferred-phase marker. The audit at v0.3.1 surfaced four documentation-vs-implementation gaps that had silently accumulated; v0.3.2 closed them and instituted this invariant to prevent recurrence.
- **Core invariants #1 and #16 rewritten** to honestly describe what `mlock` defends (kernel paging to swap) and what it does NOT defend (core dumps, `/proc/$pid/mem` reads, Python GC copies). The aspirational tone was replaced with an evidence-citing tone (specific file paths, specific test names).
