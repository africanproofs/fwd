# v1.1.0a103 — PROTOCOL_PAYLOAD bound to an explicit protocol-id allowlist

**Ship type:** feature (per-ship doctrine surface: this file + one README index line + the two version files).

**Role attribution:** grounded + implemented by Opus 4.8 directly (small, additive, fail-closed custody
tightening); operator-gated commit. Sonnet not involved.

## Why

`PROTOCOL_PAYLOAD` is the one deliberate path-(i) compromise (ADR-0005 §Raw-hash resolution): the
`submitSignatures` payload is opaque protocol bytes, so fwd `keccak` + EIP-191-signs the bytes rather than
reconstructing the preimage from typed fields. A friendly-adversary review (grounded 2026-06-14) asked
whether this opaque-bytes signing surface was bounded. It was bounded by **length only** — a holder of the
`protocol-message-sign` caller token could have fwd sign `keccak(any ≤ MAX bytes)` for an arbitrary
subprotocol. (It stays domain-separated from EVM-tx signing by the EIP-191 prefix, so it can never forge a
transaction — only a wrong consensus payload.)

ADR-0005 already *claimed* the policy was "bounded by protocol-id and length" — that was doc-drift; the code
bound only length. This ship makes the ADR claim true.

## What changed (`src/` — 4 files + 2 test files)

- `domain/policy.py` — `FspPermissionBlock` gains `allowed_protocol_ids: list[int]` (default empty).
- `app/fsp_policy.py` — `evaluate_fsp` adds a **fail-closed** gate for `PROTOCOL_PAYLOAD`, parallel to the
  existing UPTIME/`chain_ids` rule: a `PROTOCOL_PAYLOAD` permission block with **no** `allowed_protocol_ids`
  signs nothing; a `protocol_id` outside the allowlist is denied (both at step 5).
- `api/sign_fsp_message.py` — the `PROTOCOL_PAYLOAD` validator now **requires** `protocol_id` (so the gate
  always has it; previously audit-only).
- `app/policy_init.py` — the generated `fsp/protocol-message-<net>` block emits
  `allowed_protocol_ids: [100, 200]` (FTSO scaling + FDC, AP's mainnet subprotocols).
- `tests/unit/test_sign_fsp_message_policy.py` — 3 new gate tests (no-allowlist → deny; id-not-in-allowlist
  → deny; permitted id → signs). `tests/unit/test_fsp_message_extended.py` — fixture now supplies
  `protocol_id` (required).

Backward-compatible: the field is optional in the schema; only `PROTOCOL_PAYLOAD` is gated, and no live
caller uses `PROTOCOL_PAYLOAD` yet (fsp is pre-canary; clif/claim does not sign it).
