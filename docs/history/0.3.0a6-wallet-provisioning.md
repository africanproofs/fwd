## What landed

First real production code in `fwd`. The wallet provisioning path is complete end-to-end:

- `src/fwd/settings.py` — pydantic-settings `Settings` class; all env vars in one place; `get_settings()` lru-cached singleton.
- `src/fwd/domain/signer.py` — pure Protocol types: `SignedTransaction(NamedTuple)`, `Signer(Protocol)`.
- `src/fwd/infra/vault_client.py` — AppRole lazy login (D10 v1 strategy), `encrypt`/`decrypt` via `transit/keys/fwd-master`, 403-retry-once pattern, token zeroized on `__aexit__`.
- `src/fwd/infra/db.py` — async SQLAlchemy engine with SQLite pragmas (WAL, synchronous=NORMAL, busy_timeout=5000, foreign_keys=ON); `session_scope` context manager.
- `src/fwd/infra/wallet_repo.py` — `wallets` table definition (SQLAlchemy Core `MetaData`), `Wallet` frozen dataclass, `WalletRepo` with `create`/`get_by_name`, `WalletExistsError`/`WalletNotFoundError`.
- `src/fwd/infra/envelope_signer.py` — `EnvelopeSigner.create_wallet`: generate secp256k1 privkey → `bytearray` buffer → Vault encrypt → `WalletRepo.create` → zeroize in `finally`. `sign_transaction` raises `NotImplementedError` (lands in Phase 3c).
- `src/fwd/app/wallet_create.py` — app-layer orchestration; `VaultUnavailableError` wraps infra `VaultError` to maintain layer boundary; `WalletNameTaken` for 409 path.
- `src/fwd/app/dependencies.py` — `SignerCM` context manager assembles `VaultClient` + `AsyncSession` + `EnvelopeSigner`; `get_signer()` FastAPI dependency.
- `src/fwd/api/admin_auth.py` — `require_admin` bearer middleware; `hmac.compare_digest`; fail-closed 503 when `FWD_ADMIN_KEY` unset.
- `src/fwd/api/wallets.py` — `POST /v1/admin/wallets` returning 201/400/409/503.
- `src/fwd/cli/wallets.py` — `clifwd wallets create` command; HTTP-only, no direct infra dependency.
- `alembic/versions/0002_wallets.py` — migration creating the `wallets` table (name PK, address, privkey_ciphertext, vault_master_key, policy_path, created_at).
- `tests/conftest.py` — `needs_vault` skip marker; `tmp_state_db` fixture.
- 9 unit tests across settings, vault client, envelope signer, wallet repo, admin auth.
- 1 integration test: full roundtrip (create_wallet → commit → get_by_name → vault.decrypt → re-derive address → assert match).

## Deviations from canonical prompt

**Deviation 1 — VaultClient lazy login (D10 alignment)**
Spec had `await self._login()` in `__aenter__`. Moved login to first use inside `_request()` (`if self._token is None: await self._login()`). Reason: eager login in `__aenter__` breaks all unit tests that construct `VaultClient` without a real Vault; D10 explicitly names "login on first use" as the v1 strategy. Reported; Reviewer accepted.

**Deviation 2 — VaultUnavailableError at app layer (layer boundary enforcement)**
Spec's `api/wallets.py` imported `VaultError` from `fwd.infra.vault_client` directly. This violates the `api → {app, domain}` layer boundary (api cannot import from infra). Resolved by adding `VaultUnavailableError` to `app/wallet_create.py` and catching `VaultError` at `app/dependencies.py`, so the API layer only imports from the app layer. Reported; design improvement.

**Deviation 3 — Unused `Signer` import removed from envelope_signer.py**
Spec's import list included `from fwd.domain.signer import Signer`. The `EnvelopeSigner` class does not subclass `Signer`; it merely satisfies the protocol structurally. Removed to avoid ruff F401. Reported.

**Deviation 4 — ruff TC001/TC002/TC003 type-import fixes**
Multiple type-only imports required moving to `TYPE_CHECKING` blocks to satisfy ruff's import-classification rules. Affected files: `db.py`, `wallet_repo.py`, `envelope_signer.py`, `wallet_create.py`, `test_wallet_create_integration.py`, `conftest.py`. Reported.

**Deviation 5 — Check 9 URL: sync → async**
Canonical check 9 used `sqlite:////tmp/fwd-mig-test.db` (sync dialect). The alembic `env.py` uses an async engine (`aiosqlite`). Fixed to `sqlite+aiosqlite:////tmp/fwd-mig-test.db`. Reported.

**Deviation 6 — Dockerfile: /data chown + alembic auto-migration (spec gap)**
Spec did not include Dockerfile changes. Two issues surfaced during verification:
- The `/data` Docker volume is created root-owned; the non-root `fwd` user (uid=1000) could not write `state.db`. Fixed by adding `RUN mkdir -p /data && chown fwd:fwd /data` before `USER fwd`.
- The `alembic.ini` and `alembic/` directory were not copied into the image, so `alembic upgrade head` could not run in-container. Fixed by adding `COPY alembic.ini` + `COPY alembic/` to the runtime stage and changing CMD to `sh -c "alembic upgrade head && uvicorn ..."`.
Both fixes are load-bearing for the verification gate (Check 12 requires a live DB with schema). Reported.
