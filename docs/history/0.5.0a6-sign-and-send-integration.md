## What shipped

New `src/fwd/app/policy_gate.py` — `gate()` calls the a4 engine ONCE
(it decodes + evaluates all 10 D14 steps + increments rate), maps
`DenyDecision`→`PolicyDenied` (403); `release_rate_after_failure()`
undoes the step-8/9 rate increments on a post-Allow/pre-broadcast
failure, keys re-derived from `AllowDecision`+policy (no a4 engine
change), best-effort/never-raises.

`app/sign_and_send.py` — gate BEFORE nonce reservation; deny → audit
row `decision="denied"` → raise (api → 403); pre-broadcast failure →
release nonce (existing) + `release_rate_after_failure` + audit
`decision="error"` → raise; broadcast failure → audit `error`, do NOT
release rate (tx may be in mempools); broadcast success →
`add_committed_value` (wallet aggregate, same `now`) + audit
`decision="approved"`. `request_json` unified onto
`audit_repo._canonical_json` (resolves the pre-existing D16-conformance
drift). `ALLOWED_CHAINS` authZ reject removed.

`api/sign.py` — `wallet_repo.get_by_name` (404 if absent),
`app.state.policy`/`app.state.abi_registry` (missing → AttributeError →
500, fail-closed: no sign without a loaded policy), `PolicyDenied`→403
as the first except arm.

`main.py::_startup_policy_load` — `AbiRegistry.load` + `load_policy` +
`check_consistency`; writes the D16 `policy-load` audit row
(approved/error, outcome = the spec'd dict incl. policy sha256); on
errors logs each + `SystemExit(1)` (fail-fast); on success stashes
`app.state.policy`/`abi_registry`. Lifespan-gated: production
(`FWD_DISABLE_MLOCK != "1"`) always loads; test path loads only when
`FWD_POLICY_PATH` is set (existing integration tests, which set
`FWD_DISABLE_MLOCK=1` and no `FWD_POLICY_PATH`, are unbroken).

`settings.py` += `fwd_policy_path` (`/etc/fwd/policy.yaml`) +
`fwd_abis_dir` (`/app/config/abis`). `AbiRegistry.signatures_for` +
`policy_loader` check 3 (per-signature orphan; only when abi known).
`RequestScope` += `rate_repo`/`audit_repo`/`wallet_repo` on the one
shared session (single `BEGIN IMMEDIATE`, D16 atomic).

22 new tests incl. the 10-vector synthetic-attack default-deny matrix
(every D14 step → `PolicyDenied.step` + a `decision="denied"`
`sign-and-send` audit row + **`rpc.send_raw_transaction` NOT awaited**)
+ happy path; `test_policy_gate`, `test_abi_registry_signatures_for`,
`test_policy_loader_check3`, 1 gated integration smoke. NO Alembic
migration.

## Reviewer verdict: ACCEPT + 3 corrections at commit

The Reviewer did the binding file-by-file pass and independently
re-ran every gate (not trusting the subagent self-report). The six
spec-pinned safety properties were verified directly: (a) engine
called exactly once — no double rate-count; (b) release-on-failure
keys exactly mirror the engine's step-8/9 increments; (c)
`add_committed_value` only on broadcast success with the engine's
`now`; (d) audit shares the RequestScope session (no second session);
(e) no app.state-missing fallback that signs (fail-closed); (f)
lifespan gating doesn't break existing integration tests. The
synthetic-attack matrix genuinely asserts no-sign/no-broadcast on
every deny vector.

Three corrections (v0.4.0a5 precedent — Reviewer corrects at commit
when the canonical-prompt spec was wrong, documents it):

1. **path-a (real bug the subagent introduced + did not report).**
   `main.py:_startup_policy_load` error branch raised `SystemExit(1)`
   inside `async with session_scope()` after the error-append, having
   silently dropped the canonical-prompt §9 `await session.commit()`
   (and asserted the opposite in a comment). `SystemExit` is
   `BaseException`; `session_scope`'s `except Exception` neither
   commits nor rolls back, so the D16 forensic policy-load-error row
   was **discarded** (violates decisions.md:686 "the row remains as
   evidence"). Fixed: explicit `await session.commit()` before
   `raise SystemExit(1)`.
2. **path-c (dead code).** The `canonical_json` public alias added to
   `audit_repo.py` was grep-confirmed unused — sign_and_send/main use
   the (spec-permitted) private `_canonical_json`. Removed the
   speculative alias (Core invariant #3, surgical).
3. **Reviewer-owned logic fix (incomplete lift).** The chain-allowlist
   lift was half-done: `RpcClient.__init__` still hard-rejected
   `chain_id not in ALLOWED_CHAINS` where `ALLOWED_CHAINS =
   frozenset({114})`, so Flare/Songbird stayed blocked **regardless of
   policy** — defeating the operator's "policy is the gate" decision.
   The canonical-prompt §4 "do NOT modify infra/rpc.py (ALLOWED_CHAINS
   is just documentation)" was a Reviewer spec error: rpc.py had an
   active gate, not docs; the unit tests missed it because they
   `AsyncMock` the rpc and never construct a real `RpcClient`. Fixed:
   `ALLOWED_CHAINS = frozenset({14, 19, 114})` (the RPC-routing rail —
   chains fwd has a configured URL for; per-caller authZ is
   policy.yaml's job), docstring/comment/`RpcError` message corrected,
   and `tests/unit/test_rpc_client.py` two tests realigned
   (`test_allowed_chains_is_rpc_routing_set`,
   `test_unconfigured_chain_construction_raises` using chain 1).

The subagent's 6 reported deviations were all legitimate (unused-import
removals, `TC002` noqa, the smoke = policy-load + app.state assertion
per the spec's explicit permission, `attack9` mock-chain explanation).
The unreported dropped-commit is exactly why the binding Reviewer pass
re-runs everything rather than trusting the self-report.
