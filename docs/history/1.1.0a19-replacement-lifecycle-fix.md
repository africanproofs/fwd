# v1.1.0a19 — replacement lifecycle fix (keep tx `submitted` across replacements)

**Ship type:** code fix (the first of the three a18-review-flagged code gaps). The
a18 doc ship documented these as flagged limitations; this ship closes #1 and flips
its doctrine note to "fixed."

## The bug (a18-surfaced, code-verified)

`POST /v1/transactions/{tx_id}/sign-replacement` re-signs a stuck-but-submitted tx at
the same nonce with bumped fees, then set the tx status to `replaced`. But
`/broadcast-result` requires `pending` and `/receipt` requires `submitted` — so a
`replaced` tx was a **dead-end**: the replacement transaction's own receipt could not
be reported back (the nonce never marked confirmed — operator had to `nonce-sync`),
**and** a 2nd `sign-replacement` (also requires `submitted`) could never run, making
the documented "≤5 retries" cap **unreachable** (max 1 replacement).

## The fix (Option A — operator-approved)

Delete the single line `await scope.tx_repo.update_status(tx_id, "replaced")` in
`post_sign_replacement` (`src/fwd/api/transactions.py`). The tx now **stays
`submitted`** across replacements. Correct + sufficient because:
- `_hash_check` accepts ANY hash fwd recorded for the tx → the existing `/receipt`
  accepts the replacement's hash → `submitted → mined/reverted` + `mark_confirmed`
  runs. Gap closed with **zero new transitions**.
- Subsequent `sign-replacement` calls still see `submitted`, so the `≤5` cap
  (`len(all_attempts) >= 5`) is reachable.
- `list_stale_reservations` (the nonce/holes query) filters on `status == "pending"`
  only — a long-lived `submitted` tx never mis-surfaces as a hole (the existing
  `test_nonce_holes_submitted_tx_not_surfaced` already asserts this).
- `replaced` stays in `_VALID_STATUSES` but is now **vestigial** (no writer). No
  migration, no schema change.

## Tests (`tests/unit/test_replacement_and_nonce_sync.py`)

- `test_sign_replacement_happy_path`: post-replacement assertion `replaced` →
  `submitted` (+ docstring).
- **NEW** `test_receipt_after_replacement` (the gap-closer): submitted → replace →
  `/receipt(replacement_hash, mined_success)` → status `mined`, nonce
  `last_confirmed == nonce`. Added a `_make_report_client` helper mirroring
  `_make_replacement_client`.
- **NEW** `test_multi_replacement_reaches_cap`: 4 consecutive replacements all 200 and
  leave the tx `submitted` (5 attempts); the 5th → 409 `replacement_cap_exhausted`.
  (Pre-fix the 2nd would 409 `illegal_transition`.)
