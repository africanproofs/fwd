# v1.1.0a21 — tenacity removal (dead dependency)

**Ship type:** dependency hygiene (the third and last of the three a18-review-flagged
code gaps). Closes gap #3. **All three review-surfaced code gaps are now closed.**

## The gap

`tenacity = "^9.0"` was a main dependency that became **dead** at v1.1.0a9 — it was the
retry policy for RPC calls, and the zero-egress excision removed all RPC. Zero usage in
`src/` or `tests/` (no `import tenacity`, `@retry`, `wait_exponential`, `stop_after`),
and not a transitive dependency of any other package in `poetry.lock`.

## The fix

- Removed the `tenacity = "^9.0"` line from `pyproject.toml`
  `[tool.poetry.dependencies]` (left a struck comment documenting the removal, matching
  the `prometheus-client` precedent).
- Re-locked with **`poetry lock --no-update`** so ONLY `tenacity` is dropped and every
  other pin is preserved. (A bare `poetry lock` full re-resolve churned ~15 unrelated
  transitive deps — pydantic-core, sqlalchemy, ruff, certifi, … — and was reverted; a
  dead-dep removal must not silently expand the supply-chain surface. The `--no-update`
  diff is minimal: the `tenacity` stanza removed + the content-hash updated, package
  count 75 → 74, no version changes, nothing added.)
- `poetry install` synced the env to the minimal lock.
