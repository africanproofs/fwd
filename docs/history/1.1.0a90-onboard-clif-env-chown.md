# v1.1.0a90 — onboard chowns the clif env to the runtime user (fixes `clif … claim` permission-denied)

**Type:** install/onboard bugfix. No daemon/signing-path change.
**Date:** 2026-06-07.

## Symptom

After a from-scratch rebuild + `sudo fwd onboard rewards …`, a non-root
`clif --network songbird claim --type fee` failed immediately with:

```
open /opt/fwd/clif/.env.songbird: permission denied
```

The fwd daemon itself was healthy (sealed master ok, 3 wallets restored, policy
valid, audit chain intact) — only the clif consumer path was blocked.

## Root cause

The `clif` host wrapper (`install/clif`) runs `docker compose … run --rm clif` as
the **non-root operator**, so docker reads the clif `env_file`
(`/opt/fwd/clif/.env.<net>`) **host-side as that user**. `install.sh` chowns the
clif dir to `1000:1000` (the clif/fwd container user) at *install* time — before
the per-network env files exist. `onboard` runs as **root** (`sudo fwd onboard`)
and its `env_write()` created `.env.<net>` via `mktemp` + `mv`, leaving them
`root:root 0600` and **never chowning them back**. uid 1000 then could not read
them → permission denied.

A whole class: *onboard runs as root but writes artifacts the non-root wrappers
must read; every such artifact must be chowned to the runtime user* — `install.sh`
already does this for `config` + the clif dir (lines 180-181); `env_write` was the
gap.

## Fix

`install/onboard::env_write` now `chown 1000:1000 "$_ew_dst" 2>/dev/null || true`
after the atomic `mv` (matching `install.sh`'s clif-dir chown convention and its
non-root-install `|| true` guard). The file stays `0600` (keyless: wallet names +
caller tokens only, Core invariant #12) but is now owned by the operator/runtime
user, so the `clif` wrapper's host-side `docker compose` env read succeeds.

## Verification

Surfaced by the live from-scratch rebuild + retest (real-infra, Core invariant
#14 — a mocked test could not see the host file ownership). Immediate unblock on
the rebuilt host: `sudo chown -R 1000:1000 /opt/fwd/clif` then `clif … claim`
resolves. Forward: any onboard now writes operator-readable clif env files.
`sh -n` + `dash -n` clean on `install/onboard`.
