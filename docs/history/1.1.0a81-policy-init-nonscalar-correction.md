# v1.1.0a81 — correct a80's generated-policy over-tightening (non-scalar methods + chain_ids guard)

**Type:** correction of a same-day prior ship's generated-policy defect.
**Date:** 2026-06-06.

## Why (the defect class a80 introduced)

v1.1.0a80 flipped the generated claim/uptime/rewards methods to `allow_unconstrained_args: False` as its lever for tightening. But those three methods — `claim(_proofs tuple[])`, `signUptimeVote(tuple _signature)`, `signRewards(tuple[], tuple)` — all carry **non-scalar** args. fwd's fail-closed gate denies a non-scalar arg unless `allow_unconstrained_args: True` is set. So the a80 generator would have emitted a policy that **denies every claim and every FSP signature** — the wrong lever, and one that breaks the revenue path outright. a80 had correctly added the UPTIME cross-chain guard in *code* (`fsp_policy.py` requires `chain_ids`), but the generator never emitted a `chain_ids` allowlist for it to check.

## What changed (`app/policy_init.py`)

- Restored `allow_unconstrained_args: True` on `claim`, `signUptimeVote`, `signRewards`, each with an inline comment naming the non-scalar arg and the predicate that actually pins the constraint (`_recipient` for claim, `_rewardEpochId` for the FSP methods).
- Added `chain_ids: [chain_id]` to the generated `fsp_permissions` block — the **correct** mechanism for the a80 UPTIME cross-chain replay guard (FSP-CROSSCHAIN-001), matching what `fsp_policy.py` checks at gate step 4.

The constraint is now carried where it belongs: the per-arg predicates and the `chain_ids` allowlist, not a blanket non-scalar refusal that would have disabled signing.

## Verification

`generate_policy` output validates and loads; `test_policy_init` updated to assert the non-scalar flag is `True` on the three methods and that `fsp_permissions` carries `chain_ids`. Unit suite green.

## Files

`src/fwd/app/policy_init.py`, `tests/unit/test_policy_init.py`, version files.

## Lesson

This is the "defect found is a defect class" pattern (Core invariant #19): a80's UPTIME code-guard was sound, but the matching *generator* change was the wrong lever and would have failed closed against the operator. The instance fix is restoring the flag; the class fix is that a generated-policy change must be validated by loading the policy and confirming the intended call still *passes* — not only that the new constraint exists.
