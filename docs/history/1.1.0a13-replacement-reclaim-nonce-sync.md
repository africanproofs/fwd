# v1.1.0a13 — replacement + reclaim + admin nonce-sync

**Shipped 2026-05-27.** The hardening that closes the two robustness gaps the
sign-only model left: stuck-tx replacement (Core invariant #11, now client-driven)
and orphaned-reservation / nonce-drift handling (Core #4's reconciliation, now
client-fed). Operator-authorized.

## What shipped

**`POST /v1/transactions/{tx_id}/sign-replacement`** — client-triggered stuck-tx
replacement. Re-signs the **same recorded intent at the same nonce** with bumped
fees, returns the new `signed_raw_tx` for the client to re-broadcast. Guards:
caller-ownership (404), replaceable-state (`submitted` only, else 409), the bump
rule (`max_priority_fee ≥ ⌈prev×1.125⌉`, `max_fee ≥ prev`, under the global caps),
and the ≤5-attempt cap (Core #11). On sign failure the reserved nonce is **not**
released (the original attempt may be in mempools) and a forensic `error` row is
committed before a 503. Every refusal commits its forensic audit row before raising
(Core #5/#19). **Reclaim mechanic (operator-decided): same-intent replacement only —
fwd never hands a reserved nonce to a different intent.**

**`POST /v1/admin/nonce-sync`** (admin-only) — bounded-monotonic reconciliation of
fwd's nonce view to chain truth (an egressing operator/client supplies the on-chain
count; fwd can't self-probe). In-sync → no-op; a forward advance within
`FWD_NONCE_SYNC_MAX_ADVANCE` (default 64) heals a gap; a **rewind or a jump beyond
the bound is refused (409)** — that needs deliberate operator action, not an API
call.

**`GET /v1/admin/nonce/holes`** (admin-only, read-only) — surfaces orphaned
reservations (status `pending`, `reserved_at` older than
`FWD_RESERVATION_LEASE_SEC`, default 900s): the **operator-alarm** half of the
reclaim decision. fwd surfaces holes; it does **not** auto-reissue.

**Supporting:** `reserved_at` column on `transactions` (set at sign time); a new
`transaction_attempts` table (per-attempt gas/fee/signed_raw/hash/seq — the
original sign records attempt 1; each replacement records attempt N+1, so the bump
rule reads the prior attempt). New `ReplacementScope` (signer + tx + attempt +
nonce + audit on one session). `NonceRepo.set_next_nonce` (admin-only). Audit
actions `tx-replacement` + `nonce-sync`. Alembic migration `0007`. Settings
`fwd_nonce_sync_max_advance` (64) + `fwd_reservation_lease_sec` (900).

## Deviations (legitimate)

- The sign-replacement endpoint signs in the api/ layer; since api/ may not import
  `SealError` (infra), the catch around the single `signer.sign_transaction` call is
  broad (`Exception`, `# noqa: BLE001`), scoped to that call, and **commits a
  forensic `error` row then raises 503** — it does not swallow, and the nonce is not
  released. (A future cleanliness pass could extract an app-layer `sign_replacement`
  use-case to translate `SealError`→`VaultUnavailableError` and narrow the catch.)
- `attempt_repo` is an optional `None`-default arg on `sign_transaction` for
  backward-compat with existing tests; attempt-1 is recorded when present.
