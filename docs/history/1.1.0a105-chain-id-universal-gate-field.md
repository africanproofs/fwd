# v1.1.0a105 — chain_id is a universal FSP gate-scoping field

**Ship type:** fix (ship-blocker). Implemented by Opus 4.8 directly per the canonical prompt
`~/.claude/plans/fwd-canonical-prompt-chain-id-gate-field.md`; operator-gated. Bounded surface: the API
model + the message/fastupdate API-level tests + one new integration test + the two version files +
this history file + one README line.

## The bug (grounded 2026-06-14, friendly-adversary round 2)

`chain_id` plays two roles in the FSP path: a HASH field (REWARD_DISTRIBUTION + VOTER_REGISTRATION
chain_scoped only) AND a GATE replay-scoping field (`evaluate_fsp` denies a request whose `chain_id`
is not in the block's `chain_ids`, and REQUIRES non-empty `chain_ids` for UPTIME). The generated
fsp-voter policy puts `chain_ids` on every FSP sign block, but the API model `SignFspMessageBody`
FORBADE `chain_id` on UPTIME / SIGNING_POLICY / VOTER_REGISTRATION-legacy. So over real HTTP those
requests arrived with `chain_id=None` and the gate denied them — **UPTIME was structurally unsignable;
SIGNING_POLICY / legacy unsignable under the generated policy.**

Invisible to the unit tests because they build the app-layer `SignFspMessageRequest` dataclass directly,
bypassing the API validator. The fix is proven by a REAL-ASGI test, not a dataclass test (fwd Core #14).

## The fix

`chain_id` is now a universal REQUIRED gate-scoping field on every FSP message. In
`src/fwd/api/sign_fsp_message.py`: `chain_id: int = Field(..., ge=1)`; the `chain_id is not None`
prohibition is removed from the UPTIME, SIGNING_POLICY, and VOTER_REGISTRATION-legacy branches. The
HASH-construction is UNCHANGED — `app/sign_fsp_message.py::build_chain_id` still passes `None` for the
chainless types, so `domain/fsp_message.py::build_fsp_message` excludes `chain_id` from those preimages
and the golden hashes do not move. The gate, policy_init, and the domain layer are untouched.

## Required dependent follow-ups (NOT in this fwd ship)

The consumers must now SEND chain_id on every FSP message: `fwd-client/go` (mirror the validator change),
the two Go forks (populate chain_id), and clif's Python client (its UPTIME path). Until they do, the
canary cannot sign UPTIME/SIGNING_POLICY. The second adversary ship-blocker — the FSP rate caps below the
per-round duty cycle — is its own forward ship.
