# v1.1.0a58 — FSP daemon profile-split: `fwd start <net>` = claim only; `fwd start <net> fsp` opt-in

**Type:** compose + host-wrapper ship (`docker-compose.clif.yml`, `install/fwd`, docs). Reviewer-implemented (3 profile renames + 1 wrapper sub-case); verified by `docker compose config` per profile + `sh -n`. Operator-authorized ("fwd profile-split"). Closes the a56-surfaced FSP-daemon crash-loop (drill finding B).
**Date:** 2026-06-03.

## Why (drill finding B)

The second from-scratch live drill showed `clif-fsp-auto-<net>` crash-looping: `clif fsp auto` **refuses and exits** when `FSP_AUTO_ENABLED=false` (the default — "a valid signature over wrong data is irreversible", D15), and `restart: unless-stopped` loops it. Re-confirmed with the freshly-built clif (not an old-image artifact), so it is clif's deliberate fail-safe. Because a56's `fwd start <net>` started BOTH the claim and FSP daemons, the common "always-on claims, FSP-auto off" case got a crash-looping FSP container. Operator chose the fwd-side fix (profile-split) over a clif-side idle-when-disabled change.

## What changed

- **`docker-compose.clif.yml`:** the three `clif-fsp-auto-<net>` daemons move from `profiles: ["<net>"]` to `profiles: ["<net>-fsp"]` (coston2-fsp / songbird-fsp / flare-fsp). The claim daemons (`clif-auto-<net>`) keep `["<net>"]`. So `--profile <net>` activates ONLY the claim daemon; the FSP auto-signer is a separate opt-in profile.
- **`install/fwd`:** `fwd start <net>` → `--profile <net>` (claim daemon only); **`fwd start <net> fsp`** → `--profile <net> --profile <net>-fsp` (claim + FSP auto-signer). Help + header + `docs/one-command-install.md` updated. This matches clif's hard-off-by-default ethos: the FSP auto-signer is started only by an explicit `… fsp` (and is only meaningful with `FSP_AUTO_ENABLED=true` in `.env.<net>`).

## Verification (Reviewer)

`docker compose config` (base `.env` + only `.env.coston2`): `--profile coston2` → `fwd` + `clif-auto-coston2` (no FSP daemon); `--profile coston2 --profile coston2-fsp` → + `clif-fsp-auto-coston2`; the claim-only full config SUCCEEDS with only `.env.coston2` present. `sh -n install/fwd install/install.sh` clean. The live `fwd start <net>` start behavior follows directly from the profile activation (the a56/a57 drill already proved the per-network claim daemon comes up reading `.env.<net>` and reaching `fwd:8080`).

Note: a misconfigured `fwd start <net> fsp` while `FSP_AUTO_ENABLED=false` would still hit clif's refuse+exit (now an explicit operator opt-in, not the default path). The clif-side "idle instead of exit when disabled" robustness change remains available as a future consumer-lane improvement if wanted.
