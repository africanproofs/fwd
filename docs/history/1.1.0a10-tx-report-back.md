# v1.1.0a10 — tx lifecycle report-back + status model

**Shipped 2026-05-27.** With fwd now sign-only (a9), it had no way to learn what
became of a signed tx after the client broadcast it. This ship adds the
**client→fwd report-back** loop so fwd's tx + nonce state tracks chain truth, with
the multi-client trust boundary enforced.

## What shipped

Two caller-gated endpoints on `src/fwd/api/transactions.py`:

- `POST /v1/transactions/{tx_id}/broadcast-result` — body `{tx_hash, outcome,
  error_class?}` where `outcome ∈ {accepted, rejected_releaseable,
  rejected_nonce_too_low}`. `accepted` → `pending→submitted` (+ `submitted_at`).
  `rejected_releaseable` → `release_if_unused` (tail-only; a non-tail gap is left as
  operator-visible drift, reclaim is a later ship) then `→failed`.
  `rejected_nonce_too_low` → `→failed` with the nonce **NOT** released (chain is
  ahead of fwd; admin nonce-sync — a later ship — is required), recorded with that
  hint.
- `POST /v1/transactions/{tx_id}/receipt` — body `{tx_hash, outcome, block_number}`
  where `outcome ∈ {mined_success, mined_reverted}`. `mined_success` →
  `submitted→mined`; `mined_reverted` → `submitted→reverted` (new status). Both call
  `nonce_repo.mark_confirmed` — the nonce is consumed on chain even when the tx
  reverts.

**Trust boundary (multi-client §4.1):** every report enforces (1) **caller
ownership** — a caller reporting on another caller's tx gets 404 (no audit row, a
non-event); (2) **tx_hash validation** — the reported hash must be one fwd recorded
for that `tx_id`, else 409 `tx_hash_mismatch`; (3) **legal-transition guard** —
broadcast-result only from `pending`, receipt only from `submitted`, else 409
`illegal_transition`. The 409 refusals append a `denied` forensic audit row and
**commit before raising** so it survives the scope rollback (Core invariant #5/#19).

**Supporting changes:** new `"reverted"` status (`_VALID_STATUSES`); new audit
actions `"tx-broadcast-result"` / `"tx-receipt"`; a lightweight `ReportScope`
(`tx_repo + nonce_repo + audit_repo` on one session, **no Vault, no RPC** — the
report path never signs) in `app/dependencies.py`. Reuses the existing
`update_status` / `release_if_unused` / `mark_confirmed`; no new repo methods, no
schema change, no migration.

## Deviations (both legitimate, surfaced by the implementer)

1. `_ownership_check` returns `Any` rather than `Transaction` — importing the infra
   dataclass into `api/` violates the layer-boundary test; runtime behaviour is
   identical, mypy passes.
2. `AsyncSession.expire_all()` is synchronous in SQLAlchemy 2.x — called without
   `await`.
