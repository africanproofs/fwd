# v1.1.0a35 — install.sh: local end-to-end run + two fixes it surfaced

**Type:** deployment-scaffolding ship (no daemon code change). Provider-distribution Phase 1.
**Date:** 2026-05-31.
**Authoring:** Reviewer (Opus) implemented directly under operator direction; operator-gated.

## Why

The a33/a34 verification stopped before `docker compose up` (the live `fwd`
container would collide). With a34's configurable container name, install.sh's
**real `up`+health path** was run end-to-end locally — an isolated instance
(`FWD_CONTAINER=fwd-localtest`, `COMPOSE_PROJECT_NAME=fwdlocaltest` → own name +
project-scoped volumes/network) alongside the untouched production stack. It
booted healthy (`master=ok`, mlock, default-deny → sign-without-auth = 401), then
the custody-init tooling was exercised on it. The run **caught two real defects**
that staged (`--no-start`) testing could not — exactly the "real-infrastructure
verification" doctrine (Core #14): mocks/staged runs lie.

## What changed (the two fixes)

1. **Config co-located in the compose dir.** install.sh wrote `.env` to
   `$FWD_DIR` but the cloned `docker-compose.yml` resolves `env_file: .env` (and
   the `./config/*` mounts) relative to its own dir (`$SRC = $FWD_DIR/src`) →
   `up` failed `env file …/src/.env not found`. Fix: write `.env` +
   `config/{policy.yaml,master.key}` directly into `$SRC` (where the compose
   expects them, gitignored, preserved across the upgrade `git checkout`);
   dropped the symlink dance.
2. **Corrected the custody-gate onboarding ORDER.** The runbook (install.sh
   banner + `one-command-install.md`) had `wallets/callers create` *before*
   loading the policy. That fails: `wallets create` returned
   `400 unknown_policy_path` because the admin endpoints validate the requested
   `policy_path` against the **loaded (in-memory)** policy, which was still the
   inert default-deny. Correct order: `policy init` → `policy validate
   --schema-only` → **`fwd restart` (load it)** → `wallets`/`callers create` →
   full `policy validate` → `nonce init` → on-chain. (The policy loads fine
   before its wallets/callers exist — they're declared in
   `policy.wallets`/`policy.callers`, so consistency passes and there are no
   active callers to fail startup.)

## Verification (isolated local run; production untouched throughout)
- install.sh full run (`--with` no flags, fwd-core) under `fwd-localtest` /
  project `fwdlocaltest`: clone → build → master (0600/32B) → inert policy → host
  wrappers → **`up` → healthy → `{"master":"ok","fwd":"ok"}`**. mlock 275 MB;
  inert policy `VALID (callers=0)`; **sign without auth → HTTP 401** (default-deny).
- Custody-init on the instance (corrected order): `policy init` (coston2 claim) →
  `fwd restart` (load) → `wallets create` ✅ → `callers create` ✅ → full
  `policy validate` **VALID (callers=1)** → audit chain intact. Proves the
  installed stack is fully operable.
- Teardown: `docker compose -p fwdlocaltest down -v` + image removed. Production
  `fwd`/`fwd-litestream` stayed Up + healthy, audit chain intact (180 rows) the
  whole time.
