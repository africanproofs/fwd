# v1.1.0a60 — two-layer CLI output: compact operator cockpit by default, `--guided` for the walk-through

**Type:** install-script UX ship (`install/install.sh`, `install/onboard`, `install/fwd`, docs). Presentation-only — no custody/signing/broadcast/policy/nonce/daemon-profile/money-path semantics change. Reviewer-implemented; operator-authorized + plan-approved ("see this implementation through, do all the necessary reviews"). Verified by `sh -n` + `dash -n` (all five install scripts), an independent adversarial review (Opus, read-only), a stubbed-backend render drill (compact + guided), and the real `docker compose config` profile matrix.
**Date:** 2026-06-03.

## Why

The provider onboarding + lifecycle CLI was narrative-heavy: `install/onboard` read as a tutorial (3-capability block, long per-step explanations, a multi-branch final block); `install.sh` ended with an 11-line narrative; `fwd start` gave no feedback (it `exec`'d `docker compose up -d`, so nothing was printed); `fwd status` was raw `docker compose ps`. That serves a first-time provider but buries the "current state / next command" cockpit an experienced Flare operator wants. The fix is a two-layer model — **compact by default**, **guided on request** — with safety output unconditional in both.

## What changed

- **Output-mode mechanism** (`install/install.sh`, `install/onboard`): `OUTPUT` is resolved from `FWD_OUTPUT` (`guided`|`compact`, default compact) and flipped to `guided` by a new `--guided`/`--explain` flag. `onboard` gets a `guided() { [ "$OUTPUT" = guided ] && printf "$@"; return 0; }` helper that wraps explanatory text only. `install.sh` forwards `--guided` to the inline `--onboard-rewards` call. Unknown flags still `die`.
- **`install/onboard` — compact by default:** the 3-capability narration + function bullets, the `step`/`fsection` *explanations* (the section titles still print), the rehearse preamble, the decorative separators, and the doc pointer are now `guided`-only. A new **summary cockpit table** (`network · policy · wallets · callers · nonce · clif env`) prints in both modes. The on-chain block is compacted to role-labelled lines. **Every safety gate is byte-unchanged and prints in BOTH modes:** all interactive confirms (recipient/identity/key-paste/large-jump/rewind), all `warn`s (cutover, deferred/failed import, token loss/rotation, nonce drift, no-clif-layer, schema-validation-failed), the `cutover_msg`, the on-chain CUTOVER "STOP the old submitter" block, the "Verify the RewardClaimed event + clifwd audit verify (Songbird canary)" line, and the `⚠ UNRESOLVED NONCE DRIFT … exit 1` / `✓ onboard complete` terminators. The on-chain method names (`ClaimSetupManager.setClaimExecutors` etc.) and the "use the `clif` wrapper, NOT raw `docker compose run`" footgun-guard are unconditional (they are next-action instructions, not flavour — promoted from `guided` after the adversarial review's two MINORs).
- **`install.sh` — compact final block:** replaces the 11-line narrative with `fwd installed / fwd: <health> / clif: <built|fetched|not installed> / clif daemons: stopped / next: sudo fwd onboard rewards …`. `--guided` preserves the full block. The `--onboard-rewards` inline path is unchanged.
- **`install/fwd` — `start` + `status` cockpits:** `start)` no longer `exec`s — it runs `up -d` (under `set +e`, capturing the rc), prints a compact `started:` / `not started:` cockpit (clif-presence- and success-guarded), then `exit "$rc"`. **a59 profile semantics are byte-equivalent:** `fwd start` → no profile; `fwd start <net>` → `--profile <net>` (claim daemon only); `fwd start <net> fsp` → `--profile <net>-fsp` (FSP daemon only); bare `fwd start fsp` → `exit 2`. `status)` becomes a bounded cockpit (`compose ps` + per-network clif-env presence + a next-action hint). Help updated.
- **Docs:** `docs/one-command-install.md` (compact-default + `--guided`/`--explain`/`FWD_OUTPUT` in the host-command contract + onboarding flags; a new post-onboard go-live checklist) and `README.md` (one-line note). `CLAUDE.md` §Scope unchanged — CLI presentation is not a scope-level fact.

## Verification (Reviewer)

- `sh -n` AND `dash -n` clean on all five install scripts (`install.sh`, `onboard`, `fwd`, `clifwd`, `clif`).
- **Independent adversarial review** (Opus, read-only): executed the scripts under dash with a stubbed `docker`, probed every `fwd start` sub-command, the failure path, the summary-table glob, format-string injection, and the `HAS_CLAIM=0/HAS_FSP=0` worst case. Verdict SAFE-TO-SHIP, 0 BLOCKERs / 0 MAJORs; its two borderline MINORs (on-chain method names + raw-`docker compose run` caveat) were promoted to unconditional.
- **Stubbed-backend render drill** (no container, no prod contact): rendered `install/onboard rewards --networks coston2` in compact and guided. Compact dropped all narration but kept every `note`, the `no terminal to paste …` safety warn, the summary table (`coston2 ok defer ok defer written`), the on-chain checklist with method names, the rehearse caveat, and `✓ onboard complete` — a 7/7 safety-line presence check passed. The clif env was written keyless (no `PRIVATE_KEY`), 0600, `WRAP_REWARDS=false`, per-network sender, `FSP_AUTO_ENABLED=false`. `fwd start coston2` → claim daemon only; `fwd start coston2 fsp` → FSP daemon only; `fwd status` → cockpit.
- **Real `docker compose config` profile matrix:** default → `fwd`+`litestream`; `--profile songbird` → +`clif-auto-songbird` (no FSP); `--profile songbird --profile songbird-fsp` → +`clif-fsp-auto-songbird`; `--profile songbird-fsp` → `clif-fsp-auto-songbird` only (no claim); `--profile cli` → +`clif`. a59 mapping intact.
