## The Step-0 finding (the gate working as designed)

The plan through v3 prescribed `Account.unsafe_sign_hash` (raw-digest).
Byte-verifying the real `flare-foundation/signing-tool@838b87f` (v1.2.1,
`lib/ECDSASignature.ts`) before any code overturned this: signing-tool signs
FSP messages via web3.js `web3.eth.accounts.sign(messageHash, key)`, which
applies the **EIP-191 personal-message prefix**
`keccak256("\x19Ethereum Signed Message:\n32" || messageHash)`. The fwd
primitive is therefore `Account.sign_message(encode_defunct(primitive=
message_hash_32), key)` — NOT `unsafe_sign_hash`. A signature from the
planned primitive would have been rejected on-chain. Caught before code, by
the blocking Step-0 entry gate. Consequence: EIP-191 is not `eth_sign`
raw-digest, so CLAUDE.md:49 stays literally true; the 9a-iii doctrine
surface shrinks. Verified facts + frozen KATs:
`~/.claude/plans/fwd-step0-signing-tool-preimage.md`.
