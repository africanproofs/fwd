# v1.1.0a53 — onboard rewrite: no-hand-typed nonces, clif .env.<net> reconciliation, per-network FSP sender

**Type:** feature ship (host shell + compose + the two policy-gen files + their tests). Reviewer (Opus) prescribed a self-contained canonical prompt; Sonnet implemented in an isolated subagent; Reviewer binding-passed statically (file-by-file read + `sh -n`/`dash -n` + `docker compose config` + the policy suite). The live `up`/onboard drill runs on the **production host (operator-driven)** — fwd provides the exact commands.
**Date:** 2026-06-02.

## Why

**Ship B2** — the heart of the two-ship onboarding-cohesion redesign (B1 = a52 plumbing). The Flare/Songbird cutovers showed the wizard hand-typed on-chain nonces (error-prone — a fat-fingered `550` is what motivated a50's `nonce init --force`), printed caller tokens for the operator to copy by hand, and used a single shared FSP sender. This ship removes all three: chain truth is read through clif (which has egress; fwd stays zero-egress), tokens are written into clif's per-network env, and the FSP sender defaults to per-network.

## What changed

- **No hand-typed nonces (the state machine).** `install/onboard` replaces the `ask_nonce`/`seed_sender` hand-typed path with `reconcile_nonce`: for each sender wallet it reads `clif chain nonce --network <net> --address <addr> --json` via the B1 one-shot (egress in clif; the JSON is parsed by the fwd container's python, mirroring `chain_of`), then reconciles fwd's row — absent → `nonce init`; equal → in-sync no-op; fwd<chain → `nonce sync` (and on the bounded-monotonic 409, confirm/`--accept-pending-nonces` → `nonce init --force`); fwd>chain → confirm-or-leave (never silently rewind). `pending > latest` aborts the cutover with an explicit message unless `--accept-pending-nonces`. If clif is absent/unreachable it falls back to the manual prompt (graceful degradation; `CLIF_OK`).
- **clif `.env.<net>` reconciliation (first-class).** New `env_write` atomically (`mktemp` in-dir → `chmod 0600` → `mv`) writes each network's env: `NETWORK`, `FWD_ENDPOINT`, `IDENTITY_ADDRESS`, `CLAIM_RECIPIENT_ADDRESS`, `WRAP_REWARDS` (**preserve-existing-else-true**), `FWD_WALLET_NAME`, the three caller tokens, `FSP_SIGNING_WALLET_NAME`, `FSP_SENDER_WALLET_NAME`, `CLIF_STATE_DIR=.clif-state/<net>`, `FSP_AUTO_ENABLED` (preserve-else-false), and preserved RPC overrides. A pre-write `grep PRIVATE_KEY` guard refuses to ever write a key name (clif keyless invariant, defense-in-depth).
- **Caller tokens captured, not printed.** New `caller_ensure` mints → writes the token to env (prints only a 12-char prefix unless `--show-secrets`); on an existing caller it **preserves** the token already in the env, and with `--rotate-missing-callers` it `revoke` + `create --replace` (a51's revoked-name reuse) to re-mint when the token is lost and the env has none — otherwise it stops with a clear message. Without a clif layer, tokens are printed (no env to write to).
- **Per-network FSP sender is the default.** `generate_policy` + `clifwd policy init --fsp-sender` default flips `shared` → **`per-network`** (`fsp-sender-<net>`); the wizard creates the matching wallet and seeds its nonce per (sender, chain). `--fsp-sender shared` stays available. Atomic with the onboard rewrite, so there is no window where the generator emits a sender wallet the wizard doesn't create.
- **`--identity` re-added** to `install.sh` + `install/fwd` (B1 removed it as premature; this ship makes `install/onboard` accept it and write it as clif's `IDENTITY_ADDRESS`). New onboard flags: `--identity`, `--fsp-sender`, `--accept-pending-nonces`, `--rotate-missing-callers`, `--show-secrets`; a one-screen three-capabilities narration block.
- **Multichain daemons.** `docker-compose.clif.yml` gains `clif-auto-<net>` + `clif-fsp-auto-<net>` for coston2/songbird/flare under `profiles: ["multichain"]` (so `up`/`fwd start` don't auto-start them), each on its own `.env.<net>`. The existing `clif-auto`/`clif-fsp-auto` + the B1 one-shot `clif` are untouched.
