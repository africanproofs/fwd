# v0.3.0a5 — Doctrine: Enforced hand-off demarcation in canonical prompts

> Reviewer-only doctrine ship landed 2026-05-02. No Sonnet involvement. Locks the canonical-prompt hand-off format to a single mandatory shape.

## What this ship adds

A reinforced bullet under § Development workflow → Reviewer (Opus 4.7) — PRESCRIBES → "Reviewer obligations" in `CLAUDE.md`:

> **Demarcate every hand-off in canonical prompts with EXACTLY this format — no variations:**
>
> 1. A bold marker on its own line: `**HAND-OFF — <recipient> (paste verbatim into <destination>):**`
> 2. A blank line.
> 3. A fenced code block (4-backtick if the payload contains 3-backtick blocks; 5-backtick if nested deeper) wrapping the entire hand-off payload end-to-end. **Nothing outside the fences belongs to the hand-off.**

Plus a mandatory pre-handoff scan command:

```sh
grep -c '^\*\*HAND-OFF — ' ~/.claude/plans/fwd-canonical-prompt-<ship>.md  # ≥ 1
```

Plus the manual eyeball check that the line immediately after the bold marker is empty and a fenced block opens within the next 3 lines.

## Why

Pasting Sonnet "go look at this paragraph" rather than "copy these exact bytes between these fences" has been a recurring source of subtle deviations:

- **Truncation at paragraph boundaries.** Sonnet stops at the first apparent terminator (a blank line, a heading) and misses content that was logically part of the same hand-off.
- **Accidentally-included Reviewer asides.** A note like "Sonnet: this is the right approach because X" gets pasted into Sonnet's prompt, where Sonnet treats it as instruction rather than rationale.
- **Buried instructions.** A list item three layers deep gets noticed by the Reviewer but skipped by Sonnet.

The fence is a hard boundary. The operator copies verbatim between `\`\`\`\`` and `\`\`\`\``. Zero ambiguity. Sonnet sees exactly what the Reviewer intended.

## Enforcement model

The fence rule lives in CLAUDE.md (always loaded into agent context) under Reviewer obligations. Future Reviewer sessions reading their role doctrine see the rule before drafting. Pre-handoff scan is the explicit grep gate that runs before announcing a canonical prompt ready.

There is no automated CI test for this — canonical prompts live at `~/.claude/plans/`, outside the repo. Enforcement is Reviewer discipline + the grep check + operator-side verification (the operator can grep the prompt themselves before pasting).
