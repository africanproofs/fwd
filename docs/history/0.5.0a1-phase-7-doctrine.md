# v0.5.0a1 — Phase 7 doctrine (Reviewer-only)

**Shipped**: 2026-05-13
**Author**: Opus 4.7 (Reviewer). No Sonnet involvement.
**Predecessor**: v0.4.6 (`8cfd22c` — Phase 6 GA verification gate met live)

## Why this ship

Phase 7 is the most policy-shaped phase in the project: three substrate
pieces (policy engine, ABI intent decoder, hash-chained audit log) that
together implement Core invariants #2 (default-deny), #3 (sign intent,
never opaque bytes), and #5 (append-only audit log). Getting the
schemas wrong now is expensive — every Phase 8+ migration commits to
them.

v0.5.0a1 is a Reviewer-only doctrine ship that locks down the schemas
BEFORE any Phase 7 implementation alpha lands. Same pattern as
v0.4.0a4 (prompt-wrapper doctrine) and v0.3.3 (D11/D12/D13 pre-Phase-4
doctrine).

## What lands

### Three new decisions

**D14 — Policy engine implementation** (refines D13 with Phase 7 specifics):
- File location: `FWD_POLICY_PATH` env var (default `/etc/fwd/policy.yaml`); operator-mounted, gitignored
- Schema: Pydantic v2 strict; `version: 1` field; caller-keyed indirection per D13
- Method signatures use full ABI form (`claim(address,uint256)`), not bare names
- 10-step evaluation order (resolve caller policy → contract → decode intent → method → max_value → arg_predicates → wallet_allowlist → caller rate → wallet rate + aggregate)
- Rate-limit state: two SQLite tables (`rate_buckets`, `wallet_buckets`), fixed UTC-aligned buckets, stale-bucket cleanup at policy-load
- Reload semantics: startup-only in v1 (SIGHUP deferred to Phase 10)
- Startup fail-fast on orphan callers / orphan method signatures / orphan wallet refs

**D15 — ABI intent decoder shape and registry**:
- Library: `eth_abi` (already a transitive of `eth-account`; no new top-level dep)
- `DecodedIntent` dataclass: `(contract, method_signature, selector, args)`
- Pure function returns `None` on any failure; caller treats as default-deny
- ABI registry: in-repo `config/abis/<name>.json` + `registry.yaml`
- v0.5.0 scope: 3 ABIs (RewardManager, ParticipantRegister, ERC-20)
- Type support: address / uint* / int* / bool / bytes32 — dynamic types deferred

**D16 — Audit log hash-chain scheme**:
- SHA-256 (not BLAKE3 — no new wheel dep)
- Canonical sorted-key compact JSON for `request_json` + `outcome`
- Hash input: NUL-joined `(prev_hash, ts, caller, action, request_json, decision, decision_reason, outcome)`
- Genesis: `prev_hash = '0' * 64`
- One audit_log row per request (existing v0.4.0a3 schema supports this without migration)
- Writes share request's RequestScope session (v0.4.5 single-session-per-request invariant)
- `clifwd audit verify | show | tail` walker CLI lands at v0.5.0a4

## Operator decisions at v0.5.0a1

Four substantive choices were gated through `AskUserQuestion` before
the doctrine was written:

| Question | Decision | Rationale |
|---|---|---|
| ABI registry location | In-repo `config/abis/` | ABIs are public; bake-time pinning; no runtime explorer dep |
| Rate-limit state | Fixed UTC-aligned buckets | Simpler than sliding; Phase 10 can refine if production hits the boundary-burst case |
| Reload semantics | Startup-only in v1 | Cheap restart; policy changes are operator-gated anyway; SIGHUP deferred to Phase 10 |
| v0.5.0a1 doctrine ship | Approve as outlined | 5-alpha cadence + GA; doctrine lands first |

## What v0.5.0a1 deliberately does NOT do

- **Land any code.** Reviewer-only doctrine ship. The substrate alphas
  start at v0.5.0a2.
- **Modify existing tests.** No test changes; 215 + 3 skipped unchanged.
- **Backfill historical audit rows.** The audit log records forward
  from v0.5.0 only.
- **Hot-reload policy.yaml.** Startup-only in v1.
- **Support dynamic ABI types** (bytes, string, arrays, tuples).
  Decoder returns `None`; document the gap; add support when a real
  consumer needs it.
- **Lock-split the sign-and-send writer-lock critical section.** ~5–10
  ms additional holding time from audit + rate writes is within the
  30 s busy_timeout headroom; Phase 10 may revisit if production
  contention surfaces.
- **On-chain audit-log anchoring.** Phase 10 deliverable.
