# v1.1.0a47 — wizard polish: tidy the key-line punctuation + self-explanatory nonce prompt

**Type:** tooling ship (`install/onboard`; no daemon `src/` change).
**Date:** 2026-06-01. Reviewer (Opus); operator-gated. Verified under a pty harness.

## Why

Two operator-reported rough edges in the a46 wizard:
1. The per-wallet line rendered a **double em-dash** — the note's ` — <role>`
   separator plus an em-dash *inside* the role string
   (`… @ 0x… — your signing policy address — the _signature signer …`).
2. The a46 restructure folded the nonce step into each function section but
   **dropped the explanation**, leaving a bare `current on-chain nonce (tx count)
   for imported …` prompt that read cryptically next to the just-minted token.

## What changed

- **Tidied role strings** to use parentheses, not an internal em-dash, so each
  wallet line has a single separator: `… @ 0x… — your signing policy address (the
  _signature signer FlareSystemsManager.signUptimeVote/signRewards recovers)`.
- **Self-explanatory nonce prompt**: a one-line lead-in (`<wallet> sends
  transactions, so fwd needs its next nonce (fwd is offline; it cannot read the
  chain).`) then `nonce for <wallet> = its current on-chain transaction count (look
  up <address> on the block explorer; enter 0 if this key has never sent a tx)
  [default 0]:` — it now says what to enter, how to find it, and the default.

No behavior change; presentation only.

## Verification

pty-harness import-existing run: each wallet line shows a single ` — <role>` with
parenthesized detail; the nonce step prints the lead-in + the explorer-pointing
prompt and seeds the supplied value. `sh -n` clean.

## Files

`install/onboard`, version files. No `src/` change.
