# v1.1.0a45 — default onboarding network coston2 → songbird

**Type:** tooling/docs ship (`install/` + docs; no daemon `src/` change).
**Date:** 2026-06-01. Reviewer (Opus); operator-gated.

## Why

The wizard defaulted to `--networks coston2` and prompted for an
`fsp-signing-coston2` key. But **FSP signing only works on a network where your key
is a registered voter**, and AP is a registered FTSO provider on **Flare**
(signing policy `0x3FA07a1d…`) and **Songbird** (`0xfB021c01…`) only — there is no
Coston2 key, and an FSP signature from an unregistered key is rejected on-chain
(`invalid signing policy address`). The operator caught this: "which one for
coston2? I only have songbird and flare." Operator decision: **default to
songbird** (AP's canary; the key they actually hold).

## What changed

- **Default network coston2 → songbird** in `install/onboard` (`NETS`) and
  `install/install.sh` (`ONB_NETWORKS`) + their help/header text.
- **Worked examples converted to songbird** (chain 19, `*-songbird` names): the
  `install.sh` fallback banner runbook and the `docs/one-command-install.md` manual
  runbook + one-command/host-command examples.
- **`docs/policy.example.yaml` regenerated for songbird** — a faithful,
  YAML-identical render of `clifwd policy init --networks songbird … --capabilities
  claim,fsp` (Songbird RewardManager `0xE26AD68b…`, FlareSystemsManager
  `0x421c69E2…`, chains [19]); the eval-order header is preserved.
- **Registration caveat added** (docs + banner + onboard help): FSP signing needs
  your key registered as a voter on the chosen network — Songbird / Flare for AP;
  `coston2` only if you are a registered Coston2 voter (the claim path has no such
  constraint). The rehearse-then-mainnet guidance is now Songbird (canary) → Flare.

No behavior change beyond the default string; the wizard, paste import, and
`--networks flare`/`coston2` all work exactly as before.

## Verification

- Round-trip: the regenerated `docs/policy.example.yaml` is **semantically
  identical** to `clifwd policy init --networks songbird --capabilities claim,fsp`
  and passes `clifwd policy validate --schema-only` (3 callers / 2 permissions /
  3 wallet_constraints / 1 fsp_permissions).
- No stray `coston2` / `chain 114` left in the onboarding surface except the
  intentional registration caveats.
- `sh -n` clean on `install/onboard` + `install/install.sh`; doc fences balanced.

## Files

`install/onboard`, `install/install.sh`, `docs/one-command-install.md`,
`docs/policy.example.yaml`, version files. No `src/` change.
