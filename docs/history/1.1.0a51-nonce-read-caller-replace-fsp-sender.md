# v1.1.0a51 — nonce read-back + sync CLI, caller `--replace`, per-network FSP-sender capability

**Type:** feature ship (`src/` only). Reviewer (Opus) prescribed a self-contained canonical prompt; Sonnet implemented in an isolated subagent; Reviewer binding-passed; operator-gated. Purely additive — no existing behavior changes.
**Date:** 2026-06-02.

## Why

This is **Ship A** of a two-ship onboarding-cohesion redesign. The host-orchestration ship (Ship B — installer decoupling + the `fwd onboard rewards` wizard rewrite) needs four daemon capabilities to exist first, so the wizard can reconcile nonces without fwd touching the chain, rotate a caller whose one-time token was lost, and generate a per-network FSP-sender policy. Ship A adds exactly those capabilities and nothing else, so main stays green and each capability is unit-verifiable in isolation before the shell orchestration is built on top of it.

## What changed

- **Read-only `GET /v1/admin/nonce/{wallet}/{chain}` + `clifwd nonce get`.** Returns `{wallet, chain, next_nonce, last_confirmed}` or 404 `nonce_not_initialized`. No audit row (read-only, mirrors `GET /v1/admin/nonce/holes`; uses the existing `get_nonce_repo`/`NonceRepoCM`). The CLI exits 0 (found, body printed), 4 (absent), 2 (unreachable/no key), 1 (other). This is the read an egressing client / the onboarding wizard uses to branch absent vs in-sync vs ahead/behind before deciding `init` vs `sync` vs `init --force`.
- **`clifwd nonce sync`** — a CLI wrapper over the **existing** `POST /v1/admin/nonce-sync` (a13). Exits 0 (in_sync/advanced), 4 (not initialized), **5 (`nonce_sync_out_of_bounds`** — the bounded-monotonic guard rejected a large jump/rewind; the caller falls back to `nonce init --force`), 2 (unreachable/no key), 1 (other). No endpoint change.
- **`callers create --replace`** — re-mint a **REVOKED** caller under the **same name** (rotation). `CallerRepo.create` gains `replace: bool=False`: an ACTIVE caller is never overwritten (still `CallerExistsError`); a REVOKED caller + `replace=True` is UPDATEd in place to a fresh key/prefix/policy_path with `revoked_at=None` (prior key stays cryptographically dead). `replace` threads through `CallerCreateRequest` (recorded in the audit `request_json`), `POST /v1/admin/callers` (`replace: bool=False`), and the `--replace` CLI flag. Because the **name** is reused, policy `callers:`-block references stay stable across a rotation — no policy edit/restart needed. (The default `replace=False` keeps the revoked-name-permanently-blocked behavior intact.)
- **`generate_policy(fsp_sender_mode=...)` + `clifwd policy init --fsp-sender per-network|shared`.** `per-network` emits `fsp-sender-<net>` / `wc/fsp-sender-<net>` per network; `shared` keeps a single `fsp-sender` / `wc/fsp-sender`. Everything downstream (`wallets`, the submit `wallet_allowlist`, `wallet_constraints`, the `fsp_self_submit` carve-out for `fsp-signing-<net>`) references the variables, so it flows through. **The default is `shared` in this ship — deliberately additive, zero change to the generated policy.** Ship B flips the default to `per-network` (the operator-chosen greenfield default) atomically with the onboard rewrite that creates the matching wallets, so there is no transient window where a bare `clifwd policy init`/onboard produces a policy whose sender wallet the (unchanged) onboard script doesn't create.
