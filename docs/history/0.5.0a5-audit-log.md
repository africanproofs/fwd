## Phase-0 findings (folded into the canonical prompt)

1. **No Alembic migration.** D16 is explicit — `audit_log` exists
   since 0004. a5 ships NO migration; `audit_repo.py` defines its own
   `MetaData()` + Table mirroring 0004 for test `create_all` only
   (the `transaction_repo`/`rate_repo` house pattern).
2. **TZ hazard (highest-risk).** `_row_hash` hashes
   `ts.isoformat(timespec="microseconds")`. SQLite
   `DateTime(timezone=True)` drops tzinfo on round-trip (the v0.4.0a6
   receipt-watcher lesson). Naïvely, every `verify()` would
   false-fail. Fix pinned in the spec: a single `_as_utc()` applied
   symmetrically — at append-time hashing and at every read/verify
   path — so the isoformat string is byte-identical across the
   round-trip. The regression test opens a **fresh `AsyncSession`
   after commit** to exercise the real SQLite tz-drop.
3. **Pre-existing D16 drift (deferred).**
   `app/sign_and_send.py:227` (since v0.4.0a3) builds `request_json`
   with `json.dumps({...}, sort_keys=True)` — missing D16's
   `separators=(",", ":")` / `ensure_ascii=False`. Not a chain-break
   risk (the chain hashes the stored string verbatim) but a
   conformance drift. Unifying it onto `_canonical_json` is a
   **v0.5.0a6** integration task. a5 did NOT touch sign_and_send.py.

## Reviewer verdict: ACCEPT (no path-a/b/c)

All 6 Sonnet deviations legitimate:
1. `cast(CursorResult, ...)` + `cursor_result.lastrowid` for the
   INSERT'd seq — correct mypy-strict pattern for DML primary-key
   access (`Result` stub lacks `inserted_primary_key`).
2. `cast(int | None, result.scalar())` in `_min_seq` — correct
   `no-any-return` suppression (the spec's `# type: ignore[return-
   value]` was the wrong code).
3. `cli/audit.py verify` typed `int | None` (no `# type: ignore`) —
   correct Typer Optional idiom; the spec's type-ignore was unused.
4. `ruff format` reformatted 4 new files — spec-permitted style
   adaptation.
5. `test_cli_audit.py` uses monkeypatched walker functions (not a
   tmp-DB) because `get_engine`/`get_settings` are `@lru_cache`d so an
   in-process `DATABASE_URL` override after import does not redirect
   the engine; mirrors `test_cli_callers.py`'s httpx-mock pattern.
   Full repo+walker logic (incl. the TZ round-trip) is covered against
   real SQLite in `test_audit_repo.py`. Sound.
6. `timezone.utc`→`UTC` (ruff UP017) — correct.

Reviewer-verified independently: verify() linkage check chains on the
expected predecessor while the recompute uses the row's own stored
`prev_hash` (what was hashed at append) — a tampered `prev_hash` is
caught by linkage, a tampered field or stored `row_hash` by recompute;
windowed-anchor semantics correct and honestly documented (a window
after an upstream break still verifies its sub-range because the
anchor row's stored hash is intact). The TZ regression genuinely
round-trips through a fresh session. Layer boundaries clean
(`audit_repo` imports no app/api/cli; `audit_walk` no api/cli;
`cli/audit` no infra). No migration added; sign_and_send.py / docs/ /
version / CLAUDE.md untouched by Sonnet.

Cosmetic observation (not corrected): `cli/audit.py show()` formats
the null-JSON-field branch slightly differently from the parseable
branch — human-readable output only, not worth a path-c tweak.
