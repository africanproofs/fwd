# v1.1.0a31 — `clifwd policy init` (a29-schema policy generator)

**Type:** feature ship (operator tooling). Provider-distribution Phase 0, ship 2.
**Date:** 2026-05-31.
**Authoring:** Reviewer (Opus) implemented directly under operator direction; operator-gated.

## Why

Hand-authoring `policy.yaml` is the single most error-prone onboarding step — and
a29 made it harder (required `chains`, `allow_unconstrained_args` on the
non-scalar-arg methods, the recipient arg-predicate, the `fsp_self_submit`
carve-out, per-wallet `wallet_constraints`). A new provider (and AP) should not
have to assemble that by hand. `policy init` generates a correct, ready-to-edit
policy from a provider's networks + recipient, paired with the a30
`policy validate` gate.

## What changed

- **`clifwd policy init --networks <list> [--capabilities claim,fsp] [--recipient 0x..] [--out PATH]`**
  emits a complete a29-schema `policy.yaml` (stdout by default; `--out` to write).
  Per requested network it generates the claim block (RewardManager.claim,
  `chains:[id]`, `allow_unconstrained_args: true`, `_recipient` pinned,
  `max_value_wei "0"`, rate, wallet_constraints) and/or the FSP blocks (the
  `fsp_permissions` sign caller + the FlareSystemsManager `signUptimeVote`/
  `signRewards` submit caller, both with `allow_unconstrained_args`, the
  `fsp_self_submit` carve-out for the signing wallet, and a shared `fsp-sender`
  gas wallet). **Method signatures are DERIVED from the shipped ABI registry**
  (`signatures_for`), so they are byte-identical to what `check_consistency`
  validates — no hardcoded signature can drift from the ABIs.
- New `src/fwd/app/policy_init.py` (generator) + the `init` command in
  `src/fwd/cli/policy.py` (cli -> app boundary, like `policy validate`).
- New **`config/networks.yaml`** — chain id + RewardManager + FlareSystemsManager
  per flare/songbird/coston2. This is convenience DATA for the generator ONLY;
  the daemon's signing path stays chain-agnostic (reads addresses from
  `policy.yaml`, never this file). Public non-secret Flare constants; shipped in
  the image via an explicit single-file `COPY config/networks.yaml` (NOT a broad
  `COPY config/` — Core #12 / a28). Operator-overridable via `FWD_NETWORKS_FILE`.
- `src/fwd/settings.py`: `fwd_networks_file` (default `/app/config/networks.yaml`).

The generated names (`claimer-<net>`, `fsp-signing-<net>`, `fsp-sender`, callers)
are conventional defaults the operator renames; the SCHEMA is what this gets
right. Output is a starting point — the operator still creates/imports each
wallet, mints each caller token, and runs `policy validate` before deploy.
