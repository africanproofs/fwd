# v1.1.0a54 — review-fix: executable `install/clif`, real clif-presence gate, token validation before eval, no false "complete" on nonce drift, WRAP_REWARDS default false

**Type:** review-fix ship (host shell + a file-mode change + current-state docs). Reviewer (Opus) prescribed; Sonnet implemented in an isolated subagent; Reviewer binding-passed (file-by-file read + `sh -n`/`dash -n` + the `token_ok` sanity). Triggered by an independent adversarial review of the a53 onboarding rewrite. Live drill remains operator-driven on prod.
**Date:** 2026-06-02.

## Why

An independent "friendly-adversary" review of the a53 wizard surfaced defects; this ship fixes the ones that block a production onboarding drill. The review's own list missed the most load-bearing one (the file mode), which a verification pass against `git ls-files -s` caught — and which is COUPLED to the review's Finding 1.

## What changed

- **`install/clif` is now executable (mode 100755).** It shipped 0644 (created via `Write`; the static `sh -n`/`dash -n` gates never *executed* it; the a51/a52 binding-passes read content not mode). `install/onboard` execs it directly (`"$FWD_DIR/install/clif" chain nonce …`) and tests `[ -x … ]` — both fail on a 0644 file **even as root** (Linux `execve` needs an x-bit; `CAP_DAC_OVERRIDE` only helps if one is set). On a `--with-clif` prod install this silently made the wizard fall back to hand-typed nonces and skip writing `.env.<net>` — i.e. a53's two headline features no-opped. (The adversarial review missed this; the verification pass caught it.)
- **clif-presence now tests a real directory, not the exported var.** `install.sh` exports `CLIF_SRC` unconditionally even without `--with-clif`, so the old `[ -n "$CLIF_SRC" ]` was true on a base install (pointing at a non-existent dir). Changed to `[ -d "$CLIF_SRC" ]` in all three spots: `install/onboard` `CLIF_OK`, `install/onboard` Step-3 policy-load restart overlay inclusion, and `install/fwd`'s `fwd start` overlay inclusion (was `[ -f docker-compose.clif.yml ]`, which is always true since the source bundle ships that file → a base install's `fwd start` tried to start clif services with missing build/env paths). **This had to ship WITH the chmod:** the 0644 mode was accidentally masking the base-install case (CLIF_OK false anyway); making `install/clif` executable would otherwise have turned that into a live token-loss bug.
- **Caller tokens are validated before `eval`.** `caller_ensure` indirect-assigns tokens via `eval "$3=\$…"`; a token read from a hand-edited/corrupt `.env.<net>` containing `$(…)`/backticks/`;` would execute on rerun (onboard runs as root). New `token_ok` (`grep -qE '^fwd_live_[A-Za-z0-9_-]{43}$'`, matching fwd's `api_key.py` format) guards all three eval-assignments (minted / preserved-from-env / re-minted); a non-matching value dies before the eval.
- **Onboard no longer claims "complete" when a wallet was left with unresolved fwd-ahead nonce drift.** When fwd's nonce is AHEAD of chain and the operator declines the rewind, `reconcile_nonce` left the wallet as-is but the final line still printed "✓ onboard complete". Now a `ONBOARD_INCOMPLETE`/`UNRESOLVED_NONCES` flag is set on that path and the final output prints a loud "⚠ UNRESOLVED NONCE DRIFT" warning naming the wallets instead.
- **`WRAP_REWARDS` defaults to `false`** (operator directive — native FLR/SGB to recipient, not WFLR). `env_write` still preserves any existing value, so an env that already sets it is untouched.
- **Docs (current-state).** Added the a51 `GET /v1/admin/nonce/{wallet}/{chain}` endpoint and the `clifwd nonce get`/`nonce sync` + `callers create --replace` / `nonce init --force` CLI to the README + `architecture.md` API/CLI tables (they were omitted at Ship A).

Forensic scope-clean: only `install/clif` (mode 100755), `install/onboard`, `install/fwd` (shell) + the two doc tables; no other `src/fwd`, no compose, no version touched by the implementer.
