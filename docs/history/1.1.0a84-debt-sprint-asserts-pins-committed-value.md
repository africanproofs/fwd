# v1.1.0a84 — debt sprint: `assert`→explicit raise, custody pin tightening, `add_committed_value` to receipt path

**Type:** daemon correctness debt sprint (three items). One behavioural fix (cap accounting), two hardening.
**Date:** 2026-06-06.

## Why

The CTO engineering review flagged three immediate-priority debt items, two on the signing critical path:
1. `assert` statements used as runtime guards — stripped under `python -O`, the same defect class as the Core #11/a12 nonce-wedge.
2. Custody package pins written as bare carets (`^X`) — read as the Poetry default rather than a deliberate custody-supply-chain bound; silent API drift on `poetry update` is invisible to mocked tests.
3. `add_committed_value` debited the daily aggregate at **sign** time, not at **receipt** — so the aggregate cap could exhaust before confirmations arrived, contradicting D14 ("only committed value counts") and the code's own comment.

## What changed

- **`assert` → explicit raise (8 guards).** `infra/envelope_signer.py`: removed three dead `assert wallet is not None` (the repo `get_by_name` raises `WalletNotFoundError` itself), and `assert len(message_hash_32) == 32` → `raise ValueError`. `infra/transaction_repo.py`: three `assert status in _VALID_STATUSES` → `raise ValueError`. `infra/audit_repo.py`: action/decision asserts → `raise ValueError`, lastrowid assert → `raise RuntimeError`. Tests updated (`AssertionError` → `ValueError`).
- **Custody pins tightened.** `pyproject.toml`: `eth-account`, `eth-utils`, `coincurve`, `cryptography` moved from `^X` to explicit `>=A,<B` ranges (same resolved versions; explicit intent — these are custody-path supply-chain pins, not defaults).
- **`add_committed_value` moved to the receipt path (D14 correctness).** Removed from `app/sign_transaction.py` (sign time); added to `api/transactions.py` `post_receipt` on `mined_success` only. `ReportScope` / `ReportScopeCM` gain `rate_repo`; both report-test harnesses gain `rate_repo` + the `rate_metadata` table.

## Verification

783 passed, 1 skipped. Version-consistency test green. The aggregate is now incremented only on a client-reported `mined_success` receipt — matching D14 and the comment in `rate_repo.check_and_increment_wallet`.
