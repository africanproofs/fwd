# v1.1.0a89 — operator-docs refresh: concise README, new restore runbook, current install/onboard text

**Type:** documentation + install operator-text. No daemon or behaviour change.
**Date:** 2026-06-07.

## Why

The README had drifted into a second, stale runbook (verbose, missing the reward
onboarding wizard, still describing the retired two-poller daemon model). The
operator docs needed to be accurate to the current state — inert-by-default install,
opt-in `fwd onboard rewards`, the single `clif-epoch-<net>` sign→claim daemon — and a
real restore runbook needed to exist (the prior `RESTORE-RUNBOOK.md` was a gitignored
off-host placeholder).

## What changed

- **`README.md`** — rewritten as a concise current front door (~127 lines, ~−340):
  what fwd is (zero-egress sign-only) → install (inert) → opt-in onboard (`fwd onboard
  rewards --identity … --recipient …`) → enable + `fwd start <net>` (single epoch
  daemon; legacy `… fsp` maps to the same one) → daily commands → what's deployed →
  doc index. No stale-runbook markers.
- **`docs/restore-runbook.md` (new)** — step-by-step host recovery: stage software
  `--no-start` → restore `master.key`/`policy.yaml`/`.env`/clif envs (0600, uid 1000) →
  restore SQLite (cold copy or Litestream replica) → start + `clifwd health/audit
  verify` → reconcile nonces (`clifwd nonce get`/`sync --on-chain-count`) → deliberate
  resume. Safe by construction: reuses sealed ciphertext (never re-pastes keys);
  master-key-lost ⇒ regenerate + re-onboard + re-authorize (Core #17 DR).
- **`docs/architecture.md` / `docs/dependencies.md` / `docs/one-command-install.md`** —
  brought current: single epoch daemon, `--with-clif` overlay services, de-Phased
  wording, `implementation-plan.md` → `docs/history/implementation-plan.md`. The
  architecture policy example is updated to the current generated shape **and** prefixed
  with "don't hand-write — generate via `clifwd policy init`; canonical example is
  `policy.example.yaml`" (kills the example-drift class).
- **`install/install.sh` / `install/onboard` / `install/fwd`** — operator-text only:
  `RESTORE-RUNBOOK.md` → `docs/restore-runbook.md`; onboard usage/hints now teach the
  canonical `fwd onboard rewards` (alias `clifwd onboard rewards` noted); the §8
  comment corrected to "onboard only if --onboard-rewards (+TTY)" (the logic was already
  opt-in); the `fwd start` synopsis drops the legacy `[fsp]` (prose still documents it).
