**Type:** doctrine + operational-record ship (DR runbook + operator-directed CLAUDE.md index; no daemon `src/` change). The Songbird cutover itself is operational — the prod `policy.yaml` is gitignored config (never committed) and the clif repoint lives in the clif repo.
**Date:** 2026-06-01. Reviewer (Opus); operator-gated.

## Why

Production `fwd` was signing Songbird FEE claims from AP's **identity** key
(`clif-claimer-sgb-prod` @ `0xcf3A3e…`) — a doctrine violation (fwd must never hold
identity keys; offline only). Moving claims onto a dedicated **executor**
`clif-claimer-mainnet` @ `0x0A3358…` is the fix. The operator asked for a disaster-
recovery runbook for the sealed-master backup taken during this work ("write the
restore run book. make it gitignorable") and to index it in CLAUDE.md.

## What changed (committed)

- **`RESTORE-RUNBOOK.md`** authored — how to restore fwd's wallets from the sealed-
  master backup (`master.key` + `state.db` + `policy.yaml` + env) onto a new/rebuilt
  host: source+image → place secret config → create the volume → overwrite the DB via
  a throwaway container (clean WAL/SHM) → start → verify (`clifwd health`/`wallets
  list`/`audit verify`) → reconcile nonces (fwd is zero-egress). It references the
  backup bundle, so it is **gitignored** (Core #12) and kept WITH the off-host bundle.
- **`.gitignore`** — `/RESTORE-RUNBOOK.md`.
- **`CLAUDE.md` § Scope** — a one-line DR pointer to `RESTORE-RUNBOOK.md`.
  Operator-directed ("index the runbook on CLAUDE.md"); a standing current-state fact
  (where DR is documented), not version archaeology — disclosed here per Core #18 (it
  is an artifact beyond the 3-artifact feature-ship cap, authorized by operator

  `IDENTITY_ADDRESS` (`0xcf3A3e…`), a **separate** env var, never from the signing
  wallet (`clif/claimer.py` `build_claim_calldata(beneficiary=identity_address, …)`
  then signs with `wallet=fwd_wallet_name` — orthogonal; clif never resolves the
