# v1.1.0a15 — no-host-port correction (internal:true removes port publishing)

**Shipped 2026-05-27.** A bounded reconciliation: the **a14 production cutover**
(redeploying fwd to the zero-egress code on the `internal: true` network) surfaced
that the a11 claim "published ports still work under `internal: true`" is **false**.
This is the Core invariant #14/#18 pattern again — a property assumed in doctrine,
proven wrong only when run on real infrastructure.

## What was found (at the cutover)

After `docker compose up -d --build fwd` brought up the a14 container on the
`internal: true` network:
- `docker port fwd` → **empty** (no published port); host `curl 127.0.0.1:8080`
  → **connection refused**. `internal: true` removes the network's gateway, and
  with it host→container port publishing — a `ports:` mapping is silently
  ineffective.
- **Intra-network reach works**: a container on `fwd-callers` → `http://fwd:8080`
  → `{"master":"ok","fwd":"ok"}` (no `rpc` field — a14 confirmed).
- **Admin works in-container**: `docker exec fwd clifwd health` → ok;
  `FWD_ADMIN_KEY` is in the container env; `GET /v1/admin/nonce/holes` → `[]`.

So fwd is fully functional; only the host-side convenience port is gone.

## The correction

- `docker-compose.yml` — removed the ineffective `ports: 127.0.0.1:8080:8080`
  line; replaced it + the networks comment with the honest access pattern:
  **no host port; clients reach `fwd:8080` intra-network; admin via
  `docker exec fwd clifwd …`; for host-port access, an override must drop
  `internal: true` AND block egress at the host firewall.**
- `docs/history/1.1.0a11-*.md` — the false claim struck through + annotated
  (honest history; not silently rewritten).
- `CLAUDE.md` "No network egress" IS-NOT bullet — corrected ("no host port;
  admin via docker exec").

## Why this is the right trade

The operator's mandate is "no egress" (strong). `internal: true` delivers it
provably (no route — verified a11) and entirely in the compose file (no host
`iptables` dependency). Losing the host port is an acceptable price: admin runs
via `docker exec`, and clients (clif, …) reach fwd over the internal network —
which is the production access path anyway.

## Verification

No code/test change — full suite unchanged (474/1). The production fwd is running
