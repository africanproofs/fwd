# v0.5.0a3 — ABI intent decoder substrate (Sonnet-implemented, Reviewer-reviewed)

**Shipped**: 2026-05-13
**Author**: Sonnet 4.6 implementer subagent (code + tests) under Opus 4.7
Reviewer prescription + verification. First Phase 7 code ship.
**Predecessor**: v0.5.0a2 (`f1ee3f1` — Phase 7 doctrine self-review corrections)

## Why this ship

Phase 7's policy engine (v0.5.0a4) cannot evaluate `arg_predicates` until
calldata is decoded into typed arguments. v0.5.0a3 lands that decoder as
pure substrate — no sign-and-send integration (that is v0.5.0a6).

## The six doctrine corrections (Reviewer-applied at commit)

Surfaced at Phase-0 planning; folded into this code ship per the
v0.4.5/v0.4.6 combined-ship precedent (fix code + doctrine together
when implementation/exploration surfaces drift — Core invariant #18
flowing both ways in one ship). Operator chose "fold into a3" over a
separate doctrine-only ship.

1. **Struct-array undecodability vs Phase 8.** D15 a1 said
   tuples/arrays → decoder returns `None`. FTSO `claim`/`autoClaim`
   (Phase 8's target) carry `(bytes32[],(uint24,bytes20,uint120,uint8))[]`.
   Resolution: **B1 projection** — decode the FULL calldata via
   `eth_abi` (a complete codec — verified), project only
   predicatable-scalar top-level args into `.args`, omit complex args
   (still visible in `method_signature`). `None` only on decode
   *failure*. The four custody-relevant `claim` scalars
   (`_rewardOwner`, `_recipient`, `_rewardEpochId`, `_wrap`) are
   projected and predicatable; the proof array is not (nobody
   predicates merkle internals).
2. **Hazard #1 factually wrong for installed library.** D15 a1
   prescribed a strip-32→20-and-lowercase address step. `eth_abi` 5.x
   returns `address` as a lowercase `0x`-hex `str` already —
   implementing the strip would double-process a `str` and break. The
   decoder passes addresses through unchanged;
   `test_erc20_transfer_address_already_lowercase_from_eth_abi` asserts
   the library invariant as a regression guard.
3. **`DecodedIntent.contract` "checksummed" → "lowercased"** — consistent
   with `.args` addresses and the registry key.
4. **Registry "keyed by (contract_address, selector)" is physically
   impossible** (the same ERC-20 ABI serves many token addresses;
   `reward_manager` serves Flare + Coston2). Keyed `(abi_name,
   selector)`; `request.to → abi_name` is a `policy.yaml` binding (D14);
   the policy engine composes the address→name→registry path.
5. **"v0.5.0 ABIs do not use unsupported types" false at ABI level** —
   their `view` methods + FTSO proof arrays use tuples/arrays. True only
   for the **signable** surface, via B1.
6. **"no new top-level dep" reconciled** — refers to the lockfile graph
   (unchanged); the explicit `eth-abi` edge is correctness, not new
   surface.

`docs/decisions.md` D15 and `docs/architecture.md` § Intent decoder
were rewritten accordingly.

## What v0.5.0a3 deliberately does NOT do

- No sign-and-send integration (v0.5.0a6).
- No policy engine / `policy.yaml` parsing / `request.to → abi_name`
  resolution (v0.5.0a4, D14).
- No audit log substrate (v0.5.0a5, D16).
- No deep dotted-path predicate projection for nested args (Phase 10 if
  a real consumer needs it — no speculative scope).
- No ABIs beyond the three (one-file PR when a new consumer lands).
