# v1.1.0a57 — install.sh builds the clif image (a56 regression fix; caught by the live drill)

**Type:** fix ship (`install/install.sh`). Reviewer-implemented (3-line shell fix); `sh -n` clean; confirmed on real infrastructure by a from-scratch isolated re-drill (the defect a56 introduced, and the fix, are both build-time — only a live `--with-clif` install exercises them).
**Date:** 2026-06-03.

## Why (a live-drill catch)

a56 removed the *unprofiled* single `clif-auto`/`clif-fsp-auto` services, leaving EVERY clif service profile-gated (`cli` for the one-shot, `<net>` for the per-network daemons). `install.sh`'s build step ran `docker compose $COMPOSE build` with **no `--profile`**, which builds only services in active profiles + unprofiled ones — i.e. only `fwd`. So under `--with-clif` the shared `clif:dev` image was **never built**. On a fresh host the clif image would be missing entirely → `clif chain nonce` (the onboard wizard's nonce read) and `fwd start <net>` (the per-network daemons) both fail. A from-scratch a56 drill caught it: `clif:dev` was the stale pre-existing image (build skipped clif), `clif chain nonce` returned "No such command", and onboarding fell back to manual nonce entry (the a55 fallback handled it cleanly — `init 0`, exit 0 — which is why it didn't hard-fail). The a55 drill missed this because a55 still had the unprofiled clif services, so a bare `compose build` built `clif:dev`.

## What changed

`install/install.sh` build step: under `--with-clif`, add `--profile cli` to the `docker compose build` so the `clif` service (cli profile) builds the shared `clif:dev` image (the per-network daemons reuse it). Without `--with-clif` the build is unchanged (fwd only). Three lines: a `_build_prof` var set to `--profile cli` when `WITH_CLIF=1`, passed into the build invocation.

## Verification

`sh -n install/install.sh` clean. Confirmed by an isolated from-scratch re-drill built from this commit (`fwd:drill` + `clif:dev` both built; `clif chain nonce` reads the live chain; `fwd start <net>` brings up the per-network claim daemon) — prod untouched, `clif:dev` backed up + restored. (See the SHIP-LOG / drill notes for the run.)

## Known item flagged separately (NOT fixed here) — `clif fsp auto` crash-loop when disabled

The drill also showed `clif-fsp-auto-<net>` crash-looping: `clif fsp auto` **refuses and exits** when `FSP_AUTO_ENABLED=false` (the default; "a valid signature over wrong data is irreversible — D15 §5"), and `restart: unless-stopped` then loops it. This is **pre-existing clif behavior** (the single `clif-fsp-auto` had the same `command: ["fsp","auto"]`), surfaced by a56's `fwd start <net>` starting the per-network FSP daemon. The per-network CLAIM daemon (`clif-auto-<net>`) runs clean. Fix is a design call (operator-pending): clif-side "idle instead of exit when disabled" (consumer/sibling lane), and/or a fwd-side compose split so `fwd start <net>` starts only the claim daemon and the FSP daemon is an explicit opt-in. Not bundled into this regression fix.
