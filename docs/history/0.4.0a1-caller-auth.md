# v0.4.0a1 — Phase 4: Caller Authentication

**Shipped:** 2026-05-07

## Summary

Phase 4 ships per-caller bearer-token authentication via argon2id-hashed API keys. `/v1/sign-and-send` no longer accepts the admin key — callers must present a `fwd_live_<43-char-base64url>` key issued by the admin CLI. D11 (admin/caller auth bright line) is enforced structurally (separate modules, no shared import) and behaviourally (dedicated test file).

## Deliverables

### infra layer
- `src/fwd/infra/api_key.py` — `generate_api_key()`, `extract_prefix()`, `verify_api_key()`. Key format: `fwd_live_` (9) + `secrets.token_urlsafe(32)` (43 base64url chars) = 52 chars total. 8-char prefix indexed for O(1) DB lookup. argon2id hash via `argon2-cffi` with library defaults.
- `src/fwd/infra/caller_repo.py` — `CallerRepo` with `create`, `get_by_name`, `list_by_prefix_active`, `list_all`, `revoke`. SQLAlchemy `Table` definition; exceptions: `CallerExistsError`, `CallerNotFoundError`, `CallerAlreadyRevokedError`.
- `src/fwd/infra/envelope_signer.py` — added `import_wallet()` (mirrors `create_wallet` but accepts external privkey bytearray; validates 32-byte length, derives EIP-55 address, checks `--expected-address`; zeroizes in `finally`). Added `WalletImportInvalidLength`, `WalletAddressMismatch` exceptions.

### app layer
- `src/fwd/app/caller_create.py` — `create_caller(request, repo)`. Generates key in-process; persists hash (not plaintext); logs `caller.create.ok` without `api_key`.
- `src/fwd/app/caller_resolution.py` — `resolve_caller(presented_key, repo)`. Prefix-lookup → argon2id verify candidates → returns `Caller | None`.
- `src/fwd/app/caller_revoke.py` — `revoke_caller(name, repo)`. Wraps repo errors into `CallerNotFound`, `CallerAlreadyRevoked`.
- `src/fwd/app/caller_list.py` — `list_callers(repo, *, include_revoked=True)`.
- `src/fwd/app/wallet_import.py` — `import_wallet(request, signer)`. Enforces D9 refusal table (6 checks). `_shred_file()` for optional `--shred-source`. Re-exports `WalletAddressMismatch` so `cli/` imports from app layer.
- `src/fwd/app/dependencies.py` — added `CallerRepoCM`, `get_caller_repo()`. Added `from fwd.infra.caller_repo import Caller as Caller` (explicit re-export so `api/caller_auth.py` can import from app layer).

### api layer
- `src/fwd/api/caller_auth.py` — **new module, D11-isolated**. Imports NOTHING from `admin_auth`. `require_caller()`: extracts Bearer token → calls `resolve_caller` → stashes `request.state.caller` → returns `Caller`. 401 on any failure (no oracle). `caller_required = Depends(require_caller)` re-exported.
- `src/fwd/api/callers.py` — `POST /v1/admin/callers` (201/400/409), `DELETE /v1/admin/callers/{name}` (204, `response_model=None` explicit), `GET /v1/admin/callers` (200). All admin-gated. `_NAME_RE = re.compile(r"^[a-z0-9][a-z0-9_-]{0,63}$")`.
- `src/fwd/api/sign.py` — swapped `admin_required` → `caller_required`. Docstring updated.
- `src/fwd/main.py` — registered `callers_router`.

### cli layer
- `src/fwd/cli/callers.py` — `create`, `list` (reserved name, aliased), `revoke` subcommands. `_admin_headers()` reads `FWD_ADMIN_KEY`. `create` prints metadata to stderr, api_key to stdout.
- `src/fwd/cli/wallets.py` — rewritten. `import_command()` opens `SignerCM` in-process (D12). `list_command()` stub (pending `GET /v1/admin/wallets`).
- `src/fwd/cli/main.py` — registered `callers_app`.

### database
- `alembic/versions/0003_callers.py` — creates `callers` table (`name PK`, `api_key_hash UNIQUE`, `api_key_prefix`, `policy_path`, `created_at`, `revoked_at`). Partial index `idx_callers_prefix_active` on `api_key_prefix WHERE revoked_at IS NULL`. `down_revision = "0002"`.

- `pyproject.toml`: `0.3.3` → `0.4.0a1`

## Deviations from spec

1. **Test count**: spec anticipated ~89 tests total; actual is 115. Natural expansion from D9 refusal table (8 paths) and D11 bright-line (7 structural + behavioural tests).

2. **`test_caller_auth.py::test_caller_stashed_on_request_state`**: spec showed a `TestClient` route pattern using `caller_required` as a route param default. With `asyncio_mode = "auto"` (pytest-asyncio 0.24), `TestClient` inside a synchronous test causes an event loop conflict that returns 422. Fix: converted to `@pytest.mark.asyncio` calling `require_caller()` directly with a `StarletteRequest` scope dict. Behaviour tested is identical (state is set).

3. **`create_caller` test assertion**: spec assumed `result.api_key_prefix == result.api_key[9:17]`. `create_caller` returns `CallerCreateResult.api_key_prefix` from the repo's returned `Caller` (which in a mock test returns a static `"abcd1234"`). Fixed: assert that `repo.create.call_args.kwargs["api_key_prefix"]` matches the generated key's prefix — the correct invariant.

4. **`callers_endpoint` test**: uses `patch("fwd.api.callers.create_caller", ...)` for full isolation rather than going through the real use case. Consistent with how `test_sign_endpoint.py` handles the endpoint tests.

5. **`caller_auth` layer-boundary compliance**: initial draft had `from fwd.infra.caller_repo import Caller` under `TYPE_CHECKING` in `api/caller_auth.py`. Layer boundary rule forbids `api → infra`. Fix: `app/dependencies.py` re-exports `Caller as Caller` (explicit double-name suppresses F401); `caller_auth.py` imports from `fwd.app.dependencies`. Boundary test passes.
