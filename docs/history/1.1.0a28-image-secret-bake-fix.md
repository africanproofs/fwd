# v1.1.0a28 — stop baking secrets into images; untrack leaked policy backups

**Type:** security fix (custody/Core-#12 hygiene).
**Date:** 2026-05-28.
**Authoring:** Reviewer (Opus); operator-gated. Triggered by a whole-project external review + Reviewer verification.

## Why

A whole-project external review (against `e18a68e`) flagged that the Dockerfile bakes secrets into image layers. Reviewer verification confirmed it **and** uncovered a second, already-realized exposure the review missed:

1. **`Dockerfile` baked all of `config/`.** `COPY config/ /app/config/` copied the *entire* config dir; `.dockerignore` excluded `.env`/`secrets/`/`*.db` but **not** `config/master.key` or `config/policy.yaml`; and `docker-compose.yml` instructs operators to place the master at `./config/master.key`. So any **local** `docker build` on a provisioned host baked the 32-byte AES-256-GCM master + the live policy into an image layer — a direct Core #12 ("never in the repo or image") / Core #1 violation. The Dockerfile comment even claimed "policy.yaml is NOT copied" while the next line copied everything.

2. **8 `config/policy.yaml.bak-*` files were committed to the public repo** (in `872e8df "chore: maintenance"`, the a24 ship, which bulk-staged untracked files instead of explicit paths). `.gitignore` covered `config/policy.yaml` exactly but not the `.bak`/`.pre-*.bak` variants. Because they were tracked, they also baked into every CI-built image (CI builds from a clean checkout, so CI images never carried the master — gitignored — but did carry these backups).

## Exposure assessment (verified, not assumed)

- **master.key**: gitignored, **never committed** (history grep empty). Baked only into two **local** images (`:dev`, `:pre-a14-rollback`) — both verified **absent from the registry** (`docker manifest inspect`), i.e. never pushed. The master lives on the build host by design (mounted), so an unpushed same-host image layer is **zero incremental exposure**. → **No master rotation.** (The reseal path doesn't exist in the CLI anyway; rotation was not warranted.)
- **policy backups**: contain the authorization model only (caller names, wallet addresses [already public on-chain], method allowlists, value caps, rates, FSP perms) — grep for key/hash/token/argon/secret matched **nothing**. **No credentials.** → public-history **disclosure accepted, fix forward**; no `git filter-repo` rewrite (disruptive, doesn't un-publish, no creds at stake).
- wallet ciphertexts are **not** in any image (`state.db` in the leaky images is 0 bytes; the real DB is the runtime volume), so no wallet key was recoverable from the images.

## What changed

- `Dockerfile`: `COPY config/ /app/config/` → `COPY config/abis/ /app/config/abis/` (only the ABI registry must ship; policy + master + backups are bind-mounted, never baked). Corrected the false comment.
- `.dockerignore`: added `config/master.key`, `config/*.key`, `config/policy.yaml`, `config/policy.yaml.*`, `config/*.bak`, `config/*.bak-*` (defense-in-depth against any future COPY broadening).
- `.gitignore`: added `config/policy.yaml.*`, `config/*.bak`, `config/*.bak-*`, `config/*.key` so backups can never be tracked again.
- `git rm --cached` the 8 `config/policy.yaml.bak-*` / `.pre-*.bak` files (working-tree copies retained; now gitignored).

## Verification

- **Real build** (`docker build`) of the fixed image, then `/app/config` inspected: contains **only `abis/`** (registry intact — erc20 / reward_manager / participant_register / flare_systems_manager / registry.yaml present for startup); recursive scan for `master.key` / `policy.yaml*` / `*.bak*` = **none**. Throwaway verify image deleted.
- `git ls-files config/` after `git rm --cached`: no master/policy/key/bak tracked (only `abis/` + `litestream/`). The 8 backups confirmed gitignored.
- Local image cleanup: `:pre-a14-rollback`, `fwd-vault-snapshot:latest`, and the throwaway verify image deleted. `:dev` retained — it is the image of the **live, running fwd container** (Up, healthy), so it was not force-removed; it clears at the operator's next clean rebuild + container recreate (a gated redeploy). `:dev`/`:pre-a14-rollback` were never pushed, so no registry tags needed deletion.
- `docker compose config` valid; `pytest` / `ruff` / `mypy` unaffected (no `src/` change beyond the version bump).
