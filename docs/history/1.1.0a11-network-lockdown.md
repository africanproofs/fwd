# v1.1.0a11 — network lockdown (`internal: true`)

**Shipped 2026-05-27.** The network-level enforcement of the zero-egress
architecture. v1.1.0a9 removed all RPC from the fwd *code*; this ship makes it
impossible at the *network* layer for the fwd container to reach the internet at
all, regardless of code.

## What shipped

`docker-compose.yml`: the `fwd-callers` network is now `internal: true`. fwd
attaches to this network only, so it has **no gateway to the host's external
network** — no route to the internet. ~~The published port `127.0.0.1:8080` still
works (host→container DNAT is independent of the container's egress route).~~
**[CORRECTED v1.1.0a15:** this claim was WRONG and was surfaced by the a14
production cutover — `internal: true` also removes host→container port publishing,
so there is **no host port** (`docker port fwd` is empty; host curl → connection
refused). Clients reach fwd intra-network (`fwd:8080`); admin runs via
`docker exec fwd clifwd …`. See `docs/history/1.1.0a15-*.md`.**]**

**Verified empirically (the mechanism this ship rests on):** a container on an
`internal: true` bridge cannot resolve or connect to
`flare-api.flare.network:443` (`socket.gaierror` / no route), while the same image
on a normal bridge connects. So fwd — attached only to the internal network —
cannot reach the internet. This is the network-level companion to the code-level
egress grep (which already shows no `httpx`/RPC symbols in `app|api|infra`).

**Clients are dual-homed** (documented in the compose comment): a client (clif,
etc.) attaches to `fwd-callers` to reach `fwd:8080` AND to its own normal bridge
for the internet/RPC egress it needs to broadcast the signed tx fwd returns. fwd's
compose declares only the internal network; a client's own compose declares both.

## Workflow

Reviewer-authored config change (no application logic, no tests) — done directly
per the Reviewer's path-(c) authority for non-behavioural config, with the egress
mechanism verified empirically before commit.

## Verification

`internal: true` egress block proven live (above). No code/test change — the full
