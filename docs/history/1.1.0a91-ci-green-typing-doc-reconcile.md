# v1.1.0a91 — green the CI gate (mypy/ruff) + reconcile two doc-drift points

**Type:** typing fix + lint + bounded doc reconciliation. No daemon/signing-path behaviour change.
**Date:** 2026-06-08.

## Why

A multi-agent deployment-readiness assessment (fwd / fwd-client / clif) found the fwd
CI pipeline RED on `main` — the `typecheck` and `lint` stages failed, so the automated
safety net the custody doctrine (Core #14) leans on was effectively off — plus two
current-state doc-drift points (Core #18).

## What changed

1. **mypy `--strict` typecheck (3 `union-attr` errors → 0).** `WalletRepo.get_by_name`
   is typed `-> Wallet | None`, but with the default `missing_ok=False` it **raises**
   `WalletNotFoundError` and never returns `None` — so the three `EnvelopeSigner` call
   sites (`address`, `sign_transaction`, `sign_fsp_eip191`) that deref `.address` /
   `.privkey_ciphertext` were runtime-safe but mypy-unsafe. Fixed at the **root** with an
   `@overload` on `get_by_name` (`wallet_repo.py`): `missing_ok=False` (default) →
   `Wallet`, `missing_ok=True` → `Wallet | None`. Every default caller is now correctly
   non-Optional; no per-site asserts; the `missing_ok=True` callers (`api/sign.py`, the
   repo's own existence checks) stay Optional. No runtime change.
2. **ruff lint (2 `I001` → 0).** Import-sort in `test_replacement_and_nonce_sync.py` +
   `test_transactions_report.py`, via `ruff check --fix`.
3. **`architecture.md` FSP-acceptance drift (Core #18).** The `/v1/sign-fsp-message` row
   said the FSP key is "fwd-generated… not yet a registered voter" reverting `'invalid
   signing policy address'`. Reality (CLAUDE.md #17, threat-model.md): the key is an
   **imported, on-chain-registered** signing-policy voter; acceptance is *inferred* but
   not independently demonstrated because a live `signUptimeVote` reverts on the FSM
   **window guard** `'epoch not ended yet'` (which fires before the signer-registration
   check). Rewritten to present-tense reality.
4. **`envelope_signer.py` docstring (Core #18).** `vault:v1:` → `seal:v1:` (the actual
   on-disk ciphertext prefix) and "Vault-Transit" → "sealed-master". The `EnvelopeSigner`
   class name + the `vault` param/attr + the `vault_master_key` column are a **separate
   gated refactor** (API/migration) and are intentionally left unchanged here.
