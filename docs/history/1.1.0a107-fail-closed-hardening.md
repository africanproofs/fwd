# v1.1.0a107 — two fail-closed hardenings (replacement intent + nonce-wedge guard)

**Ship type:** fix (FIX-BEFORE-FLARE items from friendly-adversary round 2). Implemented by Opus 4.8
directly; operator-gated. Closes two paths that fail OPEN today.

## #6 — `/sign-replacement` no longer signs a different intent on corrupted state

`post_sign_replacement` rebuilt the calldata from the stored `request_json` and **fell back to
`data="0x"`** on a JSON parse failure (or a missing `data` key). That silently re-signs the SAME
nonce/to/value with EMPTY calldata — a DIFFERENT intent than the one reserved, violating Core invariant
#11 ("replacement re-signs the same recorded intent"). Now it **fails closed**: if the stored request
JSON is missing/malformed or carries no string calldata, it appends a forensic `denied` audit row
(`replacement_intent_unrecoverable`, commit-before-raise per Core #19) and returns **409** — the signer
is never called. A legitimate empty-calldata intent (recorded `data: "0x"`) is unaffected.

## #5 — sign path refuses to deepen a nonce wedge

If a consumer crashes after signing nonce N but before broadcasting, N is reserved but never confirmed
or released. Because of EVM nonce ordering, every higher nonce is then unminable until N resolves —
and the old behaviour kept handing out N+1, N+2, … on the next signs, **deepening the wedge** silently.
Now `sign_transaction` runs a **fail-closed nonce-wedge guard** before reserving: if `(wallet, chain)`
has a stale pending reservation (an orphan nonce older than `FWD_RESERVATION_LEASE_SEC` — the same
definition `GET /v1/admin/nonce/holes` already surfaces), it releases the rate increment, writes a
forensic `denied` row (`wallet_has_stale_nonce_hole`), and raises **`NonceWedged` → 409**. The wallet
stops at the FIRST gap (operator-visible) instead of wedging more rounds. The operator resolves it via
`/nonce/holes` (broadcast the stored `signed_raw`, replace, or release). New
`TransactionRepo.has_stale_reservation(wallet, chain, older_than)` (wallet-scoped existence check).

The fuller recovery the adversary also suggested — a **caller-safe resend endpoint** for a pending
tx's stored `signed_raw` — is a follow-up; today recovery is operator-driven via `/nonce/holes`.
