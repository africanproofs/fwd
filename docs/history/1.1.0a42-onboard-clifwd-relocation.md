# v1.1.0a42 — reward onboarding moves to `clifwd onboard rewards <class>`

**Type:** tooling ship (host wrappers + orchestrator arg surface; no daemon `src/` change).
**Date:** 2026-05-31.
**Authoring:** Reviewer (Opus); operator-gated. Verified on real (isolated) infra.

## Why

The operator questioned the a41 entry point: "shouldn't reward onboarding be a
function of clif, not fwd?" Resolution:

- **Provisioning stays in fwd.** Onboarding mints fwd's own custody state (policy,
  sealed-master wallets, caller tokens, nonces) and needs `FWD_ADMIN_KEY` + Docker
  restart authority. clif is keyless and admin-less by design (zero `/v1/admin/*`,
  no admin key) — it structurally cannot and must not host provisioning.
- **But the entry point belongs on `clifwd`, not the `fwd` lifecycle wrapper.**
  `clifwd` is fwd's admin CLI (where `wallets`/`callers`/`policy`/`nonce` already
  live), so `clifwd onboard` reads as "fwd admin onboarding", is more discoverable,
  and carries no domain confusion with `fwd start|stop|restart`.
- **Reward class is now explicit** so a future class slots in cleanly: today's set
  is `fsp` (FTSO claim + FSP signing); `validator` (staking/validator rewards) is
  reserved for the future.

## What changed

- **`install/clifwd` (host wrapper) routes `onboard`.** Adds
  `FWD_DIR="${FWD_DIR:-/opt/fwd}"`; if `$1 == onboard`, execs
  `$FWD_DIR/install/onboard "$@"` (the host orchestrator — it has the
  `docker compose restart` + host-policy-write authority the in-container `clifwd`
  lacks); everything else still `docker exec`s into the container unchanged. No
  recursion (the orchestrator calls `docker exec … clifwd` via its own function).
- **`install/fwd`** drops the `onboard)` case + usage line (the a41 entry point).
- **`install/onboard`** gains a class positional after `rewards`: `fsp` (default) |
  `validator`. `validator` prints a "future class — not yet supported" message and
  exits 2. The `--fsp-only` flag is renamed **`--sign-only`** to avoid colliding
  with the `fsp` *class* (class `fsp` = claim+sign; `--sign-only` = sign capability
  only). Header + `usage()` updated to `clifwd onboard rewards [fsp|validator]`.
- **`install/install.sh`** bakes `$FWD_DIR` into the installed `clifwd` wrapper
  (same `sed` it already does for `fwd`, so `clifwd onboard` finds
  `$FWD_DIR/install/onboard`), and the custody-gate banner leads with the
  one-command form `clifwd onboard rewards --recipient … --networks coston2`.
- **`docs/one-command-install.md`** flips every `fwd onboard rewards` →
  `clifwd onboard rewards`, moves the `onboard` line from the `fwd` block to the
  `clifwd` block in the Host command contract (noting `onboard` runs on the host),
  and documents the `rewards <class>` taxonomy (`fsp` today, `validator` future).

The a40/a41 history records keep `fwd onboard` verbatim — they truthfully describe
what those ships shipped (append-only, Core #13/#18); only the current-state docs
move to `clifwd onboard`.
