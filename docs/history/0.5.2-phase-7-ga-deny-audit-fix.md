## The bug (D16 + Core invariant #5)

The v0.5.1 deny-side live run proved default-deny **enforcement** (V1
startup fail-fast; V2–V7 → HTTP 403 with the exact D14 step; zero
broadcast). But the full audit chain contained **zero
`decision=denied`/`error` sign-and-send rows**, and a live re-test
showed a `403 step=6` with the audit `seq` unchanged (`14→14`):
**denied and errored sign-and-send requests persisted no audit row.**
This violates D16 and Core invariant #5 ("every request, decision …
is recorded") and contradicts the v0.5.0a6 ship claim
"deny→audit(`denied`)+raise".

**Root cause (confirmed in source):** `app/sign_and_send.py`'s three
exception arms do `await _audit(...); raise` — `_audit()` appends the
forensic row to the **shared `RequestScope` session** but does not
commit. The exception (`PolicyDenied` / `RpcUnreachable` /
`VaultUnavailableError`) propagates out through `RequestScopeCM` →
`fwd.infra.db.session_scope`, whose `except Exception: await
session.rollback()` arm **rolls the just-appended row back**. This is
the **exact defect class as the v0.5.0a6 `main.py` SystemExit bug**
(audit row written then discarded on the exception path because the
session rolls back instead of committing) — caught then for
`policy-load`, recurring here for `sign-and-send`. The a6 unit suite
(`test_sign_and_send_policy.py`) asserted `audit_repo.append(...)` was
*called* on a **mocked** session, never exercising the real
`session_scope` rollback — so the bug was unit-invisible and only the
live drill surfaced it. **Core invariant #14 earned its keep again**
(cf. the v0.4.5 concurrency bug).

Default-deny **enforcement** was never compromised (nothing
unauthorized broadcast); the lost surface was the **forensic
accountability for refusals and failures** — a core part of fwd's
value proposition.

## The fix (Reviewer-owned, surgical, a6 precedent)

The correct, safe approach is the v0.5.0a6 `main.py` pattern — commit
the forensic row before the exception propagates past `session_scope`
— applied to the **single shared session** (NOT a second session: a
second `session_scope` while the request session is open would
re-introduce the v0.4.5 two-session `BEGIN IMMEDIATE` writer-lock
deadlock for the step-8/9 deny case, where the gate already holds the
writer lock).

- **`infra/audit_repo.py`** — new `AuditRepo.commit()` (commits the
  underlying session; documents the durability rationale). Additive;
  no existing method changed.
- **`app/sign_and_send.py`** — the `except PolicyDenied`, the
  pre-broadcast-failure `except`, and the broadcast-failure `except`
  arms now `await audit_repo.commit()` after `_audit(...)` and before
  re-raising. Because the explicit `nonce_repo.release_if_unused` +
  `release_rate_after_failure` run BEFORE the commit on the
  pre-broadcast path, the committed operational state is correct
  (`reserve(+1)` then `release(-1)` net to zero). This also corrects
  two latent accounting bugs the prior rollback caused: a step-8/9
  **deny** now keeps its D14 rate increment (deny does not call
  `release_rate_after_failure` — the attempt is counted, per D14),
  and a **broadcast failure** now keeps the reserved nonce (per the
  broadcast-failure doctrine "do NOT release — the tx may be in
  mempools; the receipt watcher decides"). The trailing
  `session_scope` rollback becomes a harmless no-op on the
  already-committed, empty transaction.
- **`tests/unit/test_db.py`** — a **self-validating** regression test
  through the *real* `fwd.infra.db.session_scope`: a `denied` row
  appended + `AuditRepo.commit()` + raise → must persist in a fresh
  session; an `error` row appended WITHOUT commit + raise → must NOT
  persist (proves the harness genuinely exercises the rollback, so it
  cannot silently regress — the v0.4.5 `test_db.py` discipline).
- **`tests/unit/test_sign_and_send.py`** — one-line necessary mock
  adaptation: `_audit_repo_mock()` gained an awaitable `commit`
  (the seven a6 error-path tests now drive the new commit call).
