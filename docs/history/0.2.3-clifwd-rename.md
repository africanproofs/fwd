# v0.2.3 — CLI rename: `fwd-cli` → `clifwd`

> Doc-only ship landed 2026-05-01. Mechanical rename of the operator-facing CLI binary from `fwd-cli` to `clifwd`. No behavioural change.

## Why

Three reasons, in order:

1. **Pronounceable.** `clifwd` reads aloud as "Clifford" — memorable, gives the tool a personality, easier to refer to in operator transcripts and chat conversations than the hyphenated `fwd-cli`.
2. **Single token.** No hyphen → easier to type, easier to alias, easier to tab-complete, easier to grep for in shell history without `\`-escaping.
3. **Deliberate morphology.** `clifwd` = `cl` + `i` + `fwd` (the `i` is a pronunciation aid) — a compact, intentional construction, not a placeholder hyphenation.

Four reasons, really — `fwd-cli` was placeholder-shaped from the moment it was first written down. `clifwd` is what it should have been.

29 occurrences in 5 files; `clifwd` count after rename = 29.

## What did NOT change

- The Python package name remains `fwd`. Only the operator-facing CLI binary's name changes.
- The Docker Compose service name remains `fwd`. The container that hosts the FastAPI app is still `fwd`.
- The on-disk paths, env var names, file names, audit log action names — all unchanged.
- No code exists yet (Phase 2 scaffolds the project), so no `pyproject.toml` entry point or import path needs updating in this ship. Phase 2's `pyproject.toml` will land with `[tool.poetry.scripts] clifwd = "fwd.cli:app"` from day one.

## Phase 2 implication

When Phase 2's project scaffold lands, the CLI entry point in `pyproject.toml` is `clifwd`, not `fwd-cli`. The Python module that hosts the CLI logic remains `src/fwd/cli/...`. The bash invocation operators see is `clifwd <subcommand>`.
