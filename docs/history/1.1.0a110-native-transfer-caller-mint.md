# v1.1.0a110 — native-transfer callers can be minted (a109 completion)

## What shipped

The a109 native-transfer capability could define `native_transfers` rules but a
caller could NOT be **minted** against them: `POST /v1/admin/callers` validates the
requested `policy_path` via `policy_loader.policy_path_exists(policy, path,
"caller")`, which checked only `permissions` and `fsp_permissions` — so
`fwdctl callers create --policy perm/funding-<net>` failed
`400 unknown_policy_path`. Surfaced live minting clif's `clif/<net>/funding` caller
against the deployed a109 policy.

Fix (one line of logic): `policy_path_exists(kind="caller")` now also accepts
`policy.native_transfers` — mirroring `check_consistency` Check 1c and the
`policy_engine` branch (the three permission-block kinds a caller binding may
resolve to). The admin error message is updated to name all three.

## Changes

- `src/fwd/infra/policy_loader.py` — `policy_path_exists(caller)` adds
  `or policy_path in policy.native_transfers`.
- `src/fwd/api/callers.py` — the `unknown_policy_path` message now reads
  "(permissions, fsp_permissions, or native_transfers)".
- `tests/unit/test_fsp_policy_loader.py` — `policy_path_exists` accepts a
  native_transfers caller path, rejects an unknown one.

Full suite: **1014 passed, 1 skipped**; ship files ruff-clean.
