# v1.1.0a8 — admin nonce-init

**Shipped 2026-05-27.** First ship of the **zero-egress initiative**
(`docs/zero-egress-architecture-plan.md`, operator-directed 2026-05-27): fwd
becomes a sign-only signer + nonce-allocation authority; clients broadcast. This
ship is the additive prerequisite — nothing about RPC, signing, or broadcasting
changes yet.

## What shipped

An admin-only, RPC-free way to seed a `(wallet, chain)` nonce:

- `POST /v1/admin/nonce-init` (`src/fwd/api/nonce.py`) — admin-authenticated;
  body `{wallet, chain, starting_nonce}`. Reserves nothing — it exposes the
  existing idempotent `NonceRepo.init_for_wallet`. **201** on first init; **409**
  `nonce_already_initialized` if the row exists (stored `next_nonce` unchanged);
  **404** `wallet_not_found` on a wallet FK violation. Every outcome writes a D16
  audit row (`action="nonce-init"`); the refusal rows are committed before the
  `HTTPException` propagates so they survive the `session_scope` rollback (Core
  invariant #5 / #19). The approved path commits seed + audit atomically under one
  `BEGIN IMMEDIATE` via `AdminScopeCM.__aexit__`.
- `clifwd nonce init --wallet --chain --starting-nonce` (`src/fwd/cli/nonce.py`) —
  HTTP client mirroring `clifwd wallets create` (FWD_URL / FWD_ADMIN_KEY Bearer).
- `nonce_repo` added to `AdminScope` + `AdminScopeCM` (`app/dependencies.py`) so
  the seed and its audit row share one session.

**Why:** once the zero-egress excision (1b) removes the lazy on-chain nonce seed
inside `sign_and_send`, a fresh `(wallet, chain)` would have no way to obtain its
`next_nonce`. This command is the RPC-free replacement, landed *before* the
removal needs it (the plan's "not later than the removal" satisfied by landing
earlier).

## Deviations (all legitimate, all surfaced by the implementer)

1. **Layer boundary.** `api/` may not import `infra/` (enforced by
   `test_layer_boundaries`). The endpoint's needs (`_canonical_json`,
   `NonceWalletNotFoundError`) are re-exported through `app/dependencies.py`,
   matching the existing `Caller` / `policy_path_exists` re-export pattern.
2. **`_VALID_ACTIONS`.** `"nonce-init"` added to the `audit_repo` action guard —
   `audit_repo.append` asserts the action is known.
3. **`AdminScope` required field.** Three existing tests construct `AdminScope`
   directly; each gained `nonce_repo=MagicMock()`.
