# v1.1.0a52 — install decoupling + `fwd onboard` surface + `install/clif` wrapper + one-shot clif service

**Type:** feature ship (host shell + compose; no `src/` change). Reviewer (Opus) prescribed a self-contained canonical prompt; Sonnet implemented in an isolated subagent; Reviewer binding-passed (static: `sh -n` + `docker compose config` + file-by-file read) and corrected one premature flag; operator-gated. The live `up`/onboard drill is the operator's, on the production host.
**Date:** 2026-06-02.

## Why

This is **Ship B1** (plumbing) of the two-ship onboarding-cohesion redesign (Ship B). It decouples install from onboarding and adds the host command surface the wizard rewrite (Ship B2) builds on — without touching `install/onboard`'s internals, so it is non-breaking (the existing wizard keeps working via the compat alias).

## What changed

- **Install is inert by default.** `install/install.sh` no longer auto-runs the onboarding wizard. The new opt-in `--onboard-rewards` (requires a TTY + a started stack) chains onboarding onto the install; otherwise the installer ends inert and prints the terse next command. `--inert` is now a **deprecated accepted no-op** (inert is the default). The verbose manual-runbook heredoc in the final output is replaced by a one-line `sudo fwd onboard rewards …` pointer.
- **Host command surface.** `install/fwd` gains an `onboard` dispatch (`fwd onboard rewards …` → `$FWD_DIR/install/onboard`) and updated help; `fwd onboard` is the **canonical** entry point. `install/clifwd` keeps routing `onboard` to the same host orchestrator but its header is renarrated — onboarding is host-level **stack** onboarding (fwd custody + clif chain reads + clif env config), and `clifwd onboard` is now framed as a **compatibility alias**, not "clifwd owns rewards".
- **`install/clif` (new host wrapper).** Runs the keyless clif client as a one-shot in fwd's merged compose project (`--profile cli run --rm clif`), dual-homed (`fwd-callers` to reach `fwd:8080`, `egress` for its own RPC/broadcast). A **leading** `--network <N>` selects clif's per-network `.env.<N>` and is stripped; a command-level `--network` (e.g. `clif chain nonce --network …`) passes through to clif's own CLI. This is the egress-capable path the B2 wizard uses to read chain nonce truth (fwd is zero-egress).
- **One-shot `clif` service** added to `docker-compose.clif.yml` under `profiles: ["cli"]` (so `up`/`fwd start` never start it), `entrypoint: ["clif"]`, dual-homed. The existing `clif-auto`/`clif-fsp-auto` daemons are untouched.
- **`CLIF_SRC`/`CLIF_ENV` wrinkle-fix.** clif's source + per-network `.env` live at the install ROOT (`$FWD_DIR/clif`), a sibling of the compose bundle (`$SRC`) the wrappers run compose from. install.sh now bakes the absolute `CLIF_SRC` default into the `fwd`/`clifwd`/`clif` wrappers (mirroring the existing `FWD_DIR` baking), and `install/fwd` exports `CLIF_SRC`/`CLIF_ENV` for compose — so the overlay's `${CLIF_SRC:-./clif}`/`${CLIF_ENV:-./clif/.env}` resolve correctly post-install (previously they would have resolved to the wrong `$SRC/clif`).

**Reviewer correction (recorded for provenance, since SendMessage to continue the implementer session was unavailable):** the implementer (faithfully to the spec) wired a `--identity` flag through `install.sh` → `install/onboard`, but `install/onboard` is unchanged in this ship and rejects unknown args — so `fwd onboard rewards --identity 0x..` would `die "unknown arg: --identity"`. `--identity` is consumed by the onboard env-writer, which is Ship B2; it has no function in B1. The Reviewer removed all `--identity` wiring (var default, flag arm, forwarding, two next-command messages, the header example/flags line, and the `install/fwd` help line); `grep --identity install/` is now empty and `sh -n` re-passes. B2 introduces `--identity` in `install.sh` + `install/onboard` atomically.
