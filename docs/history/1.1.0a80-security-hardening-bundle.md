# v1.1.0a80 — security-hardening bundle (nonce-init guard, read-only auth, UPTIME replay guard, windowed audit)

**Type:** daemon security hardening (multiple defenses). No retired behaviour.
**Date:** 2026-06-06.

## Why

A sweep for latent custody/replay hazards surfaced four: a `force` nonce-init could silently clobber a nonce with in-flight txs; the high-frequency caller-auth SELECT contended on the SQLite writer lock by taking `BEGIN IMMEDIATE` it never needed; UPTIME FSP votes carry no epoch-bound chain context and are therefore **replayable across chains** when `chain_ids` is unconstrained; and `audit verify` over a window could not detect tampering *upstream* of the window start.

## What changed

- **`api/nonce.py` + `app/dependencies.py`** — `nonce-init` with `force=true` now **refuses** (409 `in_flight_nonces` + forensic audit row, committed before raise per Core #5/#19) when pending/submitted nonces exist for the (wallet, chain), unless the caller passes the new `force_with_in_flight=true` acknowledgement. `tx_repo` (with `count_in_flight`) is added to `AdminScope` to power the guard.
- **`infra/db.py` + `app/dependencies.py`** — `session_scope(read_only=True)` skips `BEGIN IMMEDIATE` (via a `contextvars` flag) and skips the final commit, for pure-SELECT callers. `CallerRepoCM` (the argon2 caller-auth path) adopts it — no more writer-lock contention on every authenticated request.
- **`app/fsp_policy.py` + `app/sign_fsp_message.py`** — **UPTIME cross-chain replay guard:** an UPTIME request is denied (gate step 4) unless its permission block carries an explicit `chain_ids` allowlist; and the UPTIME messageHash is reconstructed chain-less (`chain_id=None` into `build_fsp_message`) because the preimage is epoch-only and identical across chains by protocol design — the policy allowlist, not the preimage, is the replay guard.
- **`app/policy_init.py`** — generated claim/uptime/rewards methods set `allow_unconstrained_args: False`. *(This proved too tight for the non-scalar tuple args and is corrected in v1.1.0a81 — see that record; the cross-chain guard is moved to a generated `chain_ids` there.)*
- **`infra/audit_repo.py`** — `VerifyResult` gains `upstream_break` / `upstream_break_seq`: a windowed walk now detects when the anchor row at `(from_seq − 1)` exists but its stored `row_hash` ≠ the first walked row's `prev_hash` — i.e. tampering upstream of the requested range.
- New `tests/unit/test_admin_forensic_durability.py` (205 lines) plus broad test updates across the touched modules.

## Verification

Unit suite green including the new forensic-durability tests. The in-flight guard, read-only session, UPTIME chain_ids requirement, and upstream-break detection are each exercised by their respective unit tests.
