# v1.1.0a64 — installer: also hand `.env` + clif dir to uid 1000 on a root install (a63 was incomplete)

**Type:** installer fix (`install/install.sh`). No daemon/custody/signing semantics change. Operator-surfaced live: after a63 let a `sudo` install finish, `fwd onboard` (run **without** sudo) failed at Step 3 with `open /opt/fwd/src/.env: permission denied` → `docker compose … restart fwd` → `no such service: fwd`.
**Date:** 2026-06-03.

## Why (operator hit it live, immediately after a63)

a63 fixed `config/` ownership so the uid-1000 container could write/read `master.key`. But the **host wrappers** (`fwd`/`clifwd`/`clif`) run `docker compose` as the **invoking user** (uid 1000 on this single-user host, no sudo), and `docker compose` reads `$SRC/.env` (which holds `FWD_ADMIN_KEY`). A `sudo` install writes `.env` as **root, mode 0600**, so a no-sudo wrapper can't read it → compose loads no config → `no such service: fwd`. The same applies to the clif dir: onboarding's `env_write` (run as the user) writes `clif/.env.<net>` into the root-owned `/opt/fwd/clif`. a63 covered only `config/`; `.env` and `clif/` were still root-owned.

## What changed

Extend the a63 root-install `chown` to the rest of the user-operated runtime tree:

```sh
if [ "$(id -u)" = 0 ]; then
  chown -R 1000:1000 "$SRC/config" "$SRC/.env" 2>/dev/null || true
  [ -d "$FWD_DIR/clif" ] && chown -R 1000:1000 "$FWD_DIR/clif" 2>/dev/null || true
fi
```

Now a `sudo` install hands `config/` (master.key + policy — the container reads them), `.env` (the wrappers' `docker compose` reads it), and the clif dir (onboarding writes `.env.<net>` there) all to uid 1000, so the stack is fully operable **without re-sudoing each wrapper** — matching the container's uid 1000 and the operator on a single-user host. No-op for a non-root (user) install. A multi-user host whose operator isn't uid 1000 should operate a root install via `sudo fwd …` or install into a user-owned dir (noted inline + in `docs/one-command-install.md`).

## Verification (Reviewer)

`sh -n` + `dash -n` clean; the guarded block is a no-op for non-root (verified in a63). The root path's live validation is the operator's clean install + onboarding (Core invariant #14). Class note (Core invariant #19): the defect class is "a root install leaves runtime files unreadable/unwritable by the uid-1000 user that operates the stack"; a63 patched one instance (`config/`), this closes the rest (`.env`, `clif/`) — the doctrine fix is "hand the whole user-operated runtime tree to uid 1000 on a root install," not another point-patch. `poetry run pytest` (version-consistency + suite).
