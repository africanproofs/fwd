# v0.3.0 — Phase 3c, Sign and send (Phase 3 GA)

> Phase 3c sub-ship landed 2026-05-07.
> Closes Phase 3 (Vault deployment + signing core). The first ship that signs a real Coston2 transaction.

## What landed

- **`src/fwd/infra/rpc.py`** (new) — Async JSON-RPC client (`RpcClient`, `RpcManager`); `ALLOWED_CHAINS` frozenset (Coston2 only in v0.3.0); `RpcError` vs `RpcUnavailable` error split for transport-vs-shape distinction. `RpcClient` enforces `ALLOWED_CHAINS` at construction time (defense in depth). `RpcManager` owns one `httpx.AsyncClient` pool and lazily caches `RpcClient` instances per chain_id.
- **`src/fwd/infra/envelope_signer.py`** (modified) — `sign_transaction` implemented: Vault decrypt → bytearray → `Account.from_key().sign_transaction(tx_dict)` → zeroize-in-finally. Round-trip verified: signed tx recovers to wallet address. Deviation from spec: `SignedTransaction` moved from `TYPE_CHECKING`-only import to a regular runtime import (required because `sign_transaction` constructs a `SignedTransaction` instance at runtime, not just type-annotates it). Also added `assert wallet is not None` for mypy type narrowing (matches existing `address()` pattern in the same file).
- **`src/fwd/app/sign_and_send.py`** (new) — Use case orchestration. Verifies chain_id, fetches nonce/fee/gas, builds EIP-1559 tx_dict, delegates to signer, broadcasts. App-layer exceptions translate infra failures (`RpcUnavailable`+`RpcError` → `RpcUnreachable`; `VaultError` → `VaultUnavailableError`; `WalletNotFoundError` → `WalletNotFound`). `ALLOWED_CHAINS` re-exported via `import as` idiom (required by mypy strict for explicit re-export; preserves layer boundary: `api/` imports `ALLOWED_CHAINS` from `app/`, not `infra/`).
- **`src/fwd/app/dependencies.py`** (modified) — Added `RpcManagerCM` and `get_rpc_manager()` symmetric to existing `SignerCM`/`get_signer()`. Also added `RpcManager` import from `fwd.infra.rpc`.
- **`src/fwd/api/sign.py`** (new) — `POST /v1/sign-and-send`, admin-gated; 200/400/401/404/502/503 envelope. Pydantic field validators reject malformed `to`/`data`/`value_wei` at the API boundary. Pre-flight `ALLOWED_CHAINS` check before constructing `SignAndSendRequest` (defense in depth; catches the case where `for_chain()` would raise `RpcError` before `sign_and_send` fires).
- **`src/fwd/main.py`** (modified) — `sign_router` imported and mounted.
- **`src/fwd/settings.py`** (modified) — `rpc_url_flare`, `rpc_url_songbird`, `rpc_url_coston2` fields with public Flare endpoint defaults.
- **`src/fwd/version.py`** (modified) — `0.3.0a6` → `0.3.0`.
- **`pyproject.toml`** (modified) — `version = "0.3.0a6"` → `version = "0.3.0"`.

## What this ship deliberately does NOT include

- **Caller authentication** — admin-key reuse from Phase 3b. Phase 4 swaps `admin_required` for `caller_required` (URL stable).
- **Nonce manager** — `eth_getTransactionCount(addr, "pending")` per request. Race condition between concurrent same-wallet requests is documented and accepted; Phase 5 ships `BEGIN IMMEDIATE` serialization.
- **Audit log row** — `structlog` event only (`sign_and_send.ok`). Phase 7 ships hash-chained audit + structlog scrubber.
- **Receipt watcher / replacement-on-stuck** — Phase 5.
- **Idempotency-Key support** — Phase 5 with the transactions table.
- **Songbird / Flare mainnet** — allowlist refuses chain != 114. Phase 7 lifts with policy.yaml.

## Deviations from canonical prompt

1. **`SignedTransaction` moved from `TYPE_CHECKING` to runtime import** in `envelope_signer.py`. The spec states "no new imports needed for this method" (since `SignedTransaction` was already in the TYPE_CHECKING block), but `sign_transaction` constructs a `SignedTransaction(...)` instance at runtime. A `TYPE_CHECKING`-only import is not available at runtime, causing a `NameError`. Fix: promote to a regular import. No layer boundary violation (`infra/` importing from `domain/` is allowed).

2. **`assert wallet is not None` added** in `sign_transaction`. Required for mypy `--strict` type narrowing (`get_by_name` return type is `Wallet | None`; at runtime, `missing_ok=False` raises instead of returning `None`, but mypy can't infer this). Matches the existing `address()` method pattern in the same file.

3. **`ALLOWED_CHAINS` re-exported via `import as` idiom** (`from fwd.infra.rpc import ALLOWED_CHAINS as ALLOWED_CHAINS`) in `sign_and_send.py`. The spec says "(or implicit re-export) is sufficient", but mypy `--strict` requires explicit re-exports from the importing module. The `import as` pattern is the mypy-standard way to mark an import as an intentional re-export.

4. **`RpcUnavailable` gets `# noqa: N818`** in `rpc.py`. The spec does not include this suppression, but ruff's N818 rule flags exception class names that don't end with `Error`. The name `RpcUnavailable` is intentional (transport failure vs shape error distinction); adding `# noqa` is the correct minimal fix.

5. **`# noqa: TC003` on `Path` import** in `test_sign_and_send_integration.py`. Ruff TC003 wants `Path` moved to `TYPE_CHECKING`; pytest fixture injection works with deferred annotations, so this is technically valid, but following the existing `tests/conftest.py` pattern of `# noqa: TC003` is cleaner.

6. **`# noqa: SIM300` on `assert ALLOWED_CHAINS == frozenset({114})`** in `test_rpc_client.py`. Ruff SIM300 flags this comparison; the assertion matches the spec literally and `# noqa` preserves intent.
