# v1.1.0a33 — `install/install.sh` (the `curl|sh` bootstrap)

**Type:** deployment-scaffolding ship (no daemon code change). Provider-distribution Phase 1, ship 1.
**Date:** 2026-05-31.
**Authoring:** Reviewer (Opus) implemented directly under operator direction; operator-gated.

## Why

Phase 1 of the provider-distribution plan: the k3s-style one-command install.
The design (a32 `one-command-install.md`) is now backed by an actual POSIX
bootstrap that gets a fresh host from zero to a **healthy, inert, default-deny**
fwd stack — then stops at the custody gate.

## What changed

- **`install/install.sh`** (new, executable) — POSIX `sh`, build-from-source,
  single-host. Steps: preflight (docker + compose v2 + git) → clone pinned
  source (`FWD_REF`, optional `FWD_SHA` integrity pin) → `docker compose build`
  → generate `FWD_ADMIN_KEY` + an **inert `version: 1` default-deny policy** (if
  absent) → generate the sealed master **locally** (a one-shot `docker run …
  clifwd master generate`, never transmitted) → install the host `fwd`/`clifwd`
  wrappers → `up -d` (inert) + `clifwd health` → print the custody-gate
  next-steps. Re-runnable (preserves an existing master.key/.env/policy.yaml).
  - Flags: `--with-clif` (clones + wires clif; **needs clif public**),
    `--no-start` (stage without `up` — also the safe path on a host that already
    runs an `fwd` container), `--no-build`, `--production`/`--dev`, `--dir`,
    `--ref`, `--help`. k3s-style env hooks: `FWD_DIR`, `FWD_BIN_DIR`,
    `FWD_REPO`/`FWD_REF`/`FWD_SHA`, `FWD_IMAGE_TAG`, `CLIF_REPO`/`CLIF_REF`.
  - Integrity model (this iteration): git clone at a pinned ref + optional
    `FWD_SHA` HEAD pin. (A fetched release-manifest with per-artifact checksums +
    `get.proofs.africa` hosting is the next Phase-1 sub-step.)

## Verification (safe on this shared host — the live `fwd` container was untouched)
- `sh -n` clean; `--help` renders.
- A real `--no-start` staged run (`FWD_DIR=/tmp/...`, `FWD_REPO=` the local repo,
  `FWD_IMAGE_TAG=installtest`): cloned → built the image → generated the sealed
  master (**mode 0600, 32 bytes**) → wrote `.env` (mode 0600, non-empty
  `FWD_ADMIN_KEY`) + the inert `version: 1` policy → installed both host wrappers
  (with `FWD_DIR` baked). The inert policy **schema-validates `VALID` (callers=0)**
  in the built image — i.e. the installed daemon would boot inert and sign
  nothing. Idempotent re-run preserved the master/.env. Test artifacts + the
  `:installtest` image removed; the production `fwd`/`fwd-litestream` stack stayed
  Up + healthy throughout.
- NOT exercised here (correctly deferred): the actual `up`+health (needs a fresh
  host — `container_name: fwd` collides with the running stack on this machine)
  and `--with-clif` (blocked on clif going public).
