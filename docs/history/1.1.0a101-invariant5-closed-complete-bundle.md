## Headline

**Invariant #5 — *fwd never reads OR writes a consumer's env* — is closed.** `onboard` no longer writes clif's `.env.<net>` (the `env_write` retired) nor reads it (the token-recovery + pre-flight `.env` reads retired). The config `env_write` used to write is **relocated into a complete v2 bundle** (`consumer-contract-v1` §4 v2): a `config` section + the per-capability tokens. fwd composes it from onboard flags + literal defaults (no `.env` read); clif's v2 `import-credentials` writes clif's own `.env`. The breach `fwd` existed to close is closed — and working (canary).

## What changed

**The `.env` closure (`install/onboard`).** Deleted `env_write()` + its loop call; removed the `caller_ensure` `.env`-recovery read and the FSP pre-flight `SIGNING_POLICY_ADDRESS` read; deleted the now-dead `getval` helper. `caller_ensure` now **rotates** on an existing caller (revoke + `--replace`) — fwd retains no token plaintext (Core #1/#16) and may not read clif's `.env` to recover one, so a re-onboard re-mints. Banners reworded. Net: `onboard` touches NO `${CLIF_ENV_DIR}/.env.<net>` path — only the `.fwd-bundle.<net>.json` it emits.

**The complete v2 bundle.** `app/bundle_emit.py`: `BUNDLE_VERSION → 2`; `compose_bundle` gains a `config: dict[str,str]` param (emitted in the §4 order; defaults `{}` for a tokens-only rotation bundle); the **Core #7 guard extends to config** (refuse a `*PRIVATE_KEY*` config key/value; reject control-char values). `cli/bundle.py`: `bundle compose` parses `CONFIG<TAB>KEY<TAB>VALUE` stdin lines alongside the cap-tuples. `install/onboard`: composes the v2 `config` from **flags + the same literal defaults** `env_write` used (`FWD_ENDPOINT`, `WRAP_REWARDS`, `FSP_AUTO_ENABLED`, `UPTIME_AUTO_ENABLED`, `EPOCH_*`, `CLIF_STATE_DIR` always; `IDENTITY_ADDRESS`/`CLAIM_RECIPIENT_ADDRESS` under `HAS_CLAIM`) — no `.env` read. `write_bundle` + `BundleCapability` unchanged.

## The RPC-override delta (honest, Core #18)

`env_write` conveyed per-network RPC overrides by **reading clif's existing `.env`** (preserve-existing). Reading `.env` is now forbidden and onboard has no flag for them, so fwd **cannot** emit RPC overrides in the bundle. They are **clif-side** now: the operator sets them in clif's `.env`, and clif's idempotent **upsert** import preserves any line the bundle does not set (clif's allowlist includes the RPC keys, so a future flag-sourced RPC could be added without a `.env` read).

## fwd ⊥ clif — the daemon never imports a consumer, even in tests

The membrane runs one way: consumers depend on fwd's contract, never the reverse (operator directive 2026-06-10). The bundle unit test therefore pins the `consumer-contract-v1` §4 v2 shape directly (a self-contained canonical fixture + a structural conformance check) and does **not** import clif's `validate_bundle` or reach the sibling repo. Interop with clif's real v2 importer is proven by the **live canary**, never a unit-test code dependency.
