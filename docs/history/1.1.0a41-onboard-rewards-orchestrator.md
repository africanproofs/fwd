# v1.1.0a41 — `fwd onboard rewards`: the one-command reward custody setup

**Type:** tooling ship (host orchestrator; no daemon `src/` change).
**Date:** 2026-05-31.
**Authoring:** Reviewer (Opus); operator-gated. Verified on real (isolated) infra.

## Why

a40 shipped the visible default reward policy + a names-pre-filled manual runbook.
The residual load was still **sequencing ~7 admin commands across a daemon restart
with names pre-matched to the generator**. This ship collapses that into one
idempotent host command — the low-cognitive-load path the operator asked for —
while keeping the two un-automatable custody GATES (FSP signing-key import,
on-chain authorization) explicit and operator-owned.

## What changed

- **`install/onboard`** (new, POSIX, +x) — host orchestrator surfaced as
  `fwd onboard rewards`. Honors `$FWD_DIR` + `$FWD_CONTAINER`; admin commands run
  in-container (`docker exec`), where `FWD_ADMIN_KEY` lives; holds no keys. Flow:
  preflight health → `clifwd policy init` (default `claim,fsp`) captured to a host
  temp → write the policy **in place** (only if changed; back up the prior one) →
  `policy validate --schema-only` (abort+restore before any restart on failure) →
  restart to load (skipped if byte-identical) + health-poll → create the
  fwd-generated wallets (`claimer-<net>`, shared `fsp-sender`) → **GATE 1**: print
  the exact FSP-key `wallets import` command and pause (never read/transit the
  key; `--skip-fsp-import` defers) → mint the 3 caller tokens (each printed once)
  → seed the sender nonces → **GATE 2**: print the on-chain
  `setClaimExecutors`/`setAllowedClaimRecipients`/FSP-registration checklist with
  the concrete recipient. Flags: `--recipient`, `--networks` (comma list, default
  `coston2`), `--claim-only`/`--fsp-only`, `--skip-fsp-import`.
- **`install/fwd`** — new `onboard)` case → `exec "$FWD_DIR/install/onboard" "$@"`
  + usage line.
- **`docs/one-command-install.md`** — leads onboarding with **the one command**
  (`sudo fwd onboard rewards --recipient … --networks …`); the manual runbook is
  reframed as "what it does step by step / the fallback"; `onboard` added to the
  Host command contract.

## Idempotency contract (verified)

Re-running converges, never duplicates: byte-identical policy → no restart;
`wallets create` exit-3 (409) → skip; `callers create` exit-3 → warn, **never
re-emit a token** (tokens are shown once and unrecoverable); `nonce init`
already-initialized → skip.

## Key correctness point

A single-file Docker bind mount pins the inode, so the policy is overwritten **in
place** (`cat tmp > policy`, same inode) — NOT `mv` (a new inode the container
wouldn't see until restart). This is what lets `policy validate --schema-only`
read the new policy off the live mount **before** the restart, so a bad policy
aborts cleanly (restore from the backup) without ever bouncing the daemon.

## Deviation from plan

The plan listed an `install.sh` step-6 install of `onboard` to `PATH`. Omitted:
`fwd onboard` execs the in-source-tree `install/onboard` by absolute path
(`$FWD_DIR/install/onboard`, shipped +x), and `onboard` defines its own in-process
`clifwd()` (`docker exec`), so it needs nothing on `PATH`. A separate `PATH` copy
would only be drift. On manually-deployed hosts (no `fwd` wrapper) it runs
directly: `FWD_DIR=<repo> FWD_CONTAINER=fwd install/onboard rewards …`.

## Verification (Core #14 — isolated real infra)

Brought up an isolated instance from the existing `fwd:dev` image
(`FWD_CONTAINER=fwd-onbtest`, `COMPOSE_PROJECT_NAME=fwdonbtest`, own volume/network)
alongside the untouched production `fwd`, and ran `onboard`:
- **First run:** policy generated → backed up the inert `version:1` → written in
  place → `schema OK — 3 callers / 2 permissions / 3 wallet_constraints / 1
  fsp_permissions`, `VALID (schema-only)` → restart healthy → wallets
  `claimer-coston2` + `fsp-sender` created → 3 caller tokens emitted once → nonces
  seeded (`claimer-coston2`, `fsp-sender` @ chain 114) → GATE 2 printed.
- **`clifwd policy validate` (full):** `VALID (schema + consistency)` — every
  wallet/caller binds to the loaded policy.
- **Re-run:** byte-identical → no restart; wallets/callers/nonces all skipped; no
  token re-emit.
- **GATE 1 path:** prints the exact `wallets import` command; `s` skips with the
  claim-can-go-live warning.
- Torn down (`down -v`); production `fwd` healthy throughout (untouched).

The real-Coston2 reward **drill** (a clif client signing a live claim/FSP through
an onboarded instance) is the standing operator gate — it needs an imported
registered signing key + funded wallets (Core #15 custody boundary), so it is not
run here.
