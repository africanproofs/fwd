# v1.1.0a97 — `fwdctl` invocation alias + `--json` read forms

**Type:** feature (additive; behaviour-preserving). No daemon/signing-path change — `src/` change is CLI-output only (`--json` on read commands).
**Date:** 2026-06-09.
**Authorization:** operator-authorized 2026-06-09 — the "opportunistic" Phase-1 band of the cross-project flaresystems `docs/adr/0002-defer-fwd-bundle-grant-framework.md` (`docs/decisions.md` D24).

## Headline

Two small, additive conveniences that ADR-0002 does NOT make us wait for: a working `fwdctl` invocation name for the admin CLI, and a machine-scrapable `--json` form on the existing read-only list/show commands (mirrors clif's `--json` surface). The full `clifwd`→`fwdctl` rename (~250 occurrences, incl. the Typer program name) and the bundle/grant coordination framework remain **deferred** (ADR-0002).

## What changed

**Part A — `fwdctl` invocation alias (additive; `clifwd` byte-unchanged).**
- `pyproject.toml` `[tool.poetry.scripts]`: added `fwdctl = "fwd.cli.main:app"` (kept `clifwd = "fwd.cli.main:app"`) — enables `poetry run fwdctl`.
- `Dockerfile`: `ln -s clifwd /usr/local/bin/fwdctl` after the `clifwd` shim — the in-container alias resolves via the symlink **independently of the console-script** (the shim exists precisely because `poetry install --no-root` never creates console-scripts in the image).
- `install/fwdctl` (new host wrapper, mode 0755): a byte-faithful copy of `install/clifwd` — only the header lead and the final `exec docker exec "${FWD_CONTAINER:-fwd}" fwdctl "$@"` delegation token differ; the `FWD_DIR`/`FWD_CONTAINER`/`COMPOSE_PROJECT_NAME`/`CLIF_ENV_DIR` exports and the `onboard` routing block are verbatim.
- `install/install.sh`: installs `install/fwdctl` alongside `clifwd` and includes `fwdctl` in the three `FWD_DIR`/`FWD_CONTAINER`/`CLIF_ENV_DIR` baking loops; log line → `{fwd,clifwd,fwdctl}`.
- The Typer program name stays `clifwd` by design — flipping it is the deferred full-rename ship, not this one.

**Part B — `--json` on the existing read-only commands (read-only ONLY; no new endpoints/concepts).**
- `callers list --json` — emits the raw `/v1/admin/callers` body (`CallerSummary` carries `name`/`api_key_prefix`/`policy_path`/`created_at`/`revoked_at` — **never** the api_key or a hash).
- `wallets list --json` — serializes the `WalletSummary` rows (`name`/`address`/`policy_path`/`created_at` — public-safe; **never** privkey ciphertext or the master key).
- `policy validate --json` — a structured result (`schema_ok`, `version`, the four counts, `consistency_checked`, `consistency_errors`, `valid`); the human path is byte-identical and **exit codes are unchanged** (2 on schema/consistency failure, 0 on valid).
- No `--json` on any mutating command; no `capability_id`/coordinator surface; no secret field in any `--json` output (Core #12).

## The three accepted deviations (implementer-surfaced, Reviewer-accepted)

1. **Part A test is a wiring test, not `poetry run fwdctl --help`.** The alias lives at the host-wrapper + in-container-shim + installer layer (the Typer program name stays `clifwd`; the `fwdctl` console-script is Reviewer-owned). `tests/unit/test_fwdctl_alias.py` (7 tests) proves `install/fwdctl` is a faithful copy modulo header+delegation token (exports + onboard routing verbatim), the Dockerfile symlinks `fwdctl`→`clifwd`, and `install.sh` installs it. The literal `poetry run fwdctl --help` / `docker exec fwd fwdctl health` checks belong to the real-infra stage (below).
2. **Dockerfile alias = symlink** (`ln -s clifwd /usr/local/bin/fwdctl`) rather than a second `printf` shim — spec-permitted; the symlink guarantees byte-identical behaviour to the shared shim.
3. **`callers` vs `wallets` `--json` mechanism** — `callers list` emits the raw response (`r.text`); `wallets list` serializes the rows (`json.dumps(r.json())`), honoring the spec's per-command distinction. Both carry the same fields as their human form, minus nothing, plus no secret.

## Real-infrastructure verification (Core #14)

`docker compose build fwd` (the symlink lands: `/usr/local/bin/fwdctl -> clifwd` confirmed in the image). The production signer was **not** restarted; the rebuilt image was exercised via throwaway `--rm` containers, with `health` hitting the live daemon's read-only `/healthz` over the `fwd_fwd-callers` network (the a97 cutover of the running container stays an operator-gated redeploy):

```
# both from the rebuilt image, against the live daemon /healthz:
fwdctl health  →  {"master":"ok","sealed_master":"ok","fwd":"ok"}
clifwd health  →  {"master":"ok","sealed_master":"ok","fwd":"ok"}   (byte-identical → PASS)

fwdctl policy validate --schema-only --json
   →  {"schema_ok": true, "version": 1, "callers": 1, "permissions": 1,
       "wallet_constraints": 1, "fsp_permissions": 0, "consistency_checked": false, "valid": true}

fwdctl version  →  1.1.0a97        clifwd version  →  1.1.0a97   (same app, both names)
```

`fwdctl health` == `clifwd health` on the rebuilt image — the alias resolves end-to-end via the in-container symlink, independent of the `pyproject` console-script. (`wallets list --json` against the live daemon needs the operator's `FWD_ADMIN_KEY` — runnable at the gated redeploy; the secret-free shape is covered by the unit test + the schema-only `--json` above.)
