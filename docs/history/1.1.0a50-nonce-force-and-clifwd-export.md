# v1.1.0a50 — `clifwd nonce init --force` (correct a mis-seed) + `install/clifwd` exports FWD_DIR/FWD_CONTAINER

**Type:** feature + fix ship (`src/` + host wrapper). Reviewer (Opus) prescribed; Sonnet implemented in an isolated subagent; Reviewer binding-passed; operator-gated.
**Date:** 2026-06-01.

## Why (two gaps the Flare cutover surfaced)

1. **No nonce correction.** `clifwd nonce init` / `POST /v1/admin/nonce-init` is create-only — an existing `(wallet, chain)` returns 409 `nonce_already_initialized`, and `nonce-sync` is bounded-monotonic (only advances). When a nonce is **mis-seeded too high** (operator fat-fingered the wizard's per-network prompt — entered `550` for the Flare nonces that should have been `claimer-flare@14=0` / `fsp-sender@14=486`), there was **no CLI way to lower/correct it** — only a gated direct DB `UPDATE`. The auto-mode classifier (correctly) gates such raw prod-custody-DB writes, so a correction required explicit operator authorization for a DB hack.
2. **Wrapper didn't export FWD_DIR.** `install/clifwd` set `FWD_DIR` as a shell var (not exported), then `exec`'d `$FWD_DIR/install/onboard`; the onboard child didn't inherit it and fell back to `/opt/fwd` → `onboard: no /opt/fwd/config`.

## What changed

- **`clifwd nonce init --force`** — an operator-gated, **audited** overwrite. `NonceRepo.init_for_wallet` gains `force: bool=False`: `force=True` uses `on_conflict_do_update` to overwrite an existing row to the **exact state a fresh init produces** (`next_nonce=starting`, `last_confirmed=None`, `last_reconciled_at=now`) — NOT `set_next_nonce`'s `last_confirmed=value-1`. `POST /v1/admin/nonce-init` takes `force`; the existing-AND-not-force → 409 path is unchanged (default still refuses, protecting against accidental overwrite); the existing-AND-force path writes an **approved** audit row with `decision_reason="force_overwrite"` and `outcome={"from": …, "to": …}` (the before→after is recorded — Core invariant #5). The CLI gains `--force`. So a mis-seed is corrected with a real, audited tool instead of a DB hack.
- **`install/clifwd`** now `export FWD_DIR` (token shape `${FWD_DIR:-/opt/fwd}` preserved so `install.sh`'s sed still matches) **and** `export FWD_CONTAINER` — the routed `onboard` inherits both.
