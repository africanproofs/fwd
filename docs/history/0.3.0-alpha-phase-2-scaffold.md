# v0.3.0-alpha — Phase 2 project scaffold

> First non-throwaway code ship. Landed 2026-05-01. Verification gate met.

## What landed

- **Project metadata.** `pyproject.toml` (Poetry, Python 3.12, all 19 runtime + 5 dev deps from `docs/dependencies.md` pinned with caret ranges). `clifwd = "fwd.cli.main:app"` script entry point per v0.2.3.
- **Container build.** Multi-stage `Dockerfile` (build stage installs Poetry + builds wheels for `coincurve`'s C extension; runtime stage is `python:3.12-slim-bookworm` running as non-root user `fwd` with healthcheck on `/healthz`). `.dockerignore` excludes docs, scratch/, secrets/, and other non-image content.
- **Compose stack.** Three services (`vault` HashiCorp Vault 1.18.2; `fwd` FastAPI app; `litestream` 0.3.13). Two networks (`fwd-internal` internal-only; `fwd-callers` bridge for caller containers). Three named volumes (`vault-data`, `fwd-state`, `litestream-replica`). `fwd` exposed on `127.0.0.1:8080` only. Vault config (`config/vault/config.hcl`) uses Raft single-node storage with TLS disabled (TLS lands in Phase 3 per `architecture.md` § Vault configuration). Litestream replicates to a local file (placeholder; Phase 6 swaps for Scaleway Object Storage).
- **Python source skeleton.** `src/fwd/` with the four-layer directory structure (`domain/`, `app/`, `infra/`, `api/`, `cli/`) per `architecture.md` § Layer boundaries — empty stubs except `api/health.py` (the `/healthz` endpoint) and `cli/main.py` (the `clifwd` Typer app with `version` and `health` subcommands). Structlog configured for JSON output to stdout (the privkey-scrubber processor lands in Phase 3 with `EnvelopeSigner`).
- **Tests.** Three unit tests:
  - `tests/unit/test_version_consistency.py` — asserts `pyproject.toml`'s `version` matches `src/fwd/version.py`'s `__version__`. Core invariant #13 drift detection.
  - `tests/unit/test_layer_boundaries.py` — walks the import graph under `src/fwd/`; fails if any layer imports from a forbidden layer per `architecture.md` § Layer boundaries — Enforcement. Phase 2's stubs pass trivially; the test starts protecting Phase 3+ as soon as code lands.
  - `tests/unit/test_health_endpoint.py` — smoke test for the `/healthz` response shape using `fastapi.testclient.TestClient`.
- **Alembic.** Initialized with `alembic init --template generic`. `alembic/env.py` reads `DATABASE_URL` from env (falls back to `alembic.ini`'s SQLite default). One scaffold migration `0001_initial_scaffold.py` (no schema — Phase 5 lands the real `wallets`/`callers`/`nonces`/`transactions`/`audit_log` tables).
- **CI pipeline.** GitLab `.gitlab-ci.yml` with four stages: `lint` (ruff check + format-check), `typecheck` (mypy --strict on `src/`), `test` (pytest with coverage), `build` (Docker image build, push to GitLab Container Registry on `main`).

## What this ship deliberately does NOT include

- **No signing.** No `EnvelopeSigner`, no `/v1/sign-and-send`, no `transit/encrypt` or `transit/decrypt` calls. Phase 3 lands those.
- **No Vault init.** Vault starts uninitialized and stays that way; `/healthz` reports `vault: sealed` as a result. Phase 3 ships `scripts/vault-init.sh` (Shamir 3-of-5 init, AppRole auth, `transit/keys/fwd-master` creation).
- **No TLS.** Vault and `fwd` communicate over the `fwd-internal` Docker network without TLS; the network is the security boundary. TLS within the network lands in Phase 3 as defense-in-depth.
- **No real Litestream replication.** The Phase 2 Litestream config replicates to a local file inside the container — useless for actual backup but enough to satisfy "all three containers up" without crashing. Phase 6 swaps the file replica for Scaleway Object Storage.
- **No wallets, no callers, no policy, no audit.** Those are Phase 4 (admin auth + caller management), Phase 5 (state schema + nonces), and Phase 7 (policy + audit chain).
- **No privkey-scrubber in structlog.** Phase 2 has no privkey path in the codebase; the scrubber processor (per `architecture.md` § Implementation hazards #3) lands in Phase 3 alongside `EnvelopeSigner`.
- **No `/docs` or `/redoc`.** FastAPI's auto-generated documentation is disabled in Phase 2 (no API surface beyond `/healthz` worth documenting yet). Phase 3 enables it for `/v1/sign-and-send`.
