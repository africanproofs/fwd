# v1.1.0a87 — fix the CM-02 caller-token check (guaranteed false positive since a82)

**Type:** `install/onboard` bug fix. No daemon change.
**Date:** 2026-06-06.

## Why (operator caught it on a healthy re-onboard)

a82 added the CM-02 check: on a re-run, if a `.env.<net>` caller token is preserved, warn when that token's prefix is not found in `clifwd callers list` (intent: catch a token whose caller was revoked/rotated, leaving `.env` stale). The check **never worked** — it fired for **every** existing caller, even with freshly-minted, valid tokens.

Root cause: a prefix-slice mismatch. Per `src/fwd/infra/api_key.py`, a token is `fwd_live_` (constant 9-char environment prefix) + a 43-char random portion, and fwd's stored `api_key_prefix` — the value `clifwd callers list` displays — is the **first 8 chars of the random portion** (`_PREFIX_INDEX_LEN = 8`), i.e. token chars **10–17**, *excluding* `fwd_live_`. The CM-02 check extracted `cut -c1-12` of the **full** token = `fwd_live_` + 3 chars (e.g. `fwd_live_kKC`) and grepped the list for that literal. The list only ever shows the random-part prefix (`kKC…`, no `fwd_live_`), so `fwd_live_kKC` can never be a substring → the grep always misses → CM-02 always warns. The preserved tokens were valid the whole time.

## What changed (`install/onboard`)

CM-02 now extracts the prefix the way fwd defines it — `cut -c10-17` (first 8 chars of the random portion) — and greps `clifwd callers list` for that, with `grep -qF --` (the random base64url prefix can begin with `-`). The warning message now shows that same 8-char prefix, so it cross-references directly against the `callers list` `prefix` column.

## Verification

`sh -n` + `dash -n` clean. A drill against the **exact** `callers list` line format from `src/fwd/cli/callers.py` (`{name:<32}  {prefix:<10}  …`) confirms: the new `cut -c10-17` equals fwd's stored `api_key_prefix`; a **present** token → grep hit → no warning; the **old** `cut -c1-12` → miss (the false-positive source, reproduced); a **rotated/absent** token (different prefix in the list) → miss → CM-02 correctly still warns. The check now signals only on genuine drift. Operator's live re-onboard is the final confirmation (expect: no CM-02 lines when tokens are valid).

## Files

`install/onboard`, version files.

## Lesson (Core invariant #19)

a82's CM-02 was a Reviewer-authored check written against a *mental model* of the token format rather than the authoritative `api_key.py` definition — exactly the [[reviewer-prescribes-from-mental-model-not-code]] failure class. A check that string-matches one component's output against another's must be derived from the producing code's contract (here: `_PREFIX` length + `_PREFIX_INDEX_LEN`), and verified against that component's real output format — not a hand-modeled prefix shape.
